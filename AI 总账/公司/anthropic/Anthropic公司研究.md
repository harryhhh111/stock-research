## 核心判断

**【我的推演】Anthropic 已证明企业客户愿意大量购买模型能力，也出现真实的经营改善；但它仍是一家持续研发、不断采购算力的前沿技术公司。若以 1.5–2 万亿美元股权估值入场，投资回报依赖未来收入和股东现金流的持续跃升，当前业绩并未提供充足估值缓冲。**

怎样赚钱：客户通过直销或云平台购买 Claude 的 token 用量，另付订阅费购买 Code、Cowork 等应用及使用额度。能力提升和工作流扩展推动老客户加量；推理效率提高有助于收入增长快于算力费用，但训练、渠道分成和新租赁仍会消耗资源。

最重要的三个投资问题：

1. 模型降价和竞争加剧后，客户用量能否增长得更快，且形成回款？
2. 当前利润改善能否覆盖 2026–2028 年算力交付、融资租赁和研发爬坡？
3. 普通股投资者支付的价格，是否已提前透支 2028 年接近 2,000 亿美元收入及高现金流率？

正面证据：H1 营收同比约 1,300%，Q2 已实现 GAAP 经营盈利；H1 CFO 为正；大客户扩张与留存指标突出。反面证据：收入依赖最新模型，客户收入大量按用量波动；供应端存在大额保底；普通股控制权弱；高额股权激励、转换与新发股份影响每股价值。当前结论为**经营改善值得研究，IPO 定价仍需严格约束**，不因研究建档自动给买入结论。

## 1. 公司与业务：谁付钱、买什么、如何确认收入

【原始披露】公司仅有一个经营及报告分部；未披露可独立核验的 Claude API、Code、Cowork、Pro/Max 各自利润。不能把某应用的年化收入再叠加到合并收入。[S1，附注分部信息]

|业务层|付费方与交易例子|收费及收入确认|盈利机制与边界|
|---|---|---|---|
|Claude Platform 模型服务|软件企业将客服、编码、信息提取接入 Claude；每次运行形成用量|输入、输出、缓存等 token 按模型和服务条件计费；实际服务消耗时确认收入|扣客户推理成本后仍须承担持续研发、渠道、销售与治理成本；API 收入不等于纯 B 端收入|
|Claude Code / Cowork 等应用|企业采购员工或团队使用能力，开发者购买编码工具|可包含订阅额度及额外用量；按用量或履约期间确认，具体依合同|应用提升工作流黏性；订阅重度用户增加算力消耗，需要套餐、额度和增购规则匹配|
|Claude Pro / Max 等订阅|个人专业用户按月购买使用额度与功能|固定订阅及额外用量；订阅通常不超过一年、随履约确认|用户价值取决于额度与模型成本，订阅不等于无限量；不能假设均是个人消费|
|云平台渠道|终端客户通过 AWS、Google 等平台采购，公司提供模型服务|Anthropic 认为自己是主要责任人，**按总额确认收入**；平台代收后扣费汇回|渠道费用主要进入销售营销相关费用；不同企业总额/净额口径不统一会扭曲收入倍数比较|

【我的推演】一次企业任务即使 token 单价下降，也可能因任务次数、上下文长度、agent 循环和高级模型组合增加而带来更多账单；真正的单位经济性应比较“成功完成任务的总成本”，无法仅用价格表判断收入或利润方向。本文不把历史聊天中的模型价目当作当前有效报价。

### 3.2 为什么85%毛利率不能当作成熟软件盈利能力

公司将客户工作负载算力主要分到营收成本；训练、研发和内部使用算力主要归研发；渠道费用及免费服务等归销售营销。H1 研发9,741，占收入59.8%，功能分类销售营销3,808，占23.4%。高毛利没有覆盖持续维护技术前沿所需的全部成本。[S1，附注8]

【复算】H1 净亏损桥：经营亏损−693 + 利息收入1,111 − 可转票据/衍生工具/SAFE重估72,388 − 其他净费用8,757 − 税21 = **−80,748**。其他金融工具重估调整8,720也很重要。不能只减掉72,388就称为“真实经营亏损”；经营利润应直接看经营报表。

【复算】调整后经营利润 = −693 + 股权激励2,185 + 非现金捐赠126 = **1,618**。调整后指标便于观察经营趋势，但股权激励会稀释投资者，属于人才成本。2025还剔除15亿美元 Bartz 和解等项目；不能把所有调整项均视为永不重复。

公司披露未确认RSU费用约266亿美元，其中约29亿美元服务条件已全部或部分满足，另有未确认期权费用约28亿美元；IPO触发相关条件可能使费用集中确认。**不是266亿美元全部在上市当季一次确认**，最终金额仍待生效和修正版。[S1，股权激励及MD&A]

### 3.3 现金流质量与资本化边界

【复算】H1 CFO 3,929中，营运资本变动合计约+1,168：应收−4,982，预付及其他资产+2,094，应付及其他负债+2,679，租赁−3，递延收入+1,380。剔除这组变动的经营现金贡献约2,761；回款、预付消耗和付款时点影响重大。应收从909增至5,833，需持续核验回款，不以增长本身断言坏账。

简化FCF 3,447，半年利润转现金值得肯定；融资租赁本金另有4，扣后3,443，但仍不能据此认定未来算力扩张已获覆盖。2025和H1的其他投资支出含收购等，不全部列为维护CapEx；购买短期投资属于现金管理，不应全部当作“烧钱”。非现金融资租赁资产新增445、待付固定资产增加148，也不能替代已付现金CapEx。[S1，现金流量表]

## 4. 客户、留存和收入可持续性

【原始披露】截至9/30，TTM收入≥10万美元客户超过11,900家，≥100万美元超过1,900家，≥1,000万美元约250家；门槛嵌套，**三档不能相加**。前五客户占前三季度收入约25%，无单一客户超过10%；Q3前五之外客户收入占79%，高于Q1的64%，单季口径与九个月不可混用。[S1，客户与风险因素]

NRR约900%：选择去年对应季度产生至少1美元收入的客户，排除Pro/Max订阅客户，以这批客户今年对应季度收入/去年对应季度收入计算。它反映扩张、收缩和流失的净结果，**不是用户留存率900%、不是全体用户支出、不是TTM/TTM**。约等于老客季度收入变为9倍、增幅800%。早期小基数与低门槛有利于该指标，无法长期外推；未披露成熟客户队列和数量留存率。

【原始披露】云市场渠道收入占比2023/2024/2025/H1 2026为11%/32%/47%/48%，渠道应收占6月底净应收58%。渠道与终端客户集中不同：AWS不等于最终使用Claude的某个企业。公司按总额计入云渠道销售，渠道费用进销售营销；与OpenAI或其他供应商比较前必须对齐。[S1，风险因素及收入确认]

【我的推演】优质需求证据为客户生产环境持续扩张及回款；风险来自大客户预算、初创企业融资能力、切换模型与压缩agent使用。多数大客户可在短期内减少支出，NRR不能替代不可取消订单。

|开源权重及低价模型供应商|分类、提取、路由、编码等成本敏感负载|前沿能力、企业支持、安全治理|模型可替换降低定价权，自建并非零成本；需计GPU、运维及任务成功率|
|企业软件/编码工具平台|员工入口和agent编排|直接应用Code/Cowork建立客户关系|平台可多模型路由，自研产品可能与现有渠道客户冲突|

来源：[S1，Competition及风险因素]。缺可比独立财报与统一任务价格，本文不制作假精确的市场份额、毛利率或最新模型榜单。模型公开标价不等于企业折扣、缓存后的有效价格。利润比较应扣持续训练、渠道、免费流量和人才成本。

【我的推演】API降价有竞争和效率因素；是否带来经营增益看有效任务数×单位收入能否快于成本增长。高档套餐加价/限额可以管理重度用户成本，但S-1不足以证明所有价格调整都以“消灭套利”为动机，不能将其作为管理层已证实的解释。

## 6. 行业景气与投入产出

需求端：企业从试点向生产工作流扩散，客户层级及收入提供证据；仍缺完整企业ROI、长期续约与预算替代数据。供给端：可用电力、机房、芯片交付和集群效率共同决定有效算力；签约MW/GW不等于已交付能力，token也不是跨模型统一的工作量单位。

【原始披露】截至9月底前六个月发布的模型版本贡献Q3收入超过80%，体现客户追逐新能力，也意味着模型资产经济寿命短、研发不能简单停投。公司预期收入增速随基数扩大而下降；算力费用随能力可用而确认，短期相对固定。[S1，MD&A]

【我的推演】行业需求增长与供应商利润增长可以背离。价格下降→用量扩张→算力利用率提升可形成正循环；若单位价格降幅超过利用率和效率改善，已锁定算力反而放大下行。缓存命中、更少任务失败能降低成本，但客户同样会要求降价，效率收益归属仍待验证。

### 7.3 客户承诺与供应承诺不对称

【原始披露】6月底剩余履约义务RPO **108亿美元**，约75%预计未来12个月确认；递延收入16.50亿美元。RPO含不可取消承诺下待确认收入，不等于已收现金，也不涵盖所有随用随付未来收入。[S1附注2]

【复算】预计12个月确认部分约81亿美元。它能提供需求可见性，但无法覆盖全部长期供应付款；供应承诺更长期、客户支出更灵活。反过来，不能用RPO较小就断言未来营收只有108亿美元，原因是大量用量业务无长约。

【我的推演：压力例子】保持H1全部经营费用16,979不变、收入下降20%，经营亏损将从693扩大至约3,950。实际成本会有可变部分，此例只是展示固定成本敏感性，不是盈利预测。更好的验证是逐年租赁付款表、交付能力、利用率与收入回款共同变化。

## 8. 治理、关联交易与主要风险

### 治理与激励

【原始披露】公益公司使命要求平衡股东、利益相关方及公益目的。Founder LLC持有一股无经济权Class F，控制一般事项约50.1%投票权；LTBT通过Class T选举董事会多数席位。Class F一般事项控制与Class T董事任免权作用不同，不能简单称创始人直接控制所有董事。Class A一股一票，Class N主要给战略伙伴、无一般投票权；公司可适用受控公司部分治理豁免。[S1封面及治理章节]

【我的推演】使命和独立监督可能降低短期冒险，但当安全、资本开支与股东收益冲突时，普通股股东很难改变方向，应要求额外估值补偿。大额人才权益激励有留才作用，也使GAAP利润及每股价值承压。不能把慈善、信托和员工类别股都视为有经济分红权的股份。

Google/Amazon等兼具股东、供应商、分销伙伴及竞争者身份；购买资金可能来自同一生态的融资，但“有循环关系”不等于虚假收入。应核验终端客户现金、总额收入、渠道扣费、承诺融资及关联条件，不能重复计算链条中的需求。
