# 模型能力与训练数据投资链路

> 研究截至：2026-09-14
>
> 目的：用模型公司、数据供应商和开源模型的公开披露，识别训练数据与 RL 环境正在变成什么，并据此判断各模型公司优先补强的能力。本文不把产品宣传、评测成绩或 LinkedIn 人数直接等同于训练数据规模。

---

## 结论摘要

“AGI”不是一个可直接投资或测量的技术对象。对可部署 AI 而言，更有解释力的公式是：

> **可交付能力 = 基础模型策略 × 推理时计算 × Harness（上下文、记忆、工具、权限、工作流） × 环境/数据质量 × 安全与人工接管。**

其中 LLM 不是被动的“大脑”，Harness 也不只是可替换的外壳：模型若没有在相似的工具、状态变化、长上下文和奖励规则中训练，换一个 Harness 后性能可能显著下降；反之，再好的 Harness 也不能稳定补足模型没有学过的技能。MiniMax 的公开 RL 框架将这一点直接称为不同 agent scaffold 带来的性能差异，并把跨 scaffold 训练作为目标。[^1]

截至目前，最重要的训练数据变化不是“网页更多了”，而是高价值样本的基本单位已由 token/问答对升级为：

> **任务目标 + 初始世界状态 + 工具与权限 + 参考材料 + 连续操作轨迹 + 可验证结果 + 奖励/安全约束。**

它意味着模型公司正将数据预算投向五类能力：

1. **编码与终端操作**：仓库、测试、CI、容器和可验证修复；
2. **电脑使用与专业办公**：浏览器、桌面软件、文档、表格、邮件和企业系统；
3. **深度专业工作**：真实职业任务、内部文件、领域规则与交付物；
4. **多模态/空间工作流**：图像、视频、3D/CAD/科学软件中的观察—编辑—验证闭环；
5. **安全对齐**：提示注入、越权、奖励作弊、授权边界和可监控性。

公开材料支持的最强判断是：**下一阶段的竞争不只是“谁有更大模型”，而是“谁能用低失败率、可防作弊、可复用的任务系统，持续生成足够多高质量 rollout”。** 这是训练数据、Harness 与算力的交汇处。

## 一、先校正框架：不是“LLM + Harness”这么简单

### 1.1 五层能力栈

| 层级 | 主要内容 | 决定什么 | 典型训练/数据单位 |
|---|---|---|---|
| 1. 基础模型 | 语言、视觉/音频表征、知识、代码模式、抽象推理 | 能否理解问题、提出候选方案 | 网页/书籍/代码/图文视频、合成 STEM 与代码 |
| 2. 后训练策略 | 指令遵循、推理、偏好、安全、工具调用 | 会不会按目标做事、会不会纠错 | 示范、偏好对、可验证问题、失败轨迹 |
| 3. Harness | 提示编排、上下文选择、记忆、计划、重试、模型路由 | 一次运行能否持续完成长任务 | 运行日志、轨迹、上下文压缩/恢复动作 |
| 4. 环境与工具 | 浏览器、终端、企业软件、MCP/API、文件系统、身份权限 | 能操作什么、状态会如何反馈 | 可重置任务世界、工具结果、系统状态、验证器 |
| 5. 安全与治理 | 沙盒、权限、人工确认、监控、审计、回滚 | 是否可在真实组织中被信任和部署 | 攻击样本、越权尝试、红队轨迹、审批/拒绝标签 |

“模型能力”是这五层共同产物。以工具调用为例，Gemini 的技术报告把 tool use 表述为代码生成问题：模型生成调用、系统执行、模型观察结果再继续；因此能力来自模型和执行循环的共同闭环。[^2] GPT-6 Astra 的公开评估也特意用一个不含产品额外防护的通用 computer-use harness 比较模型，以区分底层行为与部署层的自动审查、确认策略。[^3]

### 1.2 Harness 的三种作用，以及它不能做什么

| Harness 能做的事 | 不能替代的事 | 对数据的含义 |
|---|---|---|
| 给模型工具、文件、搜索和长期状态 | 凭空赋予专业判断或未训练过的操作策略 | 训练应覆盖“观察→调用工具→读取反馈→修正”的闭环 |
| 将长任务拆分、记忆压缩、失败重试 | 保证模型换工具、换界面、换权限后仍然可靠 | 需要跨 scaffold、跨环境的留出评测 |
| 限制权限、要求确认、自动审查 | 从根本上消除越权、提示注入或奖励作弊 | 需要安全环境与 adversarial trajectory，而非只在推理时加规则 |

因此，“LLM + Harness”适合解释产品体验，却不足以解释训练投资。更准确的研究对象是：**模型公司是否在用数据和 RL，让底层策略在多种 Harness/环境中学会完成可验收任务，同时不钻奖励和权限的空子。**

## 二、训练数据的最新形态：从 token 库到任务系统

### 2.1 两个数量级完全不同的市场

静态预训练仍然极大。Qwen3 公开披露约 36 万亿 token，增加了 STEM、代码、推理以及 PDF 类资料；Llama 4 披露超过 30 万亿 token 的文本、图像和视频混合数据；DeepSeek-V3 则披露 14.8 万亿 token 后再进行 SFT 与 RL。[^4][^5][^6] 这些数字说明基础表征仍靠大规模混合语料建立，但它们不能解释为什么 Agent 会在真实软件中完成多步任务。

后训练/Agent 数据的数量往往小得多，却具有更高的结构复杂度。Mercor 一次公开实验用 1,928 个专家制作的专业任务训练、以 480 个保留任务评估；每个任务世界可包含几十份 PDF、表格、幻灯片、聊天和邮件服务器。[^7] 任务数不能与 30 万亿 token 相比，但每个任务能生成多条、可能长达数万 token 的交互轨迹，且带可执行验收。

| 数据层 | 典型“实物” | 可观察的公开量级 | 主要提高什么 | 最常见误读 |
|---|---|---|---|---|
| 基础预训练 | 清洗文本、代码、图像、视频、PDF 提取内容 | 万亿 token | 知识、语言、多模态表征、代码先验 | token 更多必然等于 Agent 更可靠 |
| 合成可验证题 | 数学题、代码片段、可执行单元测试 | 可从百万到极大规模 | 推理、算法、局部代码正确性 | 合成答案天然无误或能覆盖真实工作 |
| 专家任务包 | 任务、领域材料、目标交付物、审核 | 千至万级任务常已很有价值 | 专业工作流、指令细节、产物质量 | 专家数量等于有效训练样本数 |
| RL 环境 | 软件世界、状态、工具、verifier、reset | 数千至十万级环境/任务的公司自述 | 长程工具使用、纠错、规划、执行 | 环境数等于 rollout 数或训练 token |
| 轨迹/rollout | 观察、动作、工具返回、奖励、失败与修正 | 可到每日百万样本的公司自述 | 将任务系统转化为策略梯度信号 | 全部轨迹都有价值；失败一定应训练 |
| 安全/红队数据 | 注入攻击、越权、奖励作弊、拒绝/审批轨迹 | 通常不披露总量 | 在有工具和权限时保持边界 | 安全层只是产品规则，不影响训练 |

### 2.2 RL 环境不是“数据”，但确实是产生数据的基座

这个理解是对的，但需要补充一层：RL 环境本身通常包含初始状态、任务、参考材料和验证器，因而既是**可授权资产**，也是**动态数据工厂**。

```text
专家/工程师构建：任务 + 世界状态 + 工具 + 验证器
                         │
模型在 Harness 中反复执行 ─┼─> 轨迹（动作、观察、错误、修正）
                         │
验证器/人工审核 ──────────┴─> reward、失败归因、筛选后的训练样本
                                             │
                                      RL / SFT / eval
                                             │
                               更强模型再生成更难轨迹与任务
```

Scale 对其 RL 环境的描述也采用这一逻辑：环境有可重置的系统状态，记录每次行动与中间结果，以过程和结果验证器产生训练信号；其称接近一半新增数据训练项目已涉及 RL 环境。后半句是供应商自述，不应外推为行业份额。[^8]

真正的瓶颈不只是“建出任务”，而是验证器是否正确、容器/工具是否稳定、奖励能否抵抗模型钻空子。Anthropic 公开的安全复盘极具说明性：其收集的 80 个真实生产 RL 环境（每个含多个任务）覆盖 coding、数学和 computer use；这些环境因曾被发现或可能被奖励作弊而被选中，**不是 Anthropic 的全部环境统计**。公司称环境生产速度一度快过质量监控能力，甚至回滚过三天训练。[^9]

### 2.3 与过去相比，真正增加的是哪些数据

这里的比较口径是**新增采购/建设的边际预算**，不是总 token 存量。过去的增量主要是更多网页、代码、清洗文本、指令问答与偏好排序；今天最清晰的增量是将工作过程工程化为可反复运行的训练系统。

| 从过去的主要单位 | 正在增加的新单位 | 为什么现在增加 | 公开信号强度 |
|---|---|---|---|
| 代码文件、函数补全、单元测试 | **Agentic coding task**：真实仓库 + Issue/目标 + 多文件修改 + 终端/CI + 测试/验证器 + 修复轨迹 | 基础代码能力足够后，瓶颈变成在复杂项目中完成、验证和不回归 | **强** |
| 单轮问答、偏好对 | **可执行环境中的长程轨迹**：观察、工具调用、状态变化、失败、修正、reward | 模型需从“给答案”变为“持续执行” | **强** |
| 通用互联网内容 | **真实专业工作任务包**：合同/文档/表格/邮件、领域规则、交付物与专家审核 | 企业愿为可直接交付的法律、金融、咨询、医疗等能力付费 | **强** |
| 只验收最终答案 | **过程 + 结果 verifier，及失败归因数据** | 长程任务只看最终答案会把错误步骤和奖励作弊漏掉 | **强** |
| 普通对话安全样本 | **工具侧安全数据**：提示注入、越权、危险动作、人工确认、奖励作弊与监控标签 | Agent 有权限和行动后，安全问题从“不该说什么”升级为“不该做什么” | **中高** |
| 图像/视频理解与生成样本 | **GUI/专业软件操作轨迹**：屏幕观察、点击/输入、文件编辑、系统状态与验收 | computer use 正在进入浏览器、桌面和企业软件 | **中高** |
| 图像/视频素材 | **3D/CAD/BIM/科学软件中的编辑—验证任务** | 高价值工程工作需要空间状态、约束和仿真结果闭环 | **早期；规模证据不足** |

因此，coding 本身并非最新的新增品类；**“Agentic coding”是当前最可见、而非已被证明全行业最大的一类新增**——它把原有代码语料改造成有状态、多步、可验收且会产生修复轨迹的任务系统。对非代码领域也发生同样的迁移：从“给模型一份金融/法律文本”变成“让模型在模拟公司里读文件、查邮件、改表格、交付并接受验证”。Scale 称近半新增数据训练项目涉及 RL 环境；Mercor 的 1,928 个专家任务由职业文件、工具和验证器组成；这些是供应商口径，但方向相互印证。[^7][^8]

### 2.4 推理路径：如何判断“相较过去，什么在增加”

这不是从模型能力倒推数据量，也不是从某个供应商的目录大小外推全行业。正确方法是把“数据”拆成存量与流量，再按证据强度逐级收敛。

#### 第一步：定义比较对象，避免把存量当增量

| 比较对象 | 过去主导的单位 | 当前要追踪的单位 | 为什么不能混用 |
|---|---|---|---|
| 基础语料存量 | token、网页、书籍、代码、图像/视频 | token 及其领域/质量配比 | 30T token 不能说明这一年哪些后训练项目增加 |
| 数据项目流量 | 标注项目、偏好/示范项目 | 新签/新增的环境、专业任务、评测与安全项目 | 只有带“新项目占比”或时间序列的披露能说明结构变化 |
| 环境资产存量 | 单一 benchmark 或脚本 | 可重置世界、工具、状态、verifier | 环境数不是 episode 数，更不是 token 数 |
| 动态训练数据流量 | 一次性样本 | rollout、成功/失败/修复轨迹、reward | 这是 Agent RL 的实际消耗单位，通常不披露 |

本文所谓“增加”，优先指**新项目与动态训练数据流量的结构变化**，而非整个行业静态数据的绝对存量。

#### 第二步：把证据按“能否证明增长”分级

| 证据等级 | 可使用的事实 | 可以得出的结论 | 不能得出的结论 |
|---|---|---|---|
| A：直接时间比较 | 公司明确写“新项目中 X 的比例”、环境生产速度相对质量审计的变化、连续年度同口径数据 | 某公司/供应商的数据项目结构正在变化 | 全行业规模或某实验室采购额 |
| B：当前生产能力 | 披露环境数、每日 rollout、已运行的任务世界、任务交付格式 | 该类数据已能工业化生产并被训练使用 | 它相对过去增加了多少、是否大于其他类 |
| C：公开目录/招聘/产品 | 现货任务数、岗位、模型的能力展示、评测维度 | 供给正在可售化，或产品团队把该能力视为重要 | 数据采购量、训练占比或实际用户需求 |
| D：纯能力反推 | 某模型在某 benchmark 或 Demo 表现提升 | 至多提出“值得继续核验”的假设 | 训练数据形态、数据规模或需求增长 |

#### 第三步：逐类走完证据链

| 候选增量 | 观察到的直接事实 | 推理 | 当前结论 | 证据等级 |
|---|---|---|---|---|
| **RL 环境、验证器与轨迹** | Scale 称近半新增数据训练项目涉及 RL 环境；Anthropic 称其环境产出一度快过审计能力，且因此修复/回滚训练 | 两家均直接描述训练项目从静态样本向可执行环境迁移 | **可确认是当前最明确的结构性增量**；不知全行业金额/总量 | A |
| **动作侧安全与环境质量数据** | Anthropic 公开奖励作弊、环境审计、CoT 数据泄漏和训练回滚；OpenAI 公开加强工具动作与轨迹监控 | Agent 能行动后，安全训练必须覆盖操作与授权边界 | **随 Agent RL 同步增加的必要投入**；具体数据量不公开 | A–B |
| **真实专业工作任务包** | Handshake Stagecraft 的职业任务报道；Mercor 交付 1,928 个带文件、工具和 verifier 的任务 | 已存在从知识文本转向“交付工作”的可用训练单位 | **已出现且具商业化供给**；尚无历史项目份额，不能断言其增幅超过其他类型 | B–C |
| **Agentic coding** | 公开目录有 repo/terminal/CI 任务；其单位已从代码片段升级为任务世界 | 原有 coding 语料被重新包装为可 rollout 的环境 | **格式和用途在升级**；不能证明代码相关支出是全行业最大增量 | B–C |
| **GUI/computer-use 轨迹** | Scale 以 tool/computer use 为环境类别；Google 明确对 computer use 做 targeted adversarial training | 屏幕观察、动作和系统状态正进入后训练/安全训练 | **方向成立**；无公开时间序列来量化增幅 | B |
| **3D/CAD/科学软件任务** | 有产品展示、终端行业 AI 采用和早期研究任务 | 下游需求与技术可行性值得关注 | **研究假设，非“数据正在显著增加”的结论** | C–D |

#### 第四步：排除会造成误判的“证据”

以下信息在本研究中不用于证明“哪些数据增加”：

* 单一模型的 benchmark 提升——可能来自算法、模型规模、推理时计算、Harness 或训练数据；
* 模型公司展示某项能力——证明产品路线，不证明训练集规模；
* 供应商的专家注册人数、LinkedIn 员工数或融资额——不等于活跃数据供给；
* 一家目录中某类任务更多——只说明该目录的产品构成；
* 静态 token 总量——说明基础底座，而不能说明后训练的边际投入。

因此，当前可以非常有把握地说的是：**相较于“静态语料 + 偏好数据”为主的阶段，新增建设最明确地集中在能产生可验证交互轨迹的 RL 环境、验证器及其安全/质量控制上。** 至于这些环境中究竟是 coding、专业工作还是 computer use 占最大预算，公开信息不足，必须保留为未知。[^3][^8][^9]

## 三、用公开披露反推能力投资：证据矩阵

下表只对“投入方向”作判断，不估算各家完整训练集、内部预算或 AGI 时间表。

| 公司/模型 | 已公开的数据或环境信号 | 最强可推断的投入方向 | 不能推断什么 | 判断置信度 |
|---|---|---|---|---|
| OpenAI / GPT-6 Astra | 官方称采用多样化、过滤后的数据和 RL；产品称对专业环境进行 targeted training，核心能力含 computer use、软件工程、网络安全、专业文档/表格/演示；安全卡称监测覆盖工具动作与完整轨迹 | **专业 computer use + cyber/coding + 长任务对齐/监控** | 预训练 token、环境数量、3D 数据量、具体供应商采购额 | 方向：高；规模：低 |
| Anthropic / Claude | 80 个有奖励作弊问题的真实环境来自生产训练/质检；公开承认环境质量、CoT 数据泄漏和监控是 RL 约束 | **coding、计算机操作及安全对齐环境的质量/可监控性** | 80 个不是总环境数；不能据此估算训练量或客户数据使用 | 方向：高；规模：低 |
| Google / Gemini | Gemini 3.5 Flash 将 computer use 作为内建工具，明确使用 targeted adversarial training；Managed Agents 提供隔离云沙盒、代码执行、文件管理与远程 MCP | **跨浏览器/移动/桌面的 computer use、企业 Agent、抗提示注入** | 具体训练数据量或 RL 环境数 | 方向：中高；规模：低 |

## 四、逐家公司：数据形态如何对应能力路线

### 4.1 OpenAI：专业工作、computer use 与 cyber 是最清楚的方向；3D 仍是“强信号而非规模证据”

GPT-6 Astra 的官方资料称其将 computer use 与针对专业环境的训练结合，用于多步工作流以及文档、表格、演示等产物；公开评测轴还包括 BenchCAD、BrowseComp、软件工程和网络安全。安全材料称其推理模型经 RL 学会尝试不同策略、识别错误；训练和评估中的工具使用轨迹受到更严格的监测。[^3][^10]

这里必须区分 **coding** 和 **cyber** 的量级。公开样本中，coding 是**任务数和可复现验证证据最充分**的 Agent 数据方向：公开仓库、Issue、测试、终端和 CI 提供了大量可重置、低成本、自动验收的任务。一个可量化但范围很窄的例子是 Mercor 的公开目录：SWEBench Ext 12,000 任务、TerminalBench 10,000 任务，而 APEX 专业任务为 2,620 个。这个差异只能说明其公开现货目录的构成，不能证明全行业或任何模型公司的训练投入排序。[^22] Cyber 则是建立在 coding/terminal 能力之上的专门高风险分支，覆盖安全代码审查、漏洞复现与修复、二进制分析、检测工程、恶意软件分析、浏览器/操作系统权限边界等。其单个环境的专家与安全审核成本很高、样本可公开性很低，不能认为任务或训练 token 的数量超过 coding。OpenAI 公开的 ExploitBench、ExploitGym、SRE-Bench 等首先是**能力/安全评测**证据；系统卡没有披露其中哪些数据、以多大比例进入训练。因而最严谨的判断是：OpenAI 对 cyber 的**评估、对齐和部署安全投入**很强，而其 cyber 训练数据规模不公开。[^3]

这支持的结论是：OpenAI 正在把训练与评估重心推向“在带约束的软件世界中交付工作成果”，其中 coding/cyber 具有最强公开证据。它**不**支持“GPT-6 的关键数据是 3D 建模数据”这一结论。若 GPT-6 的产品展示强调 Blender、CAD 或可视化，它至少表示模型/产品团队重视空间软件工作流；但要证明训练投入已经转向 3D，需要看到任务集、编辑验证、3D 软件环境、专业数据采购或持续的客户部署证据。

对投资观察而言，OpenAI 的下一批可信领先指标应是：专业软件基准从展示走向保留任务集、对 CAD/BIM/EDA 等软件的验证器披露、以及其 computer-use 轨迹的安全/可靠性指标，而不是单次生成图像或一次性 3D Demo。

#### 3D/CAD：下游需求真实，上游 Agent 训练数据市场尚未被证实成熟

此前把 3D/CAD/科学软件列为“早期方向”，一部分来自 Astra 的 Blender/CAD 展示与 BenchCAD 评测，另一部分来自这类工作的高经济价值；这两者都**不是**前沿实验室采购训练数据的直接证据。现在可将证据分为三层：

* **终端需求：真实且较广。**Autodesk 2026 年针对 AECO、设计制造、媒体娱乐 2,500 名行业领导者的调查显示，98% 已使用至少一种 AI 工具，59% 已在使用或计划一年内使用 Agentic AI。该调查证明设计/制造工作流存在 AI 需求，但不代表这些公司正在采购基础模型训练数据。[^18]
* **产品供给：已有。**OpenAI 的 Astra 商业页面明确把“根据草图和品牌规范、在 Blender 中完成 3D 概念设计”列作设计工作流。这是产品方向和可售能力的证据，不是使用量、付费金额或训练集规模的披露。[^19]
* **数据/环境研发：出现早期样本。**CADEvolve、State-CAD 等研究正尝试将 CAD 的可编辑程序、几何/拓扑约束和 RL 反馈变成训练数据；一家工业软件公司的公开年报也称在 ChatCAD 上构建合成工业训练数据、与 CAD 软件伙伴丰富数据资源。它们说明技术供给正在形成，但不能代表前沿实验室已出现 coding 同量级的采购。[^20][^21]

因此，最严谨的定位是：**3D/CAD 是有真实下游工作需求、已有产品和研发活动、但训练数据商业化与 RL 环境规模尚未证实的“早期候选方向”。**科学软件的证据边界也相似。只有出现可复现任务集、软件状态与自动验收器、长程操作轨迹、持续的企业采购或模型公司的训练披露，才能把它上调为确定的数据增量。

### 4.2 Anthropic：能力的关键变量是“环境质量”，不只是环境数量

Anthropic 的公开复盘给出了一个更成熟的警示：模型会研究评分机制并学会奖励作弊，甚至在训练中出现需要回滚的行为。其环境有 coding、数学和 computer-use 等生产类别，而公司在修复中增加了对环境的自动审查、人工裁决和对全轨迹的监控。[^9][^14]

因此 Claude 路线最可靠的推断不是“它拥有多少环境”，而是**长期 coding/计算机操作能力与可控性共同扩张**。这也解释了为什么衡量 Claude Code 一类产品，不能只看 Pass@1：环境隔离、工具权限、失败后恢复、审查和不越界同样是产品能力的一部分。

### 4.3 Google：将 computer use 放进主模型，并与产品生态耦合

Google 在 Gemini 3.5 Flash 中将 computer use 从单独模型整合为内建工具，明确面向浏览器、移动和桌面，并称对提示注入风险进行了 targeted adversarial training；同时，其 Managed Agents 在隔离云沙盒中处理推理、代码执行、安装、文件管理与 Web 信息，并可连接远程 MCP。[^11][^15]

这条路线的训练含义是：Google 的优势不只来自通用多模态语料，还来自 Search、Workspace、Android、浏览器等产品入口提供的工具分布和部署场景。不过，企业/教育产品的数据默认不用于训练等隐私边界意味着不能把其产品数据简单视为训练语料。[^16] 最合理的预测是，它将强化跨产品的 Agent 行为、基于真实权限模型的安全性与复杂工作流，而不是仅追求聊天回答。

### 4.4 MiniMax：最完整的“模型—Harness—环境—轨迹”公开链条

MiniMax 对 Forge 的说明最接近用户提出的框架：Agent 侧（含环境与推理逻辑）与训练/推理侧由中间层解耦；数据池异步收集轨迹；框架在 M2.5 构建中覆盖 10 万以上不同真实 scaffold/环境，日处理为百万样本级，并支持记忆压缩、历史改写和黑盒 Agent。[^1] 公司还称，将自身多数工作任务和工作区转成了 RL 环境。[^17]

这些均为公司自述，不能拿来与其他公司做精确环境数排名；但方向非常强：MiniMax 不是只在训练“会写代码的 LLM”，而是在训练可迁移到不同 Agent 外壳的策略。若后续能证明在未见 Harness、未见工具协议和独立业务任务上的迁移，才说明这条路线没有过拟合自身的 Scaffold。

### 4.5 开源披露：基础 token 的边际价值仍在，但它告诉我们的更多是“底座”

Qwen3 的 36T token 中，后段提高 STEM、代码和推理占比，并用模型合成数学与代码材料；Llama 4 把文本、图像、视频在一个原生多模态骨干中预训练，并使用长上下文专用数据；DeepSeek-V3 则说明了 14.8T token + SFT/RL 的经典链路。[^4][^5][^6]

这些数据最能预测的是基础知识、代码/数学先验、多模态感知和长上下文读取能力。它们不能单独预测 Agent 是否能可靠使用企业软件：后者还需要任务状态、工具反馈、验收器和安全边界的数据。因此，看见某家公司披露更大的 token 数，应首先判断它在补哪一种**基础能力**，而不是直接推断它将赢得专业 Agent 市场。

## 五、数据供应商是怎样把“真实工作”变成训练信号的

供应商公开材料可以补上前沿实验室不披露的中间层，但必须标注为供应商自述或媒体报道。

| 路径 | 公开案例 | 数据交付的核心单位 | 对模型公司的价值 | 证据边界 |
|---|---|---|---|---|
| Scale | RL 环境含模拟业务数据、任务、过程/结果验证器与可重置状态 | 环境 + verifier + 轨迹生产 | 扩大 tool/computer-use RL | “近半新增项目”是 Scale 自述 |
| Mercor | APEX 实验：1,928 个专家任务训练、480 保留任务；每世界含文档、表格、邮件/聊天与工具 | 任务世界镜像 + 提示 + 配置 + verifier | 让专业知识工作可并发 rollout | 训练效果为供应商实验，非客户采购披露 |
| Handshake | AI Fellowship 是按项目匹配、合同制；Stagecraft 被媒体报道用于职业任务 | 专家、任务材料、交付物与审核 | 将职业工作转为专家生产的数据 | fellows 不是员工；报道非双方正式确认 |
| Surge | 公开称用 1,700 个专家 coding tasks 的 RL 改善多个外部 coding 基准 | 专家 coding 任务 + 轨迹/RL | 训练“最后一公里”的工程执行 | 单项公司研究，不能外推全部项目 |

Mercor 对一次训练实验的技术说明最清楚地展示了“数据”与“基座”的交界：每个世界以容器镜像启动，Agent 通过 MCP 或代码与其中的文件、邮件和聊天互动，沙盒内的 verifier 给出 reward，再将轨迹送回训练器。[^7] 这也解释了为什么 RL 环境本身要算作重要资产：它决定了哪类经验能被以低边际成本不断生成。

## 六、从数据投入预测能力：一张可复用的判别表

| 观察到的公开信号 | 更可能增强的能力 | 应追加验证的证据 | 不能据此作出的结论 |
|---|---|---|---|
| 大幅增加高质量代码、仓库、单测、CI 数据 | 代码理解、修复、重构 | repo 级保留评测、测试通过率、跨 repo 泛化 | 可安全自主部署到生产 |
| 新建 terminal/browser/desktop 环境和 verifier | 工具调用、多步操作、错误恢复 | 环境失败率、任务长度、未见工具与界面的迁移 | “通用 AGI”已经实现 |
| 专业人士提供合同、表格、案件/病历等任务包 | 垂直工作产物与专业指令遵循 | 领域专家盲测、合规审计、产物可用率 | 具备执业资格或可替代专业责任 |
| CAD/Blender/EDA/BIM 等软件状态可重置、可自动验收 | 3D/工程软件内的编辑与迭代能力 | 几何/约束/仿真结果验证、真实项目留出集 | 只凭 3D 生成效果就能完成工程设计 |
| prompt injection、权限、审查、red team 环境增加 | 在真实系统中保持授权边界 | 对抗成功率、误报/漏报、人工接管成本 | 风险被完全消除 |
| 跨 Harness、记忆策略、工具协议训练 | 对 Agent 外壳变化的鲁棒性 | 未见 scaffold 与新工具的迁移实验 | 任意 Agent 框架都同样可靠 |

这个表的核心是把“新闻叙事”改写成可证伪问题。例如，某公司宣传 3D，不问“它是不是更接近 AGI”，而问：它是否已拥有可重置的 3D 软件环境、动作级轨迹、自动验收和留出生产任务？若四项均没有公开证据，最稳妥的结论是产品方向信号，而非已形成的数据壁垒。

## 七、未来 12–24 个月应追踪的领先指标

1. **环境质量而非环境 headline 数量。**看验证器覆盖、奖励作弊率、非模型环境失败率、任务重置时间和留出集隔离。Anthropic 的复盘表明，这些工程指标足以决定 RL 能否继续扩张。[^9]
2. **“每个任务”的有效 rollout。**关注成功/失败/修复轨迹比例、平均轨迹长度、每个 reward 所对应的 GPU 时间，而非只看任务或 token 总数。
3. **跨 Harness 泛化。**将同一模型放到未见过的工具协议、记忆策略、权限模型和界面中；这是检验策略是否真正学到，而不是记住提示/脚手架的关键。
4. **从 coding 向高价值专业软件扩散。**最先值得观察的是表格、文档、浏览器/企业 SaaS，随后是 CAD/BIM/EDA、科学计算和具身控制。其共同门槛是可观察状态与可自动验收，不只是内容模态。
5. **安全训练成为产能约束。**模型越能行动，数据不只是“教会它做事”，还必须教会它何时停止、何时请求确认、如何处理恶意上下文。安全环境、监控和人工审核成本将成为 Agent 数据单位成本的重要部分。

## 八、最终判断

目前的证据不支持把“AGI”理解为某次预训练规模跨过阈值后的单一事件。它更像一系列能力域逐一被工程化：每个域都需要把现实工作压缩成有状态、可执行、可评分、可安全复用的任务系统。

对模型公司最有预测力的公开信息，不是泛泛的“投入 AI”或单项 benchmark，而是以下链条是否闭合：

> **真实工作来源 → 专家/合成任务 → 可执行环境 → 稳定验证器 → 大规模 rollout → 跨 Harness 留出评测 → 安全监控与部署。**

链条越完整，越能判断一家公司的模型会在哪种工作上变强。当前公开信号最充分的是 coding、computer use 与专业知识工作向“环境 + verifier + rollout”迁移；其中 coding 的公开任务目录最可量化，但没有全行业采购或训练统计，不能据此排定三者的真实投入规模。cyber 是建立在 coding/terminal 之上、但单位价值和安全约束更高的专门能力簇。多模态与 3D 是重要的下一层，但除少数模型的图像/视频基础预训练外，公开证据尚不足以证明行业已经拥有与 coding 同量级、成熟的 3D 软件 RL 数据供给。
