# 数据标注层：从数据类型到模型能力的映射与市场定价

> 整理日期：2026-09-08
> 来源：整合原有分散对话片段、厂商披露、供应商公开目录与调查报道，统一逻辑框架
> 核心命题：**决定模型能力的不是数据"量"，而是数据的"结构"——什么类型的数据在涨，模型就在什么能力上变强**

---

## 一、为什么传统数据不够了

之前的训练数据都是**静态的**：一段文本、一个问答对、一个"A 回答比 B 回答好"的排序。模型读完就算，学到的是"一次性给出好答案"。

但现实世界的能力——比如让 AI 帮你"打开浏览器、登录公司系统、导出上月销售数据、做成图表发邮件"——是**一个过程**：要连续操作几十步，中间每一步都依赖前一步的结果，而且随时可能出错。静态数据教不了这个，就像你没法只看别人的"考试答案"学会开车。

解决办法就是两个新范式：**RL 环境是"驾校和考场"，Agent 轨迹是"驾考录像 + 评分单"**。

---

## 二、核心概念：RL 环境与 Agent 轨迹

### 2.1 RL 环境（RL Environment）：可执行的仿真任务世界

**RL 环境 = 一个仿真的软件/任务世界 + 一套评分规则。**

它长这样：

1. **一个沙盒**：比如一个模拟的电商后台、一个 Linux 终端、一个浏览器、一个 Excel——模型可以在里面真实地点击、输入、执行命令
2. **一个任务**：比如"给所有库存低于 100 的商品补发采购单"
3. **一套评分细则（rubric/reward）**：由专家事先写好，自动检查模型最终的结果对不对、过程有没有踩红线，给出分数

关键点是**环境会给反馈**：模型操作错了，环境会报错、状态会变化，模型必须自己想办法纠正。AI 实验室在这种环境里用强化学习训练：试一次 → 得个分 → 调整 → 再试，反复上万次，模型就学会了"怎么干活"。

这就解释了为什么一条 RL 任务数据能卖 200–2,000 美元——数据公司卖的不再是一行文字，而是**一整个可执行的仿真环境 + 一套精密的自动评分规则**，这个工程量完全不同。

### 2.2 Agent 轨迹数据（Trajectory）：完整的过程记录

**Agent 轨迹 = 模型完成一个任务的全过程录像**：每一步看了什么（屏幕/状态）、想了什么（推理）、做了什么（点击/调用工具）、环境返回了什么。

一条轨迹大概长这样（简化）：

```
任务：把表格里的销售数据做成月度对比图并发给老板
步骤1：观察 → Excel 打开，看到 Sheet1
步骤2：思考 → 需要按月汇总 → 动作：调用 pivot 工具
步骤3：环境返回 → 汇总表生成，但 3 月数据缺失
步骤4：思考 → 检查原始数据发现格式错误 → 动作：修正格式重新汇总
……
步骤N：动作：发送邮件 → 任务完成
```

**每条轨迹里最有价值的往往不是成功案例，而是"出错—发现—纠正"的那几步**（上面的步骤 3–4）。模型正是从这些节点学会"遇到意外怎么办"——这是静态问答数据完全给不了的能力。这也是为什么具身智能领域特别看重"失败样本"，逻辑是一样的。

### 2.3 两者的关系

| | 静态数据（问答对、偏好排序） | 轨迹数据 + RL 环境 |
|---|---|---|
| 形态 | 一行一行孤立样本 | 几十上百步的连续过程 |
| 学什么 | 答案"长什么样" | 过程"怎么走"，包括纠错 |
| 对应能力 | 知识、表达、单次推理 | 规划、工具调用、自主性 |
| 成本 | 一条几美元 | 一个环境/任务几百上千美元 |

行业公式：

> **RL 环境（仿真世界）提供"练兵场" → Agent 在其中反复尝试产生轨迹 → 评分规则给每条轨迹打分 → 强化学习用这些打分的轨迹更新模型 → 模型的 Agent 能力变强。**

Anthropic 愿意讨论一年花超 10 亿美元在这上面：传统文本语料是从互联网上"捡"来的，而 RL 环境必须**一个一个手工设计建造**——每个行业、每种软件、每类任务都要单独做。这是当前大模型训练里唯一还无法靠"爬互联网"解决的数据类型。

### 2.4 数据的“实物”是什么：外采、自建与用户会话要分开看

衡量这一层时，重点不应是数据供应商收入，而是**一份交付给模型公司的数据到底包含什么**。目前高价值单位正从一段文本，变成：

> **任务 + 工作背景/参考材料 + 可操作环境 + 交付物或验证器 + 专家审核。**

模型在环境中反复执行才产生轨迹；验证器或人工评分再把“是否完成工作”变成可用于训练的反馈。并非每个任务都含有人类完整示范，也不应把所有评测集都拿去训练——高质量留出集需要隔离，以防训练污染。

| 来源路径 | 已公开的真实案例 | 数据实际形态 | 能训练/评估什么 |
|---|---|---|---|
| **外部采购：OpenAI × Handshake Project Stagecraft** | 剧院财务经理根据工会集体谈判协议，制作巡演音乐家周工资 Excel 表 | 职业人设、真实任务背景、目标、参考材料、目标交付物，以及多轮专家审核 | 将专业“交活”转为可复核的任务；不只是回答“什么是财务管理” |
| **厂商自建：OpenAI Codex** | 真实软件工程任务；例如 Gitea 一项涉及 232 个文件、3,541 行变更的重构任务 | 代码仓库、任务、开发环境、测试/检查程序、模型编辑和测试的轨迹、最终结果 | 按要求开发、调试、重构和代码审查；测试结果可提供 RL 反馈 |
| **厂商自建：Anthropic RL 环境** | Anthropic 公开研究中使用了曾在前沿训练或环境质检中识别出的 80 个易被奖励作弊的 RL 环境 | 多任务可执行环境、奖励/验证逻辑与 Agent 轨迹；公开材料包含可运行代码与沙盒示例 | 说明前沿训练须持续建设、审计和修复环境；80 个只是该项安全研究的有偏样本，**不可外推为全部训练环境** |
| **供应商目录：Mercor** | APEX Agents、SWEBench Ext.、TerminalBench、BrowseComp | 企业应用克隆或容器化任务、文件系统/工具、验证器与专家评审 | 供应商可授权的现货任务；**不等于** OpenAI 或 Anthropic 已采购目录中的每一项 |
| **用户会话：OpenAI / Anthropic（受产品与用户设置约束）** | ChatGPT、Codex、Claude 消费者产品和 Claude Code 的相关会话 | 对话、代码会话、用户偏好及部分浏览器交互数据；反馈会保留关联会话 | 真实使用中“需求 → 查看/修改文件 → 执行命令 → 用户反馈 → 再修改”的闭环；不代表每条会话必然进入训练 |

#### A. OpenAI 外采的专业工作任务：Project Stagecraft

2026 年 4 月，Business Insider 根据项目文件报道，Handshake AI 的 Project Stagecraft 为 OpenAI 组织数千名专业人士制作职业任务，覆盖飞行员、药剂师、土壤科学家、机械工程技术人员和财务经理等。任务要求贡献者建立职业人设，并给出真实工作中的上下文、目标、参考资料和交付物；供应商安排两轮审核，OpenAI 再进行一轮审核。

公开样本是：一名剧院财务经理依据随附的工会集体谈判协议（CBA）摘录，制作可供音乐承包商提交巡演雇佣音乐家周工资的 Excel 表。这份“数据”的最小可理解单元是：

| 组成 | 该案例中的对应物 |
|---|---|
| 任务说明 | 按合同制作每周工资计算表 |
| 工作背景 | 剧院、巡演、本地音乐家与薪酬流程 |
| 参考材料 | CBA 摘录 |
| 目标交付物 | 可用的 Excel 工资表 |
| 质量控制 | 供应商审核 + 行业专家审核 + OpenAI 审核 |

这类案例是“外采真实工作任务”的直接证据；报道基于内部项目文件，OpenAI 和 Handshake 未对媒体置评，因此应标为**调查报道/中高可信度**，而非公司正式确认的采购合同。

#### B. OpenAI 自建的真实软件工程任务

OpenAI 明确披露，2025 年的 codex-1 在多种环境中的真实软件工程任务上进行强化学习，目标包括精确遵循要求、贴近人类工程风格，并持续运行测试直至通过。后续 GPT-5-Codex 的训练重点包括从零构建项目、增加功能和测试、调试、大规模重构与代码审查；其公开的 Gitea 重构评测示例涉及 232 个文件、3,541 行变更。

因此，Coding 数据不应被简化成“代码文本”。更接近的结构是：**现有仓库 + 工程任务 + 可运行开发环境 + 测试/检查器 + 修改过程 + 成败结果**。这里测试和检查器既是验收标准，也是强化学习的可验证奖励来源。

#### C. Anthropic 自建 RL 环境：训练基础设施也是数据产品

Anthropic 在 2026 年一项奖励作弊研究中说明：其选取了 80 个曾在前沿模型训练或环境质量审核时识别为易受奖励作弊影响的 RL 环境进行训练；这些环境后来均已修复或移除。该披露的价值不在于“80”这一数量，而在于它证明了生产训练中存在需要反复构建、监测、修复的环境和评分器。论文还提到，内部 Claude Code 沙盒审计会从真实内部会话衍生种子，让模型在真实沙盒中执行命令。

结论应保持克制：这是 Anthropic **曾用于生产训练或质检的、专为安全研究挑选的漏洞环境**，不能据此推断其完整训练环境总量或类别构成。

#### D. Mercor 的现货目录：供应商卖的不是 PDF

Mercor 的公开目录可作为供应商交付物的具体横截面。页面称所有任务由领域专家创建、审核和同行评审，以下是其自述的目录规模：

| 产品 | 任务与环境形态 | 公开规模 |
|---|---|---:|
| APEX Agents | 高保真企业应用克隆中的长程专业任务，要求浏览文件、保持上下文并完成工作 | 2,620 个任务、8 个领域 |
| SWEBench Ext. | 真实 GitHub Issue、多文件补丁、Docker 容器与 CI 验证 | 12,000 个任务 |
| TerminalBench | 多阶段终端、DevOps 与仓库任务，带完整性检查 | 10,000 个任务 |
| BrowseComp | 搜索、判断权威来源并综合证据的端到端网络研究任务 | 3,558 个任务 |

Mercor 另公开过一次直接用于后训练的实验：以 1,928 个专家制作的 APEX-Agents 现货任务，对开源 Qwen 模型进行 RL 后训练。每个任务世界包含数十份 PDF、表格、幻灯片、聊天和邮件服务器；任务交付还可包含沙盒镜像、MCP 服务和环境内验证器。这是“任务 + 环境 + 验收标准”能够直接形成训练闭环的公开演示，但其对模型效果的表述仍属于供应商自己的实验与营销材料，可信度应低于独立复现。

#### E. 用户会话是另一条数据来源，但边界更严格

Anthropic 现行消费者产品政策称：当用户允许模型改进、会话因安全原因被审查或用户明确选择加入训练时，其可使用相关聊天和 Coding 会话来改进模型。可用内容包括完整关联对话、内容、自定义风格/偏好和 Claude for Chrome 使用中收集的数据；原始连接器内容（如 Google Drive、远程或本地 MCP）不包含在内，除非被直接复制进对话。用户提交赞踩反馈时，关联会话也可能用于研究或训练。

OpenAI 的现行政策也作了相同的大类区分：个人服务（包括 ChatGPT、Codex）可能使用内容改进模型，用户可退出；ChatGPT Business/Enterprise 与 API 的输入输出默认不用于训练，除非明确选择加入。Codex 还具有独立的完整环境训练控制项。

因此，会话来源的潜在数据形态是“用户提出需求 → Agent 读取上下文/文件 → 调用工具并修改 → 运行命令 → 用户反馈 → 再迭代”。但必须明确：这是**允许收集与可能使用的范围**，不等于每条个人会话都进入训练；两家的政策均将个人产品与商业产品/API 的数据处理分开说明。

## 三、五类正在爆发的数据 → 对应五项将加强的能力

先看正在被构造成什么样的“任务 + 环境 + 验收标准”，再看谁在提供或采购它；后者是规模信号，前者才直接对应模型将获得的能力：

### 3.1 RL 环境 / Agent 轨迹数据 → "干活"的能力（最确定的下一个爆发点）

数据形态从"静态问答"变成了**可执行的仿真软件环境**。对应的能力是：工具调用、任务规划与拆解、出错后自适应、多步长程任务。

目前最好的模型在 Surge 的测试里**约 40% 的任务仍会失败**，企业级 Agent 任务完成率只有约 30%——巨大的提升空间 + 最大的采购额，这是未来 1–2 年模型能力差异的主战场。各家模型卡也在印证：MiniMax M2.5 用了 20 万+ 训练环境，Qwen3.5 用了数百万个 Agent 环境。

**硬信号**：
- Anthropic 管理层讨论过**一年内花超 10 亿美元**采购"RL 环境"——这一个数字就接近 Surge AI 2024 年的全部营收
- Surge 专门成立了 RL 环境部门，到 2026 年 8 月 RL 环境已成为其**最大产品**
- Scale、Mercor 也在全力跟进
- 国内 IDC 判断一致：需求正从大规模通用采集转向 **Agent 执行轨迹、多步任务规划、工具调用、企业工作流**数据

### 3.2 可验证推理数据（数学/代码/科学）→ 长链推理能力

自 DeepSeek R1 在 2025 年 1 月公开"可验证奖励强化学习"配方后，专家撰写、有标准答案可自动核验的难题成了高价商品。这类数据直接喂养的是模型的多步推理、证明、调试能力——数学奥赛级表现、科研辅助能力会持续增强。

### 3.3 专家工作流数据 → 垂直专业能力（医疗/法律/金融/CAD/形式化证明）

数据公司招的不是标注员而是医生、律师、注册会计师，做的是真实工作场景的诊疗路径、尽调分析、合同审校。前沿模型在专家领域的自主完成能力差距仍然巨大（TB3 测试显示与 SOTA 差距的 75.8% 来自专家环境中的长程任务而非编码本身）。预期模型会越来越像"能独立交活的初级专业人士"，而不只是"能答题的助手"。

### 3.4 具身智能数据 → 物理世界操作能力（被数据卡得最死）

机器人/VLA 模型需要遥操作视频、动作轨迹、力觉时序，以及价值极高的**失败样本**（抓取滑落在哪一帧、因为什么失败、怎么恢复）。

瓶颈是数据量级：要实现机器人的"ChatGPT 时刻"大约需要 1.1 万亿 token 的训练数据，而当前全球高质量真实数据只有几十万到百万小时级。这意味着具身能力是**上升空间最大、但速度最不确定**的方向——数据一旦突破，能力会跳变。

### 3.5 合成数据 → 边际补能，但受限于"原始性"

IDC 预期合成数据会成为第二增长引擎，但它只能放大已有能力分布，天花板仍由人类专家数据决定。

### 3.6 为什么 Coding 率先创造最大规模的 LLM / Agent 需求

Coding 是目前少见的、同时满足**价值高、频率高、可自动验证、可在数字环境内执行**的知识工作。这里“需求”应拆为三层：企业购买意愿、单项任务的推理/工具调用量、以及为训练而投入的环境与轨迹。Coding 在三层都占优，但根源不是开发者人数，而是任务结构。

| 需求形成条件 | Coding 的天然条件 | 其他知识工作的常见缺口 |
|---|---|---|
| 可复用任务来源 | 代码仓库、Issue、PR、文档与依赖关系天然相连；公开开源生态还提供大量底料 | 专业流程和材料锁在企业、客户或监管系统中，难外部复用 |
| 可执行环境 | 编辑器、终端、Git、CI/CD 和浏览器本来就可程序化操作 | CRM、ERP、邮件、财务系统权限分散，集成成本高 |
| 结果验证 | 编译、单测、集成测试、Lint、类型检查和回归测试可给出快速反馈 | “报告是否有价值”“客户是否满意”等结果反馈慢、主观且噪声大 |
| 商业价值 | 开发者成本高、软件交付是多数组织的瓶颈；效率提升可映射到交付速度和技术债 | 价值常难归因，且错误的合规/责任成本很高 |
| 任务强度 | Agent 要读仓库、查依赖、改多处文件、跑测试并修复，单项任务对应长上下文和多轮工具调用 | 很多助手型任务一两轮对话即可结束，难形成长轨迹需求 |

软件的特殊性还在于其“需求反弹”：开发成本下降后，原本不值得做的内部工具、自动化和小功能会被启动，进而再增加代码、测试、审查和运维工作。这使模型并非只替代既有工时，也会扩大软件总产量。

公开使用数据支持 Coding 的相对突出，但不能直接推断整个 LLM 行业收入结构：Anthropic 对 2026 年 2 月样本的分析中，Claude.ai 约 35% 的对话对应计算机和数学类工作，且 Coding 正迁移到更自动化的 API/Claude Code 工作流；其早期 Claude Code 研究中，79% 会话被归为自动化，普通 Claude.ai 为 49%。因此，Coding 的调用权重很可能被短对话的会话口径低估。

### 3.7 为什么暂时看不到“下一个 Coding”

这不是简单的“其他行业需求不够大”，而是多数行业还没有形成可产品化的**任务合同**：

> 明确输入 → 明确操作边界 → 可机器验收的结果 → 可控权限 → 高频重复。

Coding 同时跨过了两道门槛：一是有可规模训练的任务、环境与验证器；二是有可规模部署的沙盒、版本控制和回滚机制。财务运营、客服、销售、法务、研究和企业数据分析均有很大潜在价值，却通常至少卡在一处：私有数据、验收弱、系统权限、合规责任或低频非标准流程。

因此，下一波数据供给很可能不是第二个 GitHub 式的公开市场，而是企业内部的封闭飞轮：把系统记录、文档、权限、工作流和验收标准打包成任务环境，再由真实使用与人工复核持续产生轨迹。此时卡点从模型能力转向数据可访问性、系统集成、权限治理和质量度量。企业调研也普遍把工作流映射、数据/上下文基础设施与治理列为 Agent 从试点走向生产的主要约束。

优先观察的候选场景不是泛泛的“白领工作”，而是可部分机器验收的流程：财务对账与应收应付、IT 运维/安全、受限范围内的客服工单和数据运营。它们可能先形成高价值的**私有任务系统**，但不一定形成规模类似 Coding 的开放数据供给。

### 3.8 GPT-6 Astra 展示 3D 建模，传递了什么信号

2026 年 9 月，OpenAI 在开发者博客展示 GPT-6 Astra 在 Codex 中按自然语言需求调用 Blender Python API（`bpy`）生成**可编辑** 3D 场景，查看预览渲染后修正几何与光照，并把场景导入 Unreal Engine 5 做漫游。它宣传的核心不是一次性“生成一张 3D 图”，而是：

> 需求 → 操作专业软件 → 观察渲染/视口结果 → 迭代修改 → 交付可继续编辑的工程资产。

这提示 3D 是少数可能具备“可执行环境”的非 Coding Agent 方向。Blender/Unreal 可以提供一部分程序化反馈：场景是否能打开、脚本是否运行、几何/材质/相机是否存在并可编辑、渲染或引擎是否正常运行，以及物理/碰撞/路径/性能等局部检查。因此，潜在的数据单元可写作：**设计需求 + 3D 工程文件 + 工具/脚本操作 + 渲染或视口反馈 + 人工修改与验收**。

但这还不是“第二个 Coding”。3D 的质量判断大量取决于审美、动线和客户偏好，远弱于单元测试；高质量工程文件与资产还受版权、许可、客户保密和软件版本约束；而建筑、工业 CAD/BIM 的最终交付有尺寸、结构、法规与责任门槛。OpenAI 的案例本身也说明，几何和渲染检查不构成建筑设计或工程合规认证。

所以应把这次展示理解为**专业创作软件 Agent 的能力信号**，而非已验证的数据或商业需求拐点。后续的硬信号应是：大规模可复现的 Blender/Unreal/CAD/BIM 任务环境；对“可编辑场景正确性”而非视觉偏好的评测；以及进入游戏资产、产品设计、建筑方案迭代或数字孪生等付费生产工作流的证据。若这些未出现，3D 更像 Coding Agent 的能力外溢——底层仍是模型写脚本、调用工具、看结果、再修正。

### 3.9 数据量级：不要把任务数、环境数和轨迹数混为一谈

跨数据类型不能直接比较“有多少条”。网页/代码适合按 token 计，具身数据适合按小时、轨迹和帧计，专家工作流按独立任务计，RL 则至少要同时看环境（或任务世界）、任务、rollout 轨迹和轨迹 token。应区分三件事：

- **存量**：独立文本、代码文件、任务或环境的数量；
- **生成流量**：模型在训练中从同一任务反复跑出的轨迹数量；
- **单位复杂度**：一条样本是几十 token 的问答，还是十万 token、几十步工具调用的长程任务。

下表是公开案例的**可见量级**，并非任何一家前沿模型的完整训练配方，也不应被理解为可加总的市场总量：

| 数据类型 | 合适单位 | 公开可见量级 | 参照案例 |
|---|---|---:|---|
| 网页文本 | token | \(10^{13}\) | FineWeb 清洗去重后的英文网页超过 18.5T token |
| 公开代码 | token / 文件 | \(10^{11}\)–\(10^{12}\) token | The Stack v2 训练集约 900B token、30 亿+文件 |
| 通用人工 SFT / 偏好 | 示范、偏好对 | \(10^4\)–\(10^6\) | 公开 No Robots 为 1 万专家示范；HH-RLHF 有约 16.1 万训练样本 |
| 专家工作流任务 | 独立任务 | \(10^3\)–\(10^5\) | Mercor 目录自述 5 万+任务；APEX Agents 为 2,620 个任务 |
| RL 环境任务库 | 任务 / 任务世界 | \(10^2\)–\(10^4\) 常见，头部目录可达 \(10^4\)–\(10^5\) | Mercor 的 SWEBench Ext. 1.2 万任务、TerminalBench 1 万；Surge CoreCraft 以 1,000 个训练任务做公开实验 |
| RL 轨迹 | rollout / episode / token | \(10^6+\) 可由训练反复采样产生 | Mercor 公开配方中的单条轨迹跨度为 2K–128K token |
| 真实具身数据 | 小时、轨迹、帧 | \(10^3\)–\(10^5\) 小时仍属高价值；人类行为视频可达 \(10^6\) 小时 | 公开真实机器人 RL 数据已有 1,000+ 小时样本；HumanNet 为百万小时级人类视频项目 |
| 合成数据 | token、样本、轨迹 | 无自然上限 | 由教师模型、算力和筛选/验证机制决定；绝对数量的解释力最低 |

#### RL 环境：是“数据 + 执行基座 + 轨迹工厂”

“RL Environment 不算数据、但算产生数据的基座”这一理解方向正确，但需要更精确：环境不是纯软件基础设施。它包含任务、初始系统状态、文件/记录、模拟应用或工具接口、rubric 与 verifier 等**静态训练资产**；模型进入后，环境再产生观察、动作、状态变化和奖励构成的**动态轨迹数据**。

```text
专家任务、文件、规则
        ↓
RL 环境 = 初始状态 + 工具/软件 + 任务 + 验证器
        ↓ 模型反复执行
轨迹 = 观察 + 动作 + 状态变化 + 奖励
        ↓
RL 后训练
```

因此，1 万个 RL 任务绝不等于“只有 1 万条数据”。举例说，若每任务每轮采样 64 条轨迹、训练 10 轮，便会产生 640 万个 episode；若平均每条 2 万 token，则对应约 1,280 亿 token 的交互经验。此处仅为量纲演示，真实值取决于 rollout 数、过滤率、训练轮次与任务长度。

但轨迹数量也不能替代环境质量：模型可能在同一个有漏洞的 verifier 上反复刷出百万条“成功”轨迹，学习到的却是钻规则空子。实际应按以下顺序判断数据价值：

> **独立高保真任务世界数 → 验证器可靠性与任务覆盖度 → 每任务可产生的有效轨迹数 → 轨迹长度与失败—纠错密度。**

这进一步解释 Coding 的异常地位：它同时拥有约 \(10^{12}\) token 级公开代码存量，以及可持续产生交互经验的编译、测试和 CI 环境。多数专业领域现阶段只有 \(10^3\)–\(10^4\) 级私有任务环境，缺口不是文本量，而是可复用的任务世界与可靠验收。

### 3.10 能力演进排序

> **聊天、写作、知识问答基本饱和（通用语料已近耗尽）→ 推理持续变强 → Agent/干活能力是当前最大变量 → 垂直专业能力稳步提升 → 具身物理操作是最远但最大的彩票。**

旁证：前沿数据层（RLHF、推理、RL 环境）没有便宜版本，而底层的批量标注价格在持续下跌——钱的态度比任何预测报告都诚实。

## 四、市场价格阶梯与定价逻辑

### 4.1 市场总规模

数据标注/采集市场 2025 年约 23–49 亿美元（不同口径），增速约 28–33%，预计 2030 年到 100–170 亿美元量级；而仅"卖给前沿实验室的人类数据 + RL 环境"这一层，50 多家供应商合计年收入已达约 85 亿美元。

头部公司收入：Surge 2024 年 12 亿美元，Scale 2025 年接近 10 亿美元，Mercor 从 2024 年 5 月的 100 万美元暴涨到 2026 年 6 月的约 20 亿美元年化收入。

### 4.2 七层价格阶梯

整个市场的价格**跨度超过 1000 倍**：

| 层级 | 数据类型 | 典型价格 |
|---|---|---|
| **1. 免费层** | 公开网页语料（Common Crawl 等） | 几乎免费，只算清洗的算力成本 |
| **2. 众包微任务** | 图像分类、简单打框 | 框 $0.02–0.10/个；图像分类 $0.03–0.10/张；微任务最低 $0.001/条 |
| **3. 批量标注** | 分割、语音、文本 NLP | 语义分割 $0.10–3/张；语音 $0.10–0.30/分钟；文本 $0.01–0.15/条 |
| **4. 通用人类反馈** | SFT 问答对、RLHF 偏好排序 | 通用 SFT 对 8–25 澳元/对；RLHF 对比 15–50 澳元/次；RLHF 每条对比约 2–5 美元 |
| **5. 领域专家数据** | 医疗/法律/金融/代码标注 | 专家级 SFT 对 25–75 澳元/对；领域 RLHF 40–120 澳元/次；中国行情约 100–200 元/条；按小时：法律专家 $85–120，执业医师 $130–300 |
| **6. RL 环境/推理任务** | 专家设计的可执行任务 + 评分规则 | **$200–2,000 一个任务**；专家时薪 $75–300+ |
| **7. 版权/战略级资产** | 内容授权、公司并购 | 见下表 |

**版权授权层价格（单笔交易）**：

| 交易 | 价格 | 特点 |
|---|---|---|
| OpenAI–News Corp | 5 年约 2.5 亿美元 | 最大单笔新闻授权 |
| Reddit–Google / –OpenAI | 约 6000 万 / 7000 万美元**每年** | 按年订阅式收费 |
| Amazon–纽约时报 | 每年 2000–2500 万美元 | — |
| Shutterstock | 2023 年 AI 授权收入 1.04 亿美元 | 多买家、经审计的真实数字 |
| Anthropic 版权和解 | 15 亿美元（集体诉讼和解） | 不买的代价 |

最顶端还有"数据资产并购"：Meta 148 亿美元入股 Scale；Anthropic 讨论过一年花超 10 亿美元买 RL 环境；2026 年 8 月谷歌被报道开价 15 亿美元+ 收购 RL 环境公司 Mechanize 的团队和技术。

### 4.3 定价的底层逻辑

三个规律：

1. **稀缺性定价，不是工时定价**。执业医师标注一条临床推理的价值和普通众包天差地别——"医生不会比 MTurk 工人高 30 倍产出，但每条标注的价值结构性不同，供给也被职业资格锁死"。海湾阿拉伯语方言标注是英语的 2–3 倍价，纯粹因为合格的母语标注员少。
2. **量在跌、质在涨**：静态批量标注价格在持续下降（且不断被自动化替代），而 RL 环境类需求在暴涨——同一个市场两头分化。量的折扣是真实的：5 万条以上降 5–15%，百万级降 25–40%，但专家类数据**不因量降价**。
3. **地域差价巨大**：肯尼亚/尼日利亚时薪 $2–8，东南亚 $5–12，美国通才 $25–60，美国专家 $130–300——同样的任务差出一个数量级。

## 六、判断框架与投资启示

### 6.1 可长期使用的判断框架

> **先看数据被包装成什么任务、环境和验收机制，就知道模型下一步会强什么；再看谁能稳定生产这种数据，才判断其商业壁垒。看哪类数据稀缺，就知道哪个能力会卡住。**

### 6.2 关键判断要点

- **看价格分层就知道壁垒在哪**：越往上层（专家数据、RL 环境、版权库），越难被复制，这正是 Surge/Mercor 能两年做到十亿级收入、而传统标注商 Appen 萎缩的原因
- **任何"市场总规模"数字都要打折看**：因为最值钱的交易（私有合同）都不披露
- **价格的走向比绝对值更有信息量**：便宜的在更便宜，贵的在更贵——中间地带正在被 AI 自动标注吃掉

### 6.3 当前阶段定位

| 能力方向 | 数据饱和度 | 模型能力阶段 | 数据投入热度 |
|---|---|---|---|
| 聊天、写作、知识问答 | 近饱和 | 成熟 | ↓ 下降 |
| 长链推理（数学/代码） | 中等 | 快速进步中 | → 稳定 |
| Agent/工具调用/任务执行 | **最稀缺** | **早期，40% 失败率** | **↑ 最热** |
| 垂直专业能力（医疗/法律/金融） | 低 | 初级阶段 | ↑ 上升 |
