# DeepSeek KV Cache 技术演进与生态跟进

整理/核对日期：2026-09-22。资料检索截至同日；生态跟进部分结合 2026-09-21 的核查。

本文整合用户提供的模型介绍、技术跟进情况和技术时间线。技术及性能数字注明官方引用口径，不视为独立实测；研究判断另行标注。原始模型介绍保留在本文后半部分。

## 1. 总体脉络

可以按六类机制梳理：MLA → DSA → CSA/HCA → CSA2 → FP4 主 KV 缓存 → SWA Bounded Replay。CED 作为与这些机制协同的计算架构单列。

这是一种研究分类，不能据此断言 DeepSeek 恰好拥有六项原创发明，也不能把各代收益直接连乘。不同代际会替换架构、改变层数、精度和缓存口径。

### CSA/HCA 的压缩比如何理解

用户材料给出的 CSA 约 4:1、HCA 约 128:1，可先作为待核对的配置值保留，不能当作所有层和所有后续模型的固定定义。还需区分压缩步幅、单条目覆盖的原始 token 数，以及相邻条目是否重叠；本次未据此推导模型整体缓存量。

### CED 的位置

Causal Encoder-Decoder（因果编码器—解码器）主要通过非对称路径减少输入处理计算，并与 KV 共享协同。应将其与缓存压缩机制区分，不给 CED 单独指定未经消融验证的缓存压缩倍数。[S4]

## 5. 研究判断与后续关注

**研究判断：** DeepSeek 的路线逐渐覆盖 KV 表示宽度、历史条目数量、层间共享、数值精度和持久化策略。其竞争力需要结合这些机制在实际服务中的协同效果评估。

“技术已被他人采用”与“成本优势是否持续”没有一一对应关系。后续比较应统一模型质量、上下文长度、输入输出比例、缓存命中率、并发、硬件和延迟要求，分别观察 HBM 占用、持久化容量、传输带宽与每任务成本。

待补证据：V4/V4.1 的正式发布公告、V4 各层压缩配置、各代缓存布局的可重复复算、相同工作负载下的第三方成本测试。

**研究推断：** 单请求缓存需求降低，可能增加同一硬件可承载的并发，也可能支持更长上下文和更多 Agent 调用。因此不能只由“每 token 缓存变小”推出“整个行业的内存需求下降”。评估硬件影响时，应同时观察单位需求、调用规模、上下文长度和缓存保留时间。

“Flash 反超旗舰”的长期意义也应落实为同等任务成功率下的完成成本和耗时。小激活参数本身不足以证明整体成本更低，还需计入权重与条件记忆、带宽、工具调用、重试及输出长度。

## 7. KV Cache 放入主机 DRAM 和 SSD：起源与用途

核查日期：2026-09-22。这里的 DRAM 特指 CPU 主机内存；HBM 在器件类型上也属于 DRAM，研究中应避免混用。

**结论：行业公开方案至少在 2023 年已有；DeepSeek 自身可确认的硬盘缓存上线节点是 2024-08-02，处于 V2 时期。不能把 GPU 之外保存 KV Cache 的做法归为 V4/V4.1 才出现的创新。** 以下是可确认的历史节点，不主张已经找到全球首创。

| 时间 | 代表工作 | 与 DRAM / SSD 的关系 |
|---|---|---|
| 2023-03-13，论文提交 | FlexGen | 将权重、激活与注意力缓存的放置纳入 GPU、CPU 内存和磁盘的统一调度，服务显存受限、偏吞吐的生成任务；是运行时卸载的明确早期实例。[论文](https://arxiv.org/abs/2303.06865)、[官方项目](https://github.com/FMInference/FlexLLMGen) |

### 两种用途必须分开

1. **运行时卸载：** 正在处理的请求，其 KV Cache 超过可用显存时，将部分状态放到主机内存或磁盘，按需搬运，或在 CPU 上执行部分计算。主要解决容量问题，代价可能是传输延迟。
2. **跨请求缓存复用：** 已算过的公共前缀、文档或多轮对话状态先保存，后续兼容请求命中后加载，从而减少重复 Prefill。这里的“保存”不一定具有数据库式的断电持久性，尤其是放在易失 DRAM 中时。

可用“H​​BM 保存当前热点、主机 DRAM 承接较大缓存、SSD 保存更多可复用状态”理解典型分层，但具体系统未必必须逐级经过这三层。缓存写到 SSD 不表示 GPU 在每一步生成时都直接从 SSD 读取全部历史 KV。

### 对 DeepSeek 路线的修正理解

V2 的 MLA 已为低成本硬盘缓存提供条件；V4/V4.1 延续的是降低缓存体积、搬运负担及必须保存的状态量。前文 Bounded Replay 的意义是进一步改变局部状态的保存与恢复策略，而非首次把 KV Cache 放到 GPU 之外。[2024 年公告](https://www.deepseek.com/news/context-caching/)、[V4.1 报告](https://arxiv.org/html/2609.19969v1)

### 与 Grok 时间线的对照补充（2026-09-22）

总体结论一致：2023 年已有公开的 KV 卸载方案，DeepSeek 并非首次提出者。但“最早”宜改为“至少在 2023 年已有明确公开实例”，不作全球首创认定。

- **vLLM 的时间需纠正。** 2023 年 PagedAttention/vLLM 论文第 4.5 节已描述请求抢占时将 KV 换出到 CPU 内存。2025 年的相关 RFC 针对 V1 引擎的新卸载实现，不能写成 vLLM 直到 2025 年才开始支持 CPU KV 卸载。2026-01-08 的官方博客介绍了新的 OffloadingConnector。旧版抢占换出、新版前缀缓存扩展、模型权重卸载是不同功能。[2023 年论文](https://arxiv.org/html/2309.06180v1)、[2025 年 V1 RFC](https://github.com/vllm-project/vllm/issues/19854)、[2026 年官方博客](https://vllm.ai/blog/2026-01-08-kv-offloading-connector)。Context7 检索的[当前文档](https://docs.vllm.ai/en/stable/design/metrics)也确认旧版抢占换出与 V1 的区别。
- **不同系统不能统一描述成三层冷热缓存。** InfiniGen（2024）的重点是 CPU 内存中的 KV 管理和选择性预取；不能仅凭它采用 offloading 就说它实现了完整 SSD 层。AttentionStore/CachedAttention（2024）则明确研究跨轮对话的分层保存、逐层预加载与异步写回。[InfiniGen](https://arxiv.org/abs/2406.19707)、[CachedAttention](https://arxiv.org/abs/2403.19708)。FlexGen 更准确的概括是张量放置与传输调度，不宜简单套用“按冷热换出不活跃 KV 块”。
- **2025–2026 不应统一称为生产成熟期。** Mooncake 在 2024 年已公开；Swarm 和 KVDrive 分别有 2026 年 3 月、5 月的论文，前者重点是多 SSD 并行 I/O，后者研究 GPU/DRAM/SSD 多层管理。论文实验不能单独证明广泛生产部署。[Swarm](https://arxiv.org/abs/2603.17803)、[KVDrive](https://arxiv.org/abs/2605.18071)。
- **DeepSeek 的关键节点应补齐。** Grok 只讨论 V4.1，遗漏了 2024-08-02 的硬盘缓存上线公告。这一节点对理解其商业部署历史比“2026 年使用多层缓存”更关键。[官方公告](https://www.deepseek.com/news/context-caching/)
- **直接 GPU–SSD 路径另行核查。** Grok 提到 GPUDirect Storage，但未给具体 KV 系统与首次采用日期，本次不将其认定为 2025–2026 才出现，也不据此推断可以消除 SSD 带宽瓶颈。

据此采用的阶段划分：**2023 年已有卸载与复用研究 → 2024 年出现分层会话缓存及明确商业服务节点 → 2025–2026 年继续发展引擎集成、异步传输、多 SSD 调度与架构压缩。** 这是研究梳理，不是严格划分的产业阶段。

### 8.4 SSD 需求：增长因素与效率抵消

**材料中的市场说法，均待核验：** 北美 CSP 与中国推理场景推动企业级 SSD 需求上调；价格持续上涨；KV Cache 将贡献显著比例的 AI 数据中心 NAND 需求。当前没有原始报价序列、出货数据、预测比例或机构报告，不将这些说法写成已证实的市场结论。

- **KV Cache**：保存历史 token 的 Key/Value 状态，供后续注意力计算使用。

# 原始材料：DeepSeek-V4.1-Flash 介绍

---

**DeepSeek-V4.1-Flash** 是 DeepSeek 于 2026 年 9 月 10 日左右正式发布的最新模型（技术报告 arXiv:2609.19969，约 9 月 17 日上传），也是本月架构优化的核心成果。它是全新架构家族中的首个（也是目前最小）模型，定位为高效、多模态、长上下文的 MoE 模型，特别针对 **输入重（input-heavy）的 Agent 场景** 和 **百万级 token 上下文** 进行优化。

官方目标是：更高能力上限、更快推理、更高吞吐，同时可扩展到更大模型。模型已上线 API（调用名 `deepseek-flash`），权重开源（MIT 许可），并逐步取代 V4-Pro 和旧版 V4-Flash。

### 模型基本规格

- **总参数**：骨干（backbone）约 **552B**，另加 **196B Engram** 条件记忆模块。
- **激活参数**（非对称）：
  - Prefill（处理输入/提示）阶段：约 **8B**。
  - Decode（生成输出）阶段：约 **16B**。
- **上下文长度**：最高 **1M tokens**。
- **多模态**：原生支持文本 + 图像输入（视觉编码器 + MLP 投影器将图像转为嵌入，与文本联合处理）。
- **预训练数据**：45T 多模态 token。稀疏注意力从 64K 序列长度开始从头训练（无密集注意力预热），约 34T token 时扩展到 1M。
- **后训练**：标准 SFT + RL + On-Policy Distillation，重点在大规模自动化数据合成、环境构建和可控推理努力（reasoning effort，1–100 的标量接口，可在部署时权衡成本与质量）。
- **MoE 细节**（参考公开解读）：每层通常 1 个共享专家 + 大量路由专家（如 384），每 token 激活约 6 个。

与前代 V4-Flash（约 284B 总参数、13B 激活）相比，总参数显著增加，但实际推理成本更低、性能更强（多项 Agent 基准上超过或持平 V4-Pro）。

### 核心架构优化（围绕 KV Cache 极致压缩）

报告标题即为 *Pushing the Limits of KV Cache Compression*，几乎所有设计都服务于降低 HBM（高带宽内存）、SSD/主机内存占用和数据传输带宽，解决长上下文 Agent 的主要瓶颈。

#### 1. Causal Encoder-Decoder (CED) 非对称架构

这是最显著的结构变化：

- 40 层 Transformer 分成前 **20 层因果编码器** + 后 **20 层解码器**（均为因果注意力，只看左侧 token）。
- 解码器的**全局 KV Cache** 直接由编码器最终隐藏状态投影生成，而非每层自己计算。
- 效果：大多数输入 token 只需经过编码器，大幅降低 Prefill 计算量（接近减半）。Prefill 只激活 8B 参数，Decode 激活 16B，特别适合输入远多于输出的 Agent 工作负载（如多轮工具调用、长文档处理）。

#### 2. Compressed Sparse Attention 2 (CSA2)

在 V4 的 CSA/HCA 混合基础上进一步升级，改为**纯 CSA2**：

- 结合序列维度压缩、稀疏选择和**跨层复用**。
- 三种静态模式：
  - **Full**：自己生成全局 KV 并进行索引。
  - **Reindex**：复用前层全局 KV，用自己的 indexer Q 重新打分并选择新的 Top-K。
  - **Reuse**：直接复用前层全局 KV 和 Top-K 索引，只做稀疏注意力。
- 每层保留自己的全局 Q 和局部 Sliding-Window Attention（SWA，窗口通常 128）。
- 解码器中还有**Hierarchical Sparse Indexer**，进一步限制深层索引成本。
- 配合 **FP4 主 KV Cache**（E2M1 格式等），全局 KV Cache 降至每 token **约 890 字节**（约为 V4-Flash 的 **1/4**，相对早期 V1 压缩约 437 倍）。

前 2 层通常纯 SWA，其余层使用 CSA2（编码器压缩比 m=2，解码器 m=1 等配置，Top-K 约 512）。

#### 3. 部署级优化：SWA Bounded Replay

- 像 V4 一样每层都有 SWA（局部窗口）。
- 不再持久化完整 SWA KV 到 SSD，而是通过**只重放最近窗口（n\_win）token** 近似重建状态。
- 性能损失可忽略，持久化 KV Cache 进一步降至 V4-Flash 的约 **1/8**。
- 全局 KV（长寿命）与编码器 SWA KV（短寿命）分开管理。

#### 4. 其他高效扩展

- **Single-Pass mHC**：升级 V4 的 Manifold-Constrained Hyper-Connections，配合 Mega-mHC 内核，将激活内存流量减半。
- **Engram 条件记忆模块**：约 196B 参数，通过 token 的 2-/3-/4-gram 哈希查找稀疏访问（插入在特定层，如 1 和 14），增强知识容量而不显著增加激活参数。
- **DSpark 推测解码**：半自回归草稿生成 + 置信度调度验证，提升生成速度。
- 整体效果：单 token Decode FLOPs 随上下文长度增长几乎平坦（从 4K 到 1M 仅增加约 1/4），远优于前代。

### 训练与系统优化

- **训练基础设施**：支持解耦视觉编码器执行、长序列图像分片平衡、跨阶段注意力状态共享等。
- **推理系统**：通信-计算重叠、Engram 表分片、内核融合（CSA2 Reuse 模式 prefill 仅约 15 个内核、decode 约 11 个）。
- 后训练无新算法，主要靠数据工程和大规模 Agent 任务合成（包括多 Agent 场景）。

### 性能亮点

- 在多个 Agent 基准（如 Terminal-Bench、DeepSWE、AutomationBench 等）上达到或接近闭源前沿模型水平，日常编码和白领工作流表现出色。
- 推理能力与顶尖开源模型（如 Kimi-K3、V4-Pro）相当。
- 多模态方面，在视觉推理和专业图表理解上超越部分开源竞品，支持真实视觉 Agent 工作流（如前端开发、办公自动化中的截图自校正）。
- 整体参数效率高：Base 模型用约 1/3 总参数和 1/4 激活参数，即可达到 V4-Pro-Base 的世界知识/推理/编码水平，并在部分 held-out 评估上提升 5–10%。

### 实际影响

- **成本大幅降低**：Agent 场景中缓存命中费用占比高，KV Cache 压缩直接降低 HBM/SSD 需求和 API 费用（官方已下调定价，并继续峰谷电价模式）。
- DeepSeek 已宣布逐步下线 V4-Pro，相关请求路由到 V4.1-Flash。
- 开源权重 + 技术报告，便于社区部署优化；支持大规模（如 2000 GPU + 存储集群）部署咨询。

总的来说，V4.1-Flash 通过 **CED 非对称计算** + **CSA2 跨层复用** + **FP4 + Bounded Replay** 的组合拳，把长上下文的“内存墙”推到了新极限，同时保持甚至提升了智能水平。它更像是为真实 Agent 生产环境量身定制的高效架构，而非单纯堆参数。
