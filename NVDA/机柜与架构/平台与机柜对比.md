# GB200 / GB300 / Vera Rubin NVL72 机柜对比

> 整理/核对日期：2026-09-10（2026-09-02 补充 §5.2 NVL576 架构修正、§5.3 代际生命周期；本次补 GB200）。Rubin 规格 NVIDIA 仍标 preliminary，后续可能调整。
> 状态：截至 2026 年 8 月，GB300 已出货；Vera Rubin 已全面投产，按计划 2026 下半年出货。([英伟达][1])

**一句话结论**：三代均为"72 GPU + 36 CPU"的 NVL72 外形：GB200 开创 rack-scale AI Factory，GB300 主要把单 GPU 算力和 HBM 容量推高，Rubin 则同时重做 GPU、CPU、网络、存储与 POD 架构。GPU 数不变，但整柜功率从约 **120→142→227kW**，完整 Factory 的系统设计已成为核心变量。

## 2. 算力：10 → 15 → 50 PFLOPS/GPU

- GB200 的 B200 dense NVFP4 为约 10 PFLOPS/GPU，GB300 升至约 15 PFLOPS（+50%）；Rubin 为 50 PFLOPS，即相对 B200 **5×**、相对 B300 **约 3.3×**。
- NVIDIA 官方口径（Rubin vs 基础 Blackwell/B200）：inference ~5×、training ~3.5×、HBM 带宽 ~2.8×、NVLink ~2×。([NVIDIA Developer][3]) 真实 token 吞吐仍受模型、batch、网络、KV cache 影响，不等于参数比。
- NVIDIA 宣称 Rubin 相对 Grace Blackwell 大规模部署 **10× agent throughput**、1/10 cost per token；与 Groq 3 LPX 组合宣称 35× inference per watt——均为特定 workload 口径，不能当通用基准。([NVIDIA Developer][5])

## 3. 内存：GB200→GB300 先扩容，Rubin 再提带宽与 CPU 内存

- **GB200→GB300：HBM 容量从 13.4TB/柜增至 20.7TB/柜（约 +55%）**，带宽均为 576TB/s；GB300→Rubin 则保持 288GB/GPU、20.7TB/柜，但带宽 8→22TB/s/GPU（2.75×）。因此 Rubin 靠"喂数据更快"而非继续堆 HBM bit。对 SK hynix / Micron / Samsung，要区分 **bit demand** 与 HBM4 的 **revenue demand**。
- **CPU 内存仅在 Rubin 跃迁**：GB200/GB300 均约 17TB/柜，Rubin 升至 54TB（~3.1×），用于 Agentic AI 的 sandbox、tool execution、RL environment、KV/context 处理和 CPU 编排。([英伟达][6])

## 4. 网络：GB200→GB300 柜外翻倍，Rubin 柜内柜外再翻倍、CPO 登场

- GB200→GB300：柜内仍为 NVLink Gen5（1.8TB/s/GPU、130TB/s/柜），但 scale-out 从 ConnectX-7 400G 升至 ConnectX-8 800G，整柜 endpoint 28.8→57.6Tb/s。
- GB300→Rubin：NVLink 5→6，1.8→3.6TB/s/GPU，整柜 130→260TB/s；Scale-out 再升至 ConnectX-9 1.6Tb/s/GPU，整柜 endpoint 115.2Tb/s。([英伟达][1]；[英伟达][4])
- **CPO**：Spectrum-6 的 102.4Tb/s 交换机可采用 silicon photonics/CPO，减少可插拔光模块。([NVIDIA Developer][5]) 投资含义：GB300 可按 pluggable transceiver BOM 算光模块需求；Rubin 带宽更大但**可插拔光模块/GPU 未必同比增长**，部分价值从 pluggable 迁往 CPO/硅光。

## 5. 架构：Rack-scale → POD-scale

Rubin POD 包含五种 rack-scale system，组成 **40-rack POD / 1,152 GPU / 60 exaflops / 10PB/s scale-up 带宽**([NVIDIA Developer][5])：

1. Vera Rubin NVL72（GPU）
2. Vera CPU rack
3. Groq 3 LPX（推理加速）
4. BlueField-4 STX / CMX（KV Cache 卸载到 AI-native 存储）
5. Spectrum-6 SPX（网络）

**含义**：Rubin 完整 AI Factory 不能用 `1GW ÷ 227kW × 72` 直接算 GPU 数——非 GPU 基础设施占比更大，会明显高估。

### 5.2 Rubin Ultra 与 NVL576：2026 路线图修正（2026-09-02 补充）

**NVIDIA 自己改过路线图，网上资料互相矛盾，以 2026 最新定义为准：**

- **2025 GTC 旧版**：Rubin Ultra = Kyber NVL576 = **单柜 576 GPU / ~600kW**，2027 H2。([NVIDIA GTC2025][11])
- **2026 GTC 修正后**：Rubin Ultra 拆成**两种部署形态**——Kyber 单柜只做 **NVL144**；**NVL576 = 8 个物理 NVL72 机柜 × 72 GPU**，柜内铜互连 + **柜间直接光互连**组成一个 NVLink scale-up 域。GTC 2026 已展示内部运行的 NVL576 原型。([NVIDIA Developer][1]；[GTC26 Keynote][12])

| 产品 | 物理结构 | NVLink 域 |
|---|---:|---:|
| GB200/GB300/Rubin NVL72 | 1 rack | 72 GPU |
| Rubin Ultra Kyber NVL144 | 1 rack | 144 GPU |
| **Rubin Ultra NVL576** | **8 × NVL72 racks** | **576 GPU** |
| Feynman / Kyber NVL1152 | 8 × NVL144 racks | 1,152 GPU |

#### Rubin Ultra 两种形态对比（2026-09 状态）

| | **Kyber NVL144**（单柜） | **NVL576**（8 柜） |
|---|---|---|
| 物理形态 | 1 个 Kyber 机柜：竖插刀片 + 正交背板 + 800VDC | 8 个 MGX NVL72 级机柜 |
| NVLink 域 | 144 GPU/柜 | 576 GPU（8×72）一个域 |
| 柜间互连 | 不需要（柜内铜 + NVLink 7 交换） | **柜间直接光互连（optical scale-up）** |
| 功率 | 原设计 ~600kW；降规后（2-die/1800W）实际更低 | 官方未给可靠总数（8×~200–250kW ≈ 1.6–2MW/域） |
| 时间 | **据报道推迟到 2028** ⚠️ | **H2 2027 主力路径**（原型已在 NVIDIA 内部运行） |
| 主要风险 | 正交背板（midplane PCB）层数/线宽良率造不出来 | 光互连供应链（Coherent/Lumentum 产能） |

#### Rubin Ultra 降规连续剧（SemiAnalysis 披露，2026-07/08，Tom's Hardware 等转述）

1. GPU 封装 **4 die → 2 die**（CoWoS-L 翘曲/良率），单 GPU 功耗 2300W → 1800W（Max-Q 主流版）；
2. HBM4e **1TB（16-Hi）→ 768GB（12-Hi）**，并评估 8-Hi 兜底组合——DRAM/HBM 供给紧张是直接原因 ([TrendForce][13])；
3. **Kyber NVL144 推迟到 2028**；NVL72x2 过渡方案被客户否决后放弃。([Tom's Hardware/SemiAnalysis 转述][17])

NVIDIA 官方口径："Our roadmap is intact"，坚持 Rubin Ultra H2 2027，降规定性为"优化计算/网络/内存配置以建造更多 GPU"——**即 2027 年真正放量的 Rubin Ultra 是 8 柜光互连 NVL576，Kyber 单柜是 2028 年的事**。市场已定价：SK 海力士单日跌近 19%（Rubin Ultra 原预计占 2027 全球 HBM 需求 ~20%）。

**三个推论**：
1. **"单柜 600kW"不要再用于模型计算**——那是 2025 版路线图；8 柜 NVL576 的整套功耗 NVIDIA 未给可靠数字，2027 模型按"放大型 NVL72"（~200–250kW/柜 × 8）处理更稳妥。
2. **NVLink 首次从柜内 scale-up 跨到柜间 scale-up**：以前柜间只有 InfiniBand/Spectrum-X scale-out，现在 GPU scale-up 本身开始跨柜用光——Coherent/Lumentum 类光通信、NVLink switch、液冷、800VDC 的权重进一步提高。([NVIDIA Blog][16])
3. **Rubin Ultra ≈ Rubin 的中期增强版**（类似 GB300 之于 GB200），但规格连续降规、最终 GPU/HBM 配置**不要锁死，等量产规格**；对 HBM 需求测算的影响直接且巨大（-25% 容量/封装）。

**对 1GW 模型的含义**：2027 起"1GW = X 个 NVL72"要拆成三种单元——Rubin NVL72（1 柜/72 GPU）、Rubin Ultra NVL144（1 柜/144 GPU）、Rubin Ultra NVL576（**8 柜/576 GPU/一个 NVLink 域**，应理解为"8 柜组成的基本计算单元"而非超级机柜）。

## 6. 功率与供电：120→142→227kW，800VDC 还没到

- 72 GPU 数量不变，整柜功率约 **120→142→227kW**；每颗 GPU 分摊的机柜功率约 **1.67→1.97→3.15kW**（含 CPU/NVSwitch/NIC/电源，非 GPU TDP）。GB200→GB300 的增幅约 18%，Rubin 相对 GB300 再增约 60%。
- **GB200、GB300 与 Vera Rubin 本代均不是 800VDC**：Vera Rubin 的 Schneider RD113 仍为 facility 480VAC，rack 内由 110kW 三相 AC power shelf 整流。([Schneider Electric Blog][7])
- 800VDC（sidecar/in-row power rack，乃至 MV→固态变压器→800VDC）要等 250kW→500kW→1MW rack，即 **Rubin Ultra / Kyber 以后**。([英伟达][8])
- 代际定位：**GB200 = rack-scale 液冷与传统 AC 架构的起点；GB300 = 同一架构的高密度化；Vera Rubin = 过渡世代（重构 rack power）；Kyber 以后 = 800VDC 大规模进入**。对 Eaton/Vertiv/Schneider 的 BOM 预测很关键。

## 7. 液冷：同 GPU 热密度从 120kW 逐代上升，同 1GW 热不变

- 相同 GPU 数量下，GB300 的单柜热负载比 GB200 高约 18%，Rubin 又比 GB300 高约 60%，且绝大部分必须直接液冷。
- 相同 1GW 数据中心下总热量仍 ~1GW（1GW 电→1GW 热），变的是**热量集中到更少的柜**。
- 因此研究"每 10 万 GPU 多少 CDU"时，GB200→GB300→Rubin 的需求逐代上升；研究"每新增 1GW 多少液冷"时总量不变。Rubin 给液冷行业的真正挑战是 **MW/rack 和 flow density**，不是全球总 MW。

## 8. 对 1GW 模型的含义

纯 compute rack 上限：`1GW ÷ 单柜功率 × 72`

| | GB200 | GB300 | Rubin |
|---|---:|---:|---:|
| 理论 GPU/GW 上限 | **~600,000** | ~507,000 | **~317,000** |
| dense NVFP4 算力/GW（粗略峰值模型） | ~6.0 ZFLOPS | ~7.6 ZFLOPS | **~15.9 ZFLOPS** |

- 同样 1GW，GB200→GB300 的 GPU 数量上限约降 16%、峰值算力升约 27%；GB300→Rubin 的 GPU 数量上限再降约 37%、峰值算力约翻倍——未来固定的资源是 GW，不是 GPU 颗数。
- 真实 Rubin Factory 扣除网络/存储/CPU rack/CMX 后 GPU/GW 会进一步低于 31.7 万（详见 `../数据中心/数据中心1GW.md`：完整 Agentic 型 ~23 万/GW）。

## 9. 同额资本模型：若都投入 $10B 买 NVL72 计算平台

**这是一张“设备采购预算”表，不是 $10B 建一个完整园区的 CAPEX 表。** 分母只包括 NVL72 计算平台（GPU/CPU/HBM/NVLink/机柜内网络与液冷等随具体报价而变），**不含**土地、楼宇、变电站、园区级 UPS/配电、外部网络、CDU/冷站、备用电源、施工、并网、融资和运营资本。因此它回答的是“同一笔芯片/机柜预算能买到什么”，而不是“$10B 可以建成多少 GW 数据中心”。

### 9.1 价格口径：有市场区间，但没有统一公开成交价

NVIDIA 不公开 NVL72 的统一 list price，真实合同又会因 GPU/网络配置、是否含 in-rack CDU、L11/L12 集成层级、软件/服务、数量折扣及交付期而变化。因此以下不是“市场现货价”，而是公开可见的三类**估计口径**：

| 平台 | 卖方 ASP / BOM 锚 | 其他供应链或媒体报价 | 本文采用值 | 判读 |
|---|---:|---:|---:|---|
| GB200 NVL72 | KGI：**$3.0–3.5M** | DigiTimes 供应链消息：$2.8–3.4M | **$3.25M** | 两组范围重叠，$3M 出头可作设备采购模型的中性锚 |
| GB300 NVL72 | Morgan Stanley：约 **$4.0M** | DigiTimes 供应链消息：**$6.0–6.5M** | **$4.0M** | 分歧很大，最可能来自配置/集成范围不同；应把 $4M 当低位模型锚，而非可执行报价 |
| Vera Rubin NVL72 | Morgan Stanley BOM/客户成本：约 **$7.8M** | 市场报道的系统估计约 **$5–7.8M**；另有高配口径至 $8.8M | **$7.8M** | HBM4 与整机配置占最大不确定性，$7.8M 是偏审慎的中高位锚 |

- 结论：**可以使用 $3.25M / $4.0M / $7.8M 做跨代比较，但不能把它们当作单一“市场价”。** 尤其 GB300 的 $4M 与 $6–6.5M 报价差异，足以让同额预算下可购柜数相差逾三分之一。
- GB200 的 $3.0–3.5M 来自 KGI 卖方估计；GB300 约 $4M、Rubin 约 $7.8M 来自 Morgan Stanley 的供应链/BOM 估计经媒体转述；另一篇 DigiTimes 转述给出 GB200 $2.8–3.4M、GB300 $6–6.5M 与 Rubin 高至 $8.8M 的配置报价。([KGI][21]；[Tom's Hardware][22]；[DigiTimes 转述][23]；[Tom's Hardware][24])

### 9.2 输入：采用可追溯的中性 ASP 锚

| 平台 | 采用 ASP | 取值理由 | 价格不确定性 |
|---|---:|---|---|
| GB200 NVL72 | **$3.25M/柜** | KGI 对 GB200 NVL72 的 $3.0–3.5M 估计取中点 | 配置、网络与整合层级不同会改变报价 |
| GB300 NVL72 | **~$4.0M/柜** | Morgan Stanley 供应链估计的“约 $4M”口径 | 也有媒体/渠道报价更高；不能当 NVIDIA 官方价 |
| Vera Rubin NVL72 | **~$7.8M/柜** | Morgan Stanley 对 VR200 NVL72 的 BOM/客户成本估计 | HBM4 价格和系统配置是最大变量 |

- 速算公式：`可购机柜数 = $10B ÷ 单柜 ASP`；`GPU = 机柜 × 72`；HBM、理论 NVFP4 和机柜功率分别沿用 §1 的每柜规格。金额每增减 $1B，表中所有数量同比例增减 10%。


### 9.4 应如何解读“同样 $10B”

1. **买到的 GPU 数反而下降**：GB200 的单柜便宜，$10B 可买约 22.2 万 GPU；Rubin 仅约 9.2 万。用 GPU 颗数衡量资本效率会得出错误结论。
2. **理论算力和完整 Factory 容量上升**：Rubin 在同额预算下理论 dense NVFP4 约为 GB300 的 1.7 倍；且其完整 Factory 的非计算 IT 占比更高（§8），故约 1,280 个计算柜仍需要约 0.40GW IT 容量承载。
3. **HBM bit 需求未随资本同比上升**：同样 $10B 下，GB300 的 HBM bit 约 52PB，而 Rubin 约 27PB；但 HBM4 的带宽、堆叠、封装难度和 ASP 大幅提高，不能据此推导 HBM 厂商收入减半。
4. **真正的园区总投资会小于这张表隐含的“设备预算 ÷ 容量”直觉吗？未必。** $10B 若含土建、电力和冷却，能买到的计算柜会显著少于本表；但高密度平台需要更强的电气与液冷系统，设施侧 CAPEX/GW 也会上升。缺少同口径的已签约全包项目 BOM，现阶段不应把本表外推为 `$ / GW`。
5. **不能用于 Rubin Ultra**：Rubin Ultra 的 NVL144/NVL576 物理架构、GPU/HBM 配置和价格尚未锁定，不能同三种 NVL72 平台并列。

## 10. 投资语言总结

- **GB200 时代核心瓶颈**：首代 72-GPU NVLink rack-scale 部署 + HBM3E + 400G 网络 + 120kW 级液冷 + 园区级交付
- **GB300 时代核心瓶颈**：GPU + 更高容量 HBM3E + 800G 网络 + 100kW 级液冷 + 大规模低压供电
- **Rubin 时代**：更强 GPU + HBM4 + 1.6T 网络/CPO + 200kW+ 液冷 + 更强 rack power + AI-native context storage
- **再下一代**：500kW–1MW rack + 800VDC

Rubin 不是"GB300 快 3 倍"，而是 NVIDIA 为了让每 MW 电产生更多 token，把 GB200 开启的 AI Factory 路线从芯片重新设计到电源、液冷、网络和存储。同样 1GW 电，GPU 颗数下降，但 HBM 代际、网络带宽、功率密度、CPO、液冷和电气系统的**价值量完全重新分配**——这正是 GB200、GB300 与 Rubin 的 1GW BOM 对比价值所在。
