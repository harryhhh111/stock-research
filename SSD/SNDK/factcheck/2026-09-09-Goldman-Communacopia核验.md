## 2. 高盛/管理层多头叙事的可确认版本

以下是会议记录和二手纪要能够支持的**方向**，不是对原始券商模型的完整复原：

1. **AI 推理与 agentic workload 改变 NAND 需求结构**：企业/数据中心 SSD 的需求上升，尤其是高容量存储与推理数据层。
2. **供给增量有限**：NAND 新增产能受 fab、资本开支和制程迁移约束，短期供需紧张支撑 ASP。
3. **NBM / 长约提高可见度**：Sandisk 管理层称已有八份数据中心客户协议，FY2028 约三分之二 bit 受协议覆盖；这降低未锁定量的比例，但不是“所有产能已售罄”或固定价格收入。
4. **HBF、KV cache 下沉至 SSD 是远期可选项**：是技术/需求增量叙事，尚非已披露的成熟收入或利润来源。

Sandisk 在 9 月 9 日大会上的 management remarks 可通过 [Investing.com 会议纪要](https://www.investing.com/news/transcripts/sandisk-at-goldman-sachs-communacopia-ai-demand-reshapes-nand-93CH-4894836) 交叉查看；八份协议和 FY2028 覆盖的基础披露也应回到 [Sandisk Investor Day](https://investor.sandisk.com/news-releases/news-release-details/sandisk-details-growth-strategy-and-long-term-financial-model) 与公司年报核对。

## 4. “Agentic AI 的 KV cache 会拉动 SSD”应怎样反驳

### 4.1 高盛实际引用的证据链：有模型，但不是实测

此前仅以会议摘要讨论 KV/SSD 不充分。Sandisk 2026-08 Investor Day 的**官方《AI Infrastructure Outlook》材料**给出了高盛 9 月会议纪要所依赖的量化叙事：

| 原始材料的页面 | 公司说了什么 | 来源性质 | 能证明什么 / 不能证明什么 |
|---|---|---|---|
| p.4、p.14 | 2030 年 AI 数据中心 flash shipment TAM **1.2ZB**；工作负载拆分为 Staging 40%、KV Cache **35%**、Fast Data Lakes 25%；NAND 拆分为 QLC 66%、TLC 34%。 | 1.2ZB 引用 TechInsights Q2 2026 NAND Market Report；**35%/66% 是 Sandisk internal splits**。 | 证明 Sandisk 的多头模型确实把 KV 设为大需求源；不能证明第三方已验证 35%。 |
| p.9–11 | 将 persistent KV cache 指向 NVMe eSSD，并画出 HBM → DRAM → Direct Attached SSD → Network Attached Compute SSD → NAS SSD → HDD 的层级。 | 公司架构/产品定位。 | 证明公司并未说 active KV 全在 SSD；它假设可复用、持久 KV 会下沉至 SSD 层。 |
| p.12–13 | Persistent KV Store eSSD 的容量方程 = 并发会话数 × 保留期内 cache miss ratio × 每会话平均输入 tokens × 每 token KV 大小；2030 install base 图示为 `+ ZB`，脚注为 Sandisk internal estimate。 | 公司内部模型；关键变量没有公开基准值、范围或客户数据。 | 说明结果对并发、保留时间、命中率与 token 长度高度敏感；不能据此复算或验证 >1ZB。 |
| p.17–18 | 实验室称 SSD 方案可实现约 3× 吞吐、约 75% 更低能耗。 | Sandisk internal testing，参数未完整公开。 | 证明技术可行性/产品方向；不能直接推至所有 CSP 的真实 TCO。 |

一手原始材料：[Sandisk《AI Infrastructure Outlook》](https://investor.sandisk.com/static-files/9ee604b4-b810-4fba-bbd3-c4c605f690f9)。该材料第 4、14 页明确标注 `Sandisk internal splits`；第 12–13 页也明确标注变量会因 provider、use case、architecture 改变。

可获得的 9 月 9 日高盛纪要二手转述与上述材料一致：Goldman 将 35% / 1.2ZB 作为管理层估计，并以此支持 AI inference/KV 的长期增长机会，而非援引一个已观测的 SSD KV 装机统计。[会议纪要转述](https://www.bit.fan/en/news/list/goldman-sachs-sandisk-nbm-fy27-fy28-target-2200-ea70ecff-en-keyName-763ee0dd)；高盛原文仍为付费材料，故该层保留二手属性。

**时间口径存在未消除的冲突：** Sandisk 官方材料明确把 1.2ZB 及 35% workload split 标为 **2030 shipment estimate**；部分对 9 月 9 日高盛纪要的二手转述写成“2032”。在未取得 Goldman 原始页之前，不能断言是高盛采用了另一套 2032 预测，还是转述者错写年份。研究中应采用可核验的一手 **2030** 口径，并把“2032 / 35%”标为 ⚠️ 二手转述、待原报告复核，不能混入模型。

**更准确的结论是：方向上存在新增需求，但把它当作已大规模兑现的 eSSD 需求主引擎，是把公司 2030 情景模型、未来架构、局部工作负载和现有部署混在了一起。** 公开资料仍没有给出“全球 agentic KV cache 有多少已放入 SSD”的可复算实际比例，故不能用“高并发”直接推出大规模 SSD 需求。

### 4.2 KV cache 的实际层级

| 层级 | 典型角色 | 对 KV cache 的意义 |
|---|---|---|
| **GPU HBM（G1）** | 活跃逐 token decode 所需的工作集 | 主存放地。NVIDIA 明确称 HBM 为 active KV cache 的理想层，纳秒级访问；SSD 不能承担每个 token 的即时 attention 读取。 |
| **系统 DRAM（G2）** | 从 HBM 溢出的 staging / buffering | 可扩展并发或上下文，但仍会增加传输延迟与能耗。 |
| **本地 NVMe SSD（G3）** | 单节点 warm KV、短期重用 | 用于容量扩展和预取；必须在 decode 前把需要的 KV 预取回 DRAM/HBM，不能把 SSD 当 HBM。 |
| **CMX 以太网闪存（G3.5）** | Rubin pod 级共享、可复用的 KV context | NVIDIA 2026 年提出的新架构，目标是长上下文、多轮、多 agent 场景；其价值取决于实际部署和缓存命中率，不能当成存量 AI 机房的既成事实。 |
| **共享对象/文件存储（G4）** | 冷历史、日志、结果、持久化数据 | 不在即时 decode 临界路径。 |

该层级来自 NVIDIA 对 CMX 的一手技术说明：活跃 KV 在 HBM；超过 HBM 后可下沉至 DRAM 与本地 SSD；CMX 是在两者和传统共享存储之间新增的闪存层，并依靠预取把 KV 提前送回 G2/G1。[NVIDIA 技术博客，2026-03-16](https://developer.nvidia.com/blog/?p=111143)

### 4.3 高并发不等于每份 KV 都要落 SSD

- **高并发**首先增加的是同时活跃请求的 KV 总量，因此先挤压 HBM；
- **长上下文、多轮会话、跨 agent 的上下文复用**才会创造把淘汰 KV 保留并在以后重新取回的价值；
- 若会话结束后 KV 不再复用，最经济的动作可能是直接丢弃、必要时重算，而不是写入 SSD；
- 即使写到 SSD，SSD 也只是容量/预取层。若在 decode 的每一步同步从 SSD 取 KV，I/O 延迟会使 GPU 停顿，失去部署意义。

因此，SSD 对 KV 的真实需求取决于 **上下文长度 × 并发 × 多轮复用率 × 缓存命中率 × 可接受的预取延迟**，而不是只取决于“agentic AI”或“请求数”。学术系统已在尝试 SSD-backed KV cache，恰恰是因为 HBM/DRAM 不够；但论文也把从 SSD 恢复 KV 的 I/O、GPU stall 和调度问题列为核心难点，不能把实验/新架构直接等同于全面商用渗透。[Tutti 论文，2026-05](https://arxiv.org/abs/2605.03375)

### 4.4 对 Sandisk 多头叙事的含义

可接受的基准论断是：AI 服务器会增加**本地 eSSD、训练/推理数据、checkpoint、RAG 语料、日志和部分 warm KV tier**的需求。需要被证明、不能先假定的强化论断是：**Sandisk 的 35% KV workload 假设及 persistent KV Store eSSD 容量，会很快且大规模兑现，足以长期改变 NAND 周期。** NVIDIA CMX 的发布说明了这个方向有产品化潜力，但它也是一个专为 Rubin/BlueField-4 设计的新层级，不是现有 GPU 推理集群的默认配置。[NVIDIA CMX 产品页](https://www.nvidia.com/en-in/data-center/ai-storage/cmx/)

对做空研究，最有力的问题不是“KV 永远不会进 SSD”，而是：**CMX/SSD 承接的 KV 容量在未来两年到底是多少 EB、渗透率多快、能否快过 NAND bit 供给增长？** 在出现 CSP 实际部署、Sandisk/Kioxia 产品出货、或收入/bit 拆分前，应把它列为高不确定性可选项，而非基准收入。

### 4.5 大模型厂商到底披露了什么规模？

截至 2026-09-15，未找到 OpenAI、Google、Anthropic、Meta 等运营方披露其**全网 KV cache 总容量、其中 SSD 容量、缓存命中率或按工作负载拆分的 EB/TB 存量**。这恰是 Sandisk 情景模型无法被外部直接验证的缺口。它们公开的资料分为三层，不能混用：

| 披露方 / 场景 | 已公开的量 | 没有公开的量 | 对 NAND 研究的意义 |
|---|---|---|---|
| OpenAI API 的共享 prompt prefix | 单请求返回 `cached_tokens`；超过 1,024 input tokens 才可命中；通常闲置 5–10 分钟清除、最后使用后不超过 1 小时。 | 全平台 cache-hit token、并发会话、GPU/DRAM/SSD 的容量与介质。 | 说明短周期 prefix reuse 已是产品能力；不能推出持久 SSD 容量。|
| Gemini 显式 context cache（长文档、视频、代码库等） | 用户可设 TTL，默认 1 小时；API 返回每个 cache 的 token 数。隐式缓存的共同 prefix 也可命中。 | Google 生产总缓存 token、介质分层与使用量。 | 长文档/RAG 是最像“可持久复用上下文”的场景，但公开的是客户 API 能力而非 Google 需求数据。|
| Claude prompt caching（system prompt、文档、对话历史） | 5 分钟或 1 小时 cache；读缓存按输入价 0.1 倍计费。 | Anthropic 的缓存池容量、缓存命中率、SSD 配置。 | 同样证明短期复用的经济价值，不证明外部 SSD 需求。|
| Meta AI / Llama 长上下文推理 | Meta 公开称 KV 随 context 线性增长；演示单个 H100 host 可在 1 分钟内处理 100 万 token、32 个 H100 hosts 可处理 1,000 万 token。 | Meta AI 的真实并发、每 token KV 字节数、缓存存量与分层。 | 证明极长上下文的系统工程必要性；不能把 context-window 能力等同于持续 KV 存量。|
| Novita AI + vLLM 外置 KV 服务 | 生产导向评测中，一个 host 的外置 KV pool 为 **500 GiB**；大 prefix 的远端读取平均 194 GB/s。 | Novita 全网部署规模、SSD 容量和付费客户使用率。 | 是“数百 GiB/host、SSD/远端层级确实会用”的最好公开运营方例子，但不能外推为 hyperscaler EB 需求。|
| AWS HyperPod 的多轮对话测试 | 4 轮 / 2,048 tokens 写出 109 MB KV；每 worker 100 GiB NVMe 的 L2 层可随节点扩至数百 GiB。 | AWS 客户真实平均工作负载和生产装机。 | 展示多轮聊天、RAG 的实现可落到 NVMe；它是 benchmark，不是 AWS 总量披露。|

一手来源：[OpenAI Prompt Caching](https://openai.com/index/api-prompt-caching/)、[Gemini Context Caching](https://ai.google.dev/gemini-api/docs/generate-content/caching)、[Anthropic Prompt Caching Pricing](https://platform.claude.com/docs/en/about-claude/pricing)、[Meta Inference Engineering](https://engineering.fb.com/2025/10/17/ai-research/scaling-llm-inference-innovations-tensor-parallelism-context-parallelism-expert-parallelism/)、[Novita/vLLM PegaFlow](https://vllm-project.github.io/2026/05/18/pegaflow.html)、[AWS HyperPod/Curvine 测试](https://aws.amazon.com/blogs/machine-learning/tiered-kv-cache-for-large-llms-on-sagemaker-hyperpod-with-curvine/)。

**研究结论：** 现有公开资料能验证 KV cache 是真实且快速工程化的需求，也能验证 SSD/NVMe 在 warm/cold 层有用；却不能验证 Sandisk 的“2030 年 35% AI DC flash workload 是 KV”能在短期转化为某个已知的 TB/EB 级 SSD 出货。若要把该叙事写进 Sandisk FY2027–FY2028 基准盈利，至少还需看到 CSP/模型厂商披露的实际 cache-hit、保留周期、并发量，或 SSD 厂商的客户出货与收入拆分。

## 5. 使用纪律

- 将 **Buy / $2,200** 标为“多源二手转述，且此前已存在”，不可写成“9 月 9 日新上调”。
- 将 AI、NBM、HBF 视为高盛/公司多头框架；其中 NBM 覆盖、合同条款与 HBF 收入尚不足以被当作已实现利润。
- 对做空研究，优先检验价格、供给和协议条款，而不是反驳“AI 会增加 NAND 需求”这一方向性事实。
