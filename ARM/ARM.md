# Arm Holdings（ARM）公司研究

## 研究摘要与我的判断

【我的推演】Arm 的核心资产是能反复授权、并在客户量产后持续收费的 CPU 设计与软件生态。手机提供成熟的版税基础，云端新增部署提高了增长上限。自研 AGI CPU 可以扩大收入，但能否增加每股现金回报，还取决于芯片毛利、库存和投入，以及它与现有授权客户的关系。

- 正向证据：FY2027 Q2 数据中心版税同比翻倍，外部客户收入增加 306 M 美元，贡献集团同比增量 308 M 的约 99%。
- 反向证据：同期集团版税只增长 8.1%，授权及其他贡献约 84% 的营收增量。TTM 公司 Non-GAAP FCF 仅同比增长 2.1%，且未反映股权支付造成的稀释。按 11 月 5 日收盘价，股权市值约 178.4 B 美元，对应约 163 倍 TTM FCF。
- 长期目标与估值预期：管理层提出 FY2031 收入约 25 B、Non-GAAP EPS 超过 9 美元，其中完整芯片收入约 15 B。需以实际交付、产品利润和股数验证，详见第二、六章。[长期目标 J]
- 判断条件：云端版税需要在手机放缓时仍能带动整体版税，外部授权需转化为出货和收现，AGI CPU 则需用交付及利润率验证。若研发与营运资金长期跑赢增量毛利，份额上升也不足以支撑当前估值。[年报 A] · [季报 B]

## 1. 公司与业务

**IP 授权及其他。** 芯片设计公司、整机厂或云厂商为指令集、现成 CPU 核心或 CSS（预集成计算子系统）付费。架构授权让客户做自己的兼容核心，核心及 CSS 授权则减少设计和验证工作。独立 IP 通常在交付与授权起始两者较晚时确认，支持和部分组合订阅按服务期确认。部分最低版税承诺列入固定授权对价。

**版税。** 客户出货后按合同付费，通常以每颗固定费用或芯片售价比例计价。Arm 先估计当期已发生的销售，随后按客户报告修正。新品版税率和出货组合可以推高收入，即使总出货量持平。AWS 案例中，Arm 提供 Neoverse 技术，AWS 的 Annapurna Labs 设计并集成 Graviton，晶圆厂负责代工，AWS 向客户出租 EC2 算力。EC2 小时价不是 Arm 的收费基数，具体费率未公开。

**成品芯片。** Arm 2026 年发布 AGI CPU，台积电 N3P 代工，面向云厂商和整机伙伴。商业交付预计 FY2027 Q4 开始。截至最新股东信尚处交付前，未有可核验的产品收入和毛利序列。集团披露单一报告分部，授权、版税属于收入分类，利润无法按两类分摊。[年报 A] · [季报 B] · [Graviton 设计](https://www.amazon.science/blog/graviton5s-improved-design-increases-speed-and-energy-efficiency-beyond-moores-law) · [AGI CPU 制程](https://developer.arm.com/community/arm-community-blogs/b/servers-and-cloud-computing-blog/posts/introducing-the-arm-agi-cpu-1ou-dual-node-reference-server)

## 3. 盈利、负债与现金流

### 财务口径说明

- **GAAP** 为美国会计准则口径。本章历史损益表、营业利润至净利润桥及季度经营表中的收入、毛利、研发、营业利润、净利润、EPS、CFO 和资产负债数据均来自 GAAP 报表；利润率按这些金额复算。
- **Non-GAAP** 为公司调整后指标。调整后利润通常剔除股权支付、相关雇主税、收购相关费用及部分其他项目，净利润还调整投资损益、处置收益及对应税项，各期项目以原表为准。
- **FCF** 为公司定义的 Non-GAAP 自由现金流，按 CFO 减现金购置固定资产、购置无形资产、偿付无形资产义务计算。FCF 不属于 GAAP 利润，也不会因这个名称自动扣除 SBC 或全部股权激励代缴税。
- **自行复算指标** 包括同比、利润率、ROE、ROIC、TTM 滚动与估值倍数。下文明确其所用 GAAP 或 Non-GAAP 分母；FCF 再减代缴税是研究者补充现金观察口径。

### GAAP 营业利润为什么可能低于 GAAP 净利润

## 5. 竞争对手

### 5.1 竞争发生在哪个层面

**在服务器采购中，Intel Xeon 和 AMD EPYC 是 Arm 生态的重要竞争者。** 采购方决定将工作负载部署在 x86 或 Arm 平台，关系到 Arm 的技术是否被采用。但 Arm Holdings 同时卖架构许可、核心设计和成品芯片，各层面对手与收入影响不同。

| 竞争层面 | 客户的选择 | 具体对手或替代路线 | 对 Arm 收入的影响 |
|---|---|---|---|
| 指令集／软件生态 | 选 Arm、x86 或 RISC-V | Intel、AMD 的 x86 平台；RISC-V 生态 | 若从 Arm 转到其他架构，可能失去该设计的授权和后续版税 |
| 核心及子系统 IP | 在 Arm 架构内买现成核心，还是自研核心 | 苹果自研 CPU、高通 Oryon、NVIDIA Olympus 等 | 仍可保留架构许可及合同版税，但核心／CSS 的销售机会与收费组合改变 |
| 完整服务器 CPU | 买哪款处理器或租哪种实例 | Xeon、EPYC，以及 NVIDIA、Ampere 等 Arm 芯片产品 | Arm 生态扩大可增加 IP 收入；AGI CPU 自身还要争取具体采购订单 |
| 嵌入式／控制 CPU IP | 采用 Cortex 等设计或其他方案 | SiFive、Andes 等 RISC-V 核心厂商和客户自研 | 核心许可及长期量产版税面临替代 |

【我的推演】同属 Arm 架构的两颗芯片在成品市场竞争时，Arm 可能仍从双方收到许可和版税；客户转成其他指令集，影响则可能贯穿 IP 和版税两条收入线。自研兼容 Arm 核心的实际费率由合同决定，不能直接推定一定比购买现成核心少付多少钱。年报明确列出 x86、RISC-V，以及客户选择架构授权自行开发处理器的竞争风险。[年报 A] · [NVIDIA 自研 Olympus 核心](https://developer.nvidia.com/blog/inside-the-nvidia-rubin-platform-six-new-chips-one-ai-supercomputer/)

### 5.2 服务器与云端——谁争夺同一笔预算

**Intel Xeon、AMD EPYC** 面向通用服务器、企业应用、数据库及云端。客户已有的二进制软件、商业软件认证、运维工具和团队经验，会影响迁移成本。Arm 方案需要证明实际工作负载下的性能、功耗、内存、网络以及总体拥有成本有吸引力。

**AWS Graviton、Google Axion、微软 Cobalt** 是 Arm 技术的采用者，也成为云端对 x86 的竞争产品。云厂商可以围绕自有工作负载调整芯片与系统，并通过实例价格促进客户迁移。它们的技术成功能扩大 Arm IP 收入，但自用芯片的开发能力也提高了客户议价能力。

**NVIDIA Grace／Vera、Ampere 的服务器 CPU** 属于 Arm 生态内的成品选择。NVIDIA Vera 使用自研 Olympus 核心并兼容 Armv9.2，说明客户可在 Arm 指令集上自研微架构。AGI CPU 面向客户直接供货后，需与这些产品比较具体用途、整机系统和可交付性。不同芯片的核心数、线程定义、内存带宽和加速器互连存在差异，按 vCPU 数比较并不足以判断单位工作成本。[年报 A] · [NVIDIA Vera 技术说明](https://developer.nvidia.com/blog/nvidia-vera-cpu-sets-a-new-standard-for-agentic-workloads-in-ai-factories/) · [AGI CPU 平台](https://newsroom.arm.com/blog/introducing-arm-agi-cpu)

### 5.3 手机、PC 与嵌入式——竞争格局不同

手机端已有庞大的 Arm 软件和芯片生态，苹果、高通、联发科之间的手机处理器竞争，可以发生在 Arm 架构内部。对 Arm 需要观察的变量包括客户采用现成 Cortex／CSS 还是自研核心、授权谈判、单颗芯片收费和出货组合。PC 则同时面对 Intel Core、AMD Ryzen 的 x86 产品，竞争涉及 Windows 应用兼容、性能、续航和整机渠道，苹果自有软硬件体系的成功也不能直接外推到全部 PC。

RISC-V 的指令集开放，SiFive、Andes 等仍可销售收费的商业核心、工具和支持，客户也承担验证及软件适配成本。在控制器和嵌入式场景，客户可按应用要求选择较小核心，替换所需的软件范围可能较窄；高性能通用服务器和手机应用处理器则还要满足复杂软件兼容与整机验证要求。【我的推演】替代会按应用逐步发生，不能把低端控制核心的采用直接换算成高性能 CPU 的份额损失。[年报 A]

### 5.4 价格、份额与竞争验证

- **云端价格对照**。前序核对的北弗吉尼亚 Linux 按需挂牌样本，同为 2 vCPU、8 GiB，M7g 对 M7i 为 0.0816 对 0.1008 美元/小时（便宜 19.0%），M8g 对 M8i 约 0.0898 对 0.1058（便宜 15.1%）。复算为 1 − Arm 小时价 / Intel 小时价。单位工作成本还取决于吞吐、移植和实例利用率。

上述价格属于云实例挂牌样本。Arm IP 合同价格并不公开，x86 成品芯片的折扣也依合同而异，现有资料不足以制作同口径的 CPU 采购成本表。云端份额采用第 7 节头部云厂商新增部署口径；手机、PC、全球服务器存量的分母分别观察。

| 竞争判断 | 可验证证据 | 当前限制 |
|---|---|---|
| Arm 云端采用扩大是否转化为收入 | 数据中心版税、外部收入及实际客户部署 | 数据中心版税绝对金额和客户拆分未披露 |
| 自研核心是否影响 Arm 产品组合 | 客户新品采用核心／CSS 或架构许可的情况 | 各类许可费率未披露，难以量化净影响 |
| AGI CPU 是否取得成品竞争力 | 实际交付、客户上线、产品毛利和供货承诺 | 截至本次财务期尚未商业交付 |
| 替代架构是否侵蚀既有生态 | 量产设计导入、客户架构变化、版税趋势 | 不使用单次基准测试推算市场份额 |

【我的推演】Arm 当前云端扩张受益于客户定制芯片和能效需求，但软件迁移、x86 产品迭代、大客户自研以及 RISC-V 替代限制其定价。AGI CPU 又增加了供货、芯片利润率与客户关系的考验。应把生态采用率和 Arm 自身每股现金回报一起跟踪。[年报 A] · [季报 B]

## 7. 行业景气

### 周期性判断

【我的推演】Arm 是受终端周期影响、同时有技术升级和市场渗透驱动的 IP 授权公司。版税随客户芯片出货、售价及产品组合变化，手机、汽车、服务器的周期会传导到收入。授权则受客户研发预算、合同交付及确认时点影响。成熟设计持续量产和分期服务收入提供延续性，但无法完全隔绝周期。[年报 A]

五年序列中，FY2023 集团营收下降 0.9%，随后三年分别增长 20.7%、23.9%、22.8%。FY2022–FY2026 CAGR 为 16.2%。年度增长包含技术升级、收费组合及关联交易变化，不能由这五年判断 Arm 已免疫周期，也不足以据此建立固定时长的周期模型。FY2026 集团增速与外部收入增速的差异见第二章。

利润可能比收入波动更大。工程人员和产品路线需要持续投入，收入减速时研发及其他费用不一定同步缩减。AGI CPU 加入后，还增加晶圆／封装采购、库存及交付节奏的影响。行业跟踪应同时看终端量、单颗版税、授权合同、外部收入及资金占用；FY2031 目标属于增长情景，不应作为每年匀速实现的收入预测。


### 7.1 手机、汽车与嵌入式需求

手机景气看终端出货和产品档次，Arm 收入还受架构升级及单颗版税影响。FY27 Q2 公司称边缘 AI 版税大致持平，存储涨价压制中低档手机出货。汽车看车型定点到量产的时滞，Q2 公司称物理 AI 版税同比增长 50%，含汽车和机器人，未给绝对值。[季报 B] · [电话会 F]

### 7.2 云厂商自研 CPU——需求为何增长

【我的推演】云厂商自研 CPU 的经济动力，是用较大的前期开发和迁移投入，换取大规模部署后的单位工作成本节省。规模扩大提高可行性，项目仍须满足实际性能、能效、上市时间和供货条件。

云厂商了解自己的工作负载，可以围绕缓存、内存、网络和功率预算设计芯片，并同时调整软件。可反复使用的设计、Arm 核心或 CSS，以及已有工具和软件降低了部分开发工作。AWS Graviton、Google Axion、微软 Cobalt 是具体采用路线，客户买哪类技术见第四章。

AWS 披露，Graviton 经五代、八年持续投入，覆盖超过 350 种实例类型、服务超过 12 万客户。这些是实例种类和客户数，不代表处理器数量或部署份额。Google 的迁移说明涉及超过 10 万个内部应用，并分析了 38,156 次代码提交，表明架构适配也需要规模化工程投入。[AWS Graviton5](https://aws.amazon.com/blogs/aws/now-available-amazon-ec2-m9g-and-m9gd-instances-powered-by-new-aws-graviton5-processors/) · [Google 多架构迁移](https://cloud.google.com/blog/topics/systems/using-ai-and-automation-to-migrate-between-instruction-sets/?hl=en)

### 7.3 什么条件下自研才划算

简化为同一使用期、相同有效工作量的增量现金比较。研发费用含股权支付的会计数与项目现金成本分别观察。

> 自研增量净现值 = 各期采购及运行成本节省的折现合计 − 研发、验证、软件迁移及持续维护投入的折现合计。

| 变量 | 对项目回报的影响 | 研究时需要核对 |
|---|---|---|
| 实际部署量与利用率 | 摊薄固定投入，决定节省能否兑现 | 芯片量产后是否实际部署、是否有足够工作负载 |
| 同等工作量的成本差 | 包含整机采购、电力、冷却及机房资源 | 对比对象、测试任务、运行期、软件许可是否一致 |
| 开发和软件投入 | 增加前期及持续成本 | 研发多代产品、适配依赖、验证和维护成本 |
| 性能与产品时点 | 决定是否胜过届时可以买到的产品 | 比较同期 Intel、AMD 等实际产品 |
| 供货与良率 | 影响交付、单位成本和资金占用 | 晶圆、封装、内存与服务器交付分别核查 |

**假设敏感性例子**。若一次性增量投入 500 M 美元，每颗在共同使用期内、同等有效工作量下净节省 500 美元，静态盈亏平衡量为 100 万颗。若净节省降到 250 美元，平衡量变成 200 万颗。该例未折现，未计后续研发及融资费用，全部为演示假设，无法据此反推出 AWS 或 Google 的实际项目回报。

【我的推演】大规模、可控软件、稳定需求与有竞争力的芯片同时成立，自研更可能经济。规模较小或工作负载分散时，采购成熟芯片可能更合适。自研供货也不能覆盖所有客户需求，云厂商可继续同时采购 x86 和其他平台。

### 7.4 替代 x86 的份额如何传到 Arm 收入

云端景气应逐层观察服务器新增采购、芯片出货、部署利用、客户结算，以及 Arm 确认收入。

| 环节 | 发生的变化 | Arm 可获得的经济利益 |
|---|---|---|
| 云厂商减少采购部分 x86 CPU | Intel／AMD 等失去对应订单 | 是否转成 Arm 需求取决于客户选用架构 |
| 客户量产自研 Arm CPU | 核心或架构技术被采用 | 合同授权费和相关版税 |
| 代工、封装并部署服务器 | 制造与设备投入增加 | 制造收入归供应链，不能计入 Arm IP 营收 |
| 云厂商提供实例或运行自有服务 | 算力产出变现或节省运行成本 | 收益主要由云厂商及客户获得 |
| 客户直接采购 Arm AGI CPU | Arm 承担完整芯片供货 | Arm 获得芯片销售收入，同时承担成本和供货责任 |

【我的推演】Arm 架构采用量和 Arm 公司收入增幅可能不同。原来采购 100 美元的 x86 CPU，转成自研 Arm CPU 后，Arm 的新增收入取决于许可与版税合同，无法按 100 美元等额计算。自研路线也可使用其他指令集，新增自研需求并不必然全部流向 Arm。[年报 A] · [季报 B]

### 7.5 最新份额证据与供给约束

Arm 披露头部云厂商新增服务器 Arm 份额由 2024 年 15% 升至 2025 年超过 50%，2026 年底超过 60% 为公司预测。该样本不能外推至全球服务器存量，也不能等同 EC2 实例小时。FY27 Q2 数据中心版税同比翻倍，但集团版税仅增 8.1%，说明云端景气和集团最终财务表现需要分别验证。[季报 B] · [新增部署说明](https://newsroom.arm.com/blog/why-cloud-developers-are-moving-to-arm-ai-ready-infrastructure)

供给需区分晶圆产能、封装和内存供应、量产良率与整机交付。供应商承诺和客户采购订单详见第十章及第三章；预留产能不等于已生产，芯片出货不等于云实例已被充分利用。Arm 自研产品扩大后，除授权与版税外，还须观察现金采购、库存、毛利与供货是否匹配需求。

## 11. 护城河

### 11.1 核心判断——客户为什么持续付费

【我的推演】Arm 的壁垒由可授权的技术、广泛的软件适配、客户设计导入与持续量产经验共同构成。客户购买架构、核心或 CSS 后，可以沿用已有工具与软件，把工程资源用于自己的产品差异化。收费能否持续取决于客户节省的开发时间和风险，能否覆盖授权及版税成本。

必须区分 Arm 生态与 Arm Holdings 的收益。客户芯片采用 Arm 架构可扩大生态，但客户自研核心、长期合同和议价可能改变 Arm 每颗芯片的收入。AGI CPU 还要另外证明整颗芯片的供货与盈利能力。[年报 A]

### 11.2 与 x86 相比——可定制与集成能力

**客户可以自己掌握整颗芯片设计。** 在主流服务器市场，企业通常购买 Intel Xeon 或 AMD EPYC 成品。Arm 提供架构许可、现成核心和 CSS 等选择，允许云厂商围绕内存、缓存、网络和加速器设计自己的 SoC。AWS Graviton、Google Axion、微软 Cobalt 是这条路线的具体采用。其价值是按自身工作负载优化系统，也给客户更多供应链与产品路线控制空间。x86 也有半定制等合作，因此不能把 Arm 的许可灵活性表述为客户绝无其他路径。[年报 A] · [Graviton 设计](https://www.amazon.science/blog/graviton5s-improved-design-increases-speed-and-energy-efficiency-beyond-moores-law)

**系统级能效与成本有优化空间。** 对拥有大规模、相对稳定工作负载的云厂商，针对应用裁剪和集成能带来经济价值。Arm 指令集本身并不保证更快或更省电，性能还由微架构、制程、内存和系统设计决定。第五章的 Graviton 挂牌价格只能说明特定实例报价，无法证明所有 Arm CPU 都优于 x86。

**多家实现共享软件基础。** 客户可以在保持 Arm 架构的情况下，选择不同芯片或不同自研路径，复用部分软件资产。硬件外设、固件、扩展及厂商库仍需验证，不能假设任何 Arm 二进制都能无条件跨设备运行。SystemReady 通过硬件与固件基线改善标准操作系统的可部署性。[SystemReady](https://www.arm.com/architecture/system-architectures/systemready-compliance-program)

**优势边界。** x86 在既有企业应用、商业软件认证、运维经验和存量设备中有很强的迁移壁垒。若工作负载包含难迁移的二进制、特定库或认证要求，客户保留 x86 可能更经济。【我的推演】Arm 云端路线对有能力控制软件、拥有足够部署规模的客户更有吸引力，对一般企业则需要更完整的产品和服务验证。[年报 A]

### 11.3 与 RISC-V 相比——软件覆盖、交付和责任主体

**已有软件投入降低转换成本。** 客户需要的不只是指令定义，还包括编译器、操作系统、驱动、调试、性能优化及应用维护。Arm 的价值在于把现有生态带到客户新芯片上。对需要运行大量第三方应用的产品，兼容性涉及多个供应商，迁移工程更复杂。对软件由单一团队掌控的固定功能控制器，迁移范围可能更小，Arm 的优势随之减弱。

**有可购买的核心和系统方案。** CSS 提供预集成、经过验证的计算子系统，Arm 声称可减少风险、一次性开发投入，上市时间最多缩短一年。该数值为供应商产品宣传，未在本研究中独立复测。RISC-V 同样有商业 IP 公司销售核心、工具和支持，比较应落实到具体供应商的功能、交付记录及责任范围。[Arm CSS](https://www.arm.com/products/cloud-datacenter/neoverse-compute-subsystems)

**跨厂商的软件基线更成熟是阶段性优势。** RISC-V 允许模块化和定制扩展，需要共同基线支持二进制软件分发。RVA23 将一组扩展列为必选项，服务器平台规范也在推进软硬件互操作。因此兼容性差距会随标准和产品成熟而改变，不能把碎片化当作永久障碍。[RVA23 规范](https://docs.riscv.org/reference/rva23/v1.0/rva23-profiles.html) · [RISC-V 服务器平台](https://docs.riscv.org/reference/server-platform/server_platform_intro.html)

【我的推演】对需要按期推出复杂芯片的客户，付费购买成熟技术可能比自行组织全部研发和验证更划算。若客户团队强、软件可控、出货规模足够大，使用 RISC-V 节省指令集许可成本和获得定制自由的吸引力上升。RISC-V 指令集免费与商业核心是否收费需要分别比较。[RISC-V 授权 FAQ](https://riscv.org/about/faq/)

### 11.4 不同业务的护城河强弱

| 场景 | 壁垒来源 | 侵蚀因素 | 本研究判断 |
|---|---|---|---|
| 手机应用处理器 | 现有应用、操作系统、核心及整机验证，客户长期设计经验 | 大客户自研核心、授权议价、替代架构投入 | 已有生态优势较强，但收费仍受合同约束 |
| 云端与服务器 | 客户定制能力、Neoverse 软件和部署经验 | x86 存量兼容、迁移成本、客户自研 | 壁垒正在增强，客户与应用差异大 |
| 嵌入式与控制 | 工具链、开发经验、软件和安全验证 | RISC-V 商业核心及客户定制 | 按具体应用评估，固定功能场景更易替换 |
| AGI CPU | 可复用 Arm 生态与芯片设计能力 | NVIDIA、AMD、Intel 等产品，交付和供货风险 | 完整芯片的持续超额回报尚待证明 |

本表为研究者判断，不是市场份额排名。汽车安全认证针对具体产品与系统，采用 Arm 本身不能保证通过认证。

### 11.5 财务证据、趋势与反证

- **收费规模扩大。** FY2024–FY2026 版税为 1,802、2,168、2,613 M，两年增长 45.0%。授权及其他为 1,431、1,839、2,307 M。增长支持客户持续采用，但包含数量、价格、组合及关联交易变化，无法仅凭合计推断提价能力。[年报 A]
- **生态增长开始体现在云端收入。** FY27 Q2 数据中心版税同比翻倍，集团版税增 8.1%。云端新增部署份额采用第七章的限定分母，不能代替全球存量份额。[季报 B]
- **技术复制成本低，技术维护成本高。** FY26 GAAP 毛利率 97.5%，营业利润率 18.3%；Non-GAAP 营业利润率 43.0%。研发占收入分别为 56.4%／38.8%，说明生态维护和新品开发需要持续资源，收费壁垒尚不能等同不受投入约束的股东回报。[年报 A] · [财报 D]
- **现金回报需要另行验证。** TTM 公司 Non-GAAP FCF 为 1,096 M，SBC 现金流加回为 1,265 M。结合股数、研发效率及采购承诺判断价值，避免把架构普及全部资本化为股东收益。[季报 B]

最近三个完整财年与当期证据显示授权及版税规模扩大、云端采用增强。更长的产品级收费、客户续约和流失序列未披露，本研究对过去 3–5 年壁垒方向的判断主要依据已披露财务及客户设计路线，不能量化单独的生态回报率。

**改变判断的条件。** 若客户在量产主芯片中持续转向 RISC-V、授权续签受阻或单位收费承压，需下调对 IP 壁垒的判断；若收入增长长期伴随更快研发与资金占用增长，需下调对经济回报的判断。AGI CPU 则以实际交付、产品毛利及其对现有授权关系的影响评估。

## 主要风险

- 手机出货下行，若高费率产品渗透抵不过总量下降，集团版税和经营杠杆承压。观察整体版税能否随数据中心增长而加速。
- 授权增长依赖大合同及确认时点，若合同资产持续上升而收款放缓，利润增长可能领先现金回报。观察外部收入、合同资产和 CFO。
- AGI CPU 交付延迟或采购库存增加，会延后收入并占用现金，芯片业务放量也可能压低集团毛利率。观察交付、库存、毛利及授权续签。
- 当前估值要求较高的持续 FCF 增长。若增长、利润率或退出倍数低于第 6 节假设，现金回报与价格之间的差距扩大。

## 待验证问题

- 公司未披露：Arm 架构的全球服务器存量渗透率、AWS 具体版税、IP 两项各自利润、AGI CPU 合同取消条件及分季度毛利。以新增部署、集团版税、实际交付和集团毛利跟踪，无法做客户级盈利归因。
- 披露边界：FY24 年报未单列非流动融资租赁，FY27 半年报未单列该项但可以由附注 2 给出上界。采购义务披露为 FY26 年末余额及后续合同增量，未提供 9 月末统一可勾稽余额。集团固定资产和研发支出未拆出 AGI CPU 专项现金投入，芯片商业化的现金回报暂无法独立复算。
- 不可比：云端新增部署份额、全球设备存量、EC2 使用量和 Arm 财务收入是不同分母。公司预测与实绩分开。
