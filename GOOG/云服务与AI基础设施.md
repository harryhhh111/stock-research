# Google Cloud 与 AI 基础设施

> 建立及整理日期：2026-11-04。研究状态：active。公司主报告：[Alphabet（Google）](GOOG.md)。本专题是用户明确指定的AI产业链重点模块，后续云业务与建设进度优先回写这里；未配置自动更新或改变关注池。
> 本轮为既有研究拆分与整理，事实沿用截至2026-11-04已取得材料；财务截至2026Q3，项目状态按各来源日期，不代表11月4日现场验收。不是重新完成一轮全球项目普查。

## 1. 核心判断与研究边界

【我的推演】Google的AI基础设施正在从自用支撑，扩展为对外云服务和TPU系统供应；需求增长强，但资本回收与物理交付仍需验证。近期关键证据是第三方过桥容量已上线，自建扩张尚不足以完全满足即时需求。

本专题持续回答三个问题：能交付多少有效算力、客户是否真实使用并付款、投入最终带来多少可持续现金利润。覆盖GCP/Workspace、TPU、机房、电力及第三方算力；集团搜索和YouTube仅讨论其基础设施需求，不将所有数据中心都归为Cloud资产。

## 2. 云服务、芯片与机房怎样连接

| 层次 | 谁付钱、怎么赚钱 | 研究边界 |
|---|---|---|
| 自有数据中心与网络 | 支持搜索、YouTube、Gemini及对外云服务 | 内部使用不产生一笔可以再加总的外部云收入；集团CapEx不是Cloud专属CapEx |
| GCP计算/存储/AI平台 | 企业按消费量、承诺用量等付费 | 实际使用、交付和合同条款决定收入转化；订单不是现金 |
| Workspace | 企业按席位订阅协作和AI功能 | 在Cloud分部内，不能把整个Cloud营收当算力租赁收入 |
| TPU系统销售 | 向外部客户交付系统形成产品收入 | 与云上租用TPU不同，涉及备货、交付和回款；不假造单独收入或毛利 |
| 外部过桥算力 | Google付费采购第三方容量，再服务客户 | 与自建形成补充；租赁费影响利润，相关合同可能不在现金CapEx内 |
| 投资与担保 | 向合作伙伴投资或提供信用支持 | 投资收益不等于云经营收益；被投客户采购承诺不能另算一次已实现收入 |

### 为什么需要第三方过桥容量（2026-11-04补充）

【原始披露】管理层在[2026Q3官方电话会](https://abc.xyz/investor/events/event-details/2026/2026-Q3-Earnings-Call-2026-Ujou16CTw9/default.aspx)明确表示供给受限，外部算力Q3末上线、Q4扩大使用并带来短期利润率压力；更多容量可以服务更多需求。这里的“过桥”指填补可交付容量的时间缺口，不是过桥贷款，也不是一个单独物理园区名称。

【我的推演】自建需土地/许可、电力、机房、设备、网络和验收全部到位；资本开支增加不代表客户今天就能用。采购外部已就绪且兼容的容量，可在自有容量爬坡期间提前履约、减少等待和客户流失。即使第三方获得部分利润，额外订单的贡献仍可能为正；利润率下降不必然意味着利润总额下降。

必须区分采购成品算力、租机房自行装设备、向客户/伙伴出售TPU系统三种关系。本次过桥表述明确是使用第三方compute capacity；现已确认至少SpaceX协议（见下节），但尚未确认所有供应商、MW、芯片、价格、合同期限或退出时间；不能将任何第三方机房或TPU外售都算进同一“过桥项目”。“过桥”也不保证合同短期或自建投产后立即终止。第三方TPU设施与客户自有机房另属系统销售部署，经济关系需分别判断。

投资意义：近端利好具有现成兼容容量的供应商，但不能仅凭Google这一表述给某一家运营商归属订单；中期关注外购单位成本、自建投产日期、最低采购承诺和迁移/闲置风险。尚不能判断瓶颈全部来自电力、机房或某种芯片，也不能仅凭采购行为认定所有订单具有高回报。

### 供应方与客户为何通过Google购买（2026-11-04补充）

【原始披露】已核对[SpaceX 2026-06-05 SEC文件](https://www.sec.gov/Archives/edgar/data/1181412/000162828026041150/spacexagreementfwp.htm)：与Google LLC签算力服务协议，涉及约110,000张NVIDIA GPU及CPU、内存等；2026年10月至2029年6月约定月费9.2亿美元，9月前以较低费用爬坡；若9月底GPU交付不足，宽限一个月后Google可终止或按实际量降低费用。2026年底后双方可提前90天通知终止。客户保有其内容、模型和相关数据知识产权。

因此上一节“不确认供应方”应修正为“已确认至少SpaceX这一合同方，但完整过桥供应商名单及具体园区、芯片型号、实际交付量和负载分配仍未确认”。约11万张为合同约定规模，不是本轮核验的上线实绩；SEC本文件没有确定具体园区，不能直接写成Colossus 1或Colossus 2。不能把这一协议金额全部机械归入Q4公告过桥成本。

【商业机制解释/我的推演】购买Gemini模型/API或企业AI产品的客户，需要模型权利、推理服务、权限、安全、数据集成和服务支持，而不只是GPU。SpaceX交付算力不代表交付Google模型服务；Google采购底层算力再提供产品，通常不是原封不动转售GPU。已有GCP客户还会考虑数据库/存储/网络集成、迁移成本和合同责任。此处解释一般交易逻辑，不断言每位客户的合同和底层路由。

有自己模型和基础设施团队、需求规模大的客户可以直接采购第三方算力；价格可能更低也可能未必，需比较利用率、运维、网络/数据迁移、安全和容量期限。Google价值在模型及平台层时，底层容量可替换；若只是标准化GPU转售、客户可直接买同等服务，其加价能力就弱。评价护城河应看增值层与单位成本，不能只看机房所有权。

## 5. 订单、电力与容量口径

【原始披露】2025年末RPO为2428亿美元，主要与Cloud有关；2026Q3官方电话会披露Cloud backlog为5610亿美元，预计略高于55%在未来24个月转为收入。来源：[2025 10-K](https://s206.q4cdn.com/479360582/files/doc_financials/2025/q4/GOOG-10-K-2025.pdf)、[Q3官方电话会](https://abc.xyz/investor/events/event-details/2026/2026-Q3-Earnings-Call-2026-Ujou16CTw9/default.aspx)。公司已披露转化时间，不能再把最新值仅标为二手转录；订单包含服务/产品履约，不等于已收款或当期使用量。

项目记录按“物理园区→分期→电源接入→设备安装→验收→可用IT容量”跟踪。公告投资、土地开发、正式开工、通电、装机和承载客户负载是不同阶段。发电铭牌MW、接入额度MW和IT负载MW也不同；PPA购电合同不自动意味着对应新增发电机组投运。项目及客户交叉涉及同一园区时按物理地点去重。

2025年末未起租合同付款585亿美元、采购等承诺1491亿美元均是集团历史基线，不能与2026全年CapEx直接相加，也不是全部Cloud新增需求。最新承诺明细仍需按完整附注核对，详见[集团资本分配](GOOG.md)。跨公司建设线索见[数据中心建设进度](../数据中心/建设进度2026-2029.md)，未经原始材料复核的线索不升级为已投产容量。
