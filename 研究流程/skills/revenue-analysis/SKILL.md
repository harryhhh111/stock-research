# 营收分析

从研究仓库根目录定位 `研究方式.md`、`研究流程/standards/` 和 `研究流程/index/html-index.json`。读取《研究方式》的营收要求和其链接的财务与估值细则，以及展示规范和交付清单中适用条款。离开研究仓库时，说明缺少本项目的规范和报告索引。

1. **写前列覆盖矩阵。** 每家公司分别确定报告范围、财年和最新披露期。完整研究和现有主报告迁移列最近三个完整财年、当年 Q1 至最新已披露季度及可比基期，按披露范围列集团和主要分部。迁移时盘点历史主文档的有效底表及解释。局部更新按用户任务及实际影响范围复核，主报告迁移同时遇到最新财报时，两项都列入范围。
2. **取证和复算。** 优先回到公司报表、分部附注和指引，记录日期、位置、币种、单位和合并边界。需要拆季时留计算。用同期间同口径复算同比、分部占集团比例和适用的环比，逐期检查分部合计、抵销和差额。重述优先使用可追溯的可比重列。缺失或不可比逐项写明查过的材料及结论影响。
3. **写回营收模块 HTML。** 已有单页报告沿用原营收章节。营收部分前置最新实绩与指引对照。年度、单季、累计和 TTM 分表，主要分部逐期列金额、同比和占比。解释重要变化来自销量、价格、组合、汇率或并购中的哪些因素，证据不足的部分保留为未解释。图和表用同源数字，关键数据放在可直接读取的 HTML 表格。跨公司研究分别维护各自主入口。
4. **对照最终正文验收。** 逐公司、指标和期间将覆盖矩阵与 HTML 实际数字和来源对账。只在历史笔记、生成脚本或 TTM 公式出现的期间，不能计为主报告的年度或单季覆盖。核对营收摘要、图表、判断和估值输入是否同步。把结论、缺项与证据位置记入报告现有核验区。关键应查项缺失时先补，确有证据限制的记录影响，范围内未完成项保留为未通过。

## 主报告交付检查

完整公司研究和主报告迁移在写作前用公司披露确定最新完整财年和最新单季或半年，记录在本轮覆盖矩阵。先从用户要求确定任务范围，再根据披露确定期间。只有用户要求变更范围或披露证据发生变化才更新对应输入，并保留原因。主报告迁移应继承历史覆盖，同时加入最新披露。

营收章节使用 `id="revenue"`。年度和单季或半年底表分别使用 `annual-revenue` 和 `quarter-revenue` 作为表格 ID 或紧邻前置标题的 ID。实绩与指引速览可置于这两张底表前。表头首列写指标，其余列按时间顺序写 `FY2025`、`2026 Q1` 或 `2026 H1` 等期间。表内集团营收行使用 `集团营收`、`集团收入`、`集团持续经营收入` 或 `集团`，金额置于每格首位。

完成报告后，用取数前已确定的期间运行本 Skill 自带的 `scripts/check_coverage.py`。传入有实际年度和单季底表的最终页面，卡片首页记录模块链接与摘要。以下为财年 2025、最新单季 2026Q3 的调用示例，执行时替换为本次实际路径和期间。

```bash
python3 研究流程/skills/revenue-analysis/scripts/check_coverage.py 公司目录/reports/revenue-profit.html --latest-annual 2025 --latest-period 2026Q3
```

默认查三个完整财年，需延长时用 `--annual-count`。仅半年披露时使用 `YYYYH1` 或 `YYYYH2`，并在报告说明披露边界。脚本返回预期期间、实际期间、缺口和正文哈希，失败以非零退出。修正后用同一组预期期间重跑。若披露不足或口径确实不可比，保留失败项和原因，按 SOP 记录具体例外和影响。将检查结果及证据位置记入模块核验区，首页链接该记录。脚本覆盖集团底表的期间、金额是否填列和表序，分部、计算、口径及业务解释继续按内容验收执行。
