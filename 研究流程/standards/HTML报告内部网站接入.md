更新/核对日期：2026-11-19。读者：内部网站后端及前端开发。目标：直接加载本库生成的HTML，保留原有卡片、模块导航、表格、图形与来源；不重新排版成Markdown。

**推荐最小接法：显式登记可展示页面 → 发布首页、关联模块及获准资源的同版本快照 → 后端返回首页 URL → 网站用 iframe 展示。** 卡片用普通链接进入模块。仓库提供唯一报告索引及校验工具，本文件中的网站接口是接入契约，具体框架及鉴权沿用网站现有实现。

## 2. 如何发现和登记报告

直接读取仓库的 [研究流程/index/html-index.json](../index/html-index.json)，字段按 [命名与索引规范](HTML报告命名与索引规范.md) 和 [JSON Schema](../index/html-index.schema.json)。已配置旧路径的消费端需改用此路径。网站数据库可缓存索引，仓库索引为唯一维护清单。后端可直接加载 HTML。

- 候选来源可以扫描项目目录，但不能把所有`*.html`自动发布。`factcheck/data/`里有原始财报网页，Skill的`assets/report.html`是未填模板，均不是研究报告；默认排除原始证据、模板、缓存、外部参考库、临时产物。
- `report_id`是稳定ID；用`entity_id`关联公司/主题，证券仍显式用market/mic/symbol。不得凭文件夹名、ticker或文件排序自动认定身份、主报告和最新版。一个公司可有一篇主报告与多篇专题/历史版本。
- 仓库索引包含：ID、标题、主体/主题、报告类型、入口路径、文档更新日、财务截止、行情截止、内容/维护状态、正文哈希及资源清单；源版本和访问权限由发布服务结合实际commit/工作树和登录体系提供，不写成当前Schema未支持的字段。未知日期填null，不拿文件mtime冒充财报或行情截止。
- 标记`company_research`、`topic`、`update`、`demo`类型；demo默认不进真实研究列表。发布/可访问状态与研究内容完整性分开，允许显示有缺口的报告，但要标清。
- 本库`research.yaml`及`研究流程/tools/entry/validate.py`**目前仍只支持Markdown**。网站可以读取其主体身份作为关联线索，不能把旧Markdown章节或日期当新HTML内容，也不要直接改后缀绕过校验。HTML原生语义提取是后续独立适配工作。

**真实索引条目示例（HTML索引Schema v1；不是research.yaml字段，不要复制进旧YAML）：**

```json
{
  "report_id": "implied-valuation-demo",
  "title": "估值条件反推演示",
  "entity_id": null,
  "project_dir": "估值反推Skill",
  "entry_path": "估值反推Skill/演示报告.html",
  "report_type": "demo",
  "status": "ready",
  "content_status": "synthetic",
  "document_updated_at": "2026-11-17",
  "financial_as_of": null,
  "market_as_of": null,
  "layout": "legacy",
  "assets": [],
  "unpublished_links": {},
  "content_sha256": "b6eadff8de92ccdf6d6d3748105ea88623645a8fadc801d97f9d235801a728fb"
}
```

本示例不是证券主体；页面中的价格日期为合成数据，故元数据不将其声明为真实行情截止。发布元数据中的版本和权限由后端写入，不能信任浏览器传入的角色或任意文件路径。

## 3. 后端怎样提供HTML与配套文件

部署配置给出研究库/发布包根目录，不把开发机器的`/Users/...`路径写死进网站。第一版可从人工审核后上传的发布包读取，或从明确批准的Git commit导出；本站现有文件有工作树改动，不能仅用HEAD编号冒充已经提交的HTML版本。

保留索引中实际登记的相对目录结构。新报告位于`<项目>/reports/`，当前legacy入口暂不批量迁移；不能按ticker拼接路径取代索引。以下使用现有兼容文件举例，路径**仅为路由设计示例**：

```text
/research-content/{snapshot}/MSFT/MSFT.html
/research-content/{snapshot}/MSFT/传统软件与现金流.html
/research-content/{snapshot}/MSFT/factcheck/data/inputs.json
/research-content/{snapshot}/估值反推Skill/演示报告.html
```

`snapshot`表示同一批明确文件的不可变发布快照；主HTML、样式、图片和获准附件都来自同一快照。真实发布可用commit＋文件清单哈希，工作树预览用独立预览版本并明确dirty，不能覆盖旧快照后继续声称内容未变。

保留目录后，`factcheck/data/inputs.json`、`传统软件与现金流.html`和`../...`才能按原位置解析。**只把正文映射为`/{report_id}/content`，却没有处理相对资源路由，会产生断链。** 本方案不建议通过注入`<base>`偷偷修复，因为它也会改变章节锚点及其他链接语义。

处理文件时：

1. 用登记ID/快照在服务端查出入口及允许文件（entry_path＋assets，兼容页另按redirects查找目标ID并授权）；路径解码与规范化后必须落在发布根目录，并命中该快照白名单。拒绝越界、指向外部的符号链接、双重编码绕过及任意URL代理；不开放整个研究库的目录浏览。
2. HTML按UTF-8原样返回，`Content-Type: text/html; charset=utf-8`，避免二次HTML转义或转为Markdown。按文件类型返回CSS/SVG/PNG/JSON等；脚本附件若获准供查证，应作文本或附件下载，绝不在服务端执行。
3. HTML、图片、JSON和证据下载都执行同样的授权，不能只保护列表页。默认内部访问；不能因URL难猜就认为有权限保护。
4. 内容路由必须在SPA兜底路由之前匹配。未登记/缺失资源返回可识别的404或权限错误，不把网站index.html作为200响应伪装成功。
5. 页面/敏感附件宜使用`Cache-Control: private, no-store`起步；后续私有缓存按用户/快照隔离并正确处理权限撤销。不可变快照可以配ETag，但不因此进入无鉴权公共CDN。

## 4. 第一版只需要这些网站接口

下表为**建议契约，不是当前仓库已经存在的服务**，可按网站既有命名调整。

| 能力 | 建议接口 | 返回内容 |
|---|---|---|
| 报告列表 | `GET /api/research-reports` | 已授权报告的ID、标题、类型、主体、截止日/状态、可用版本 |
| 阅读入口 | `GET /api/research-reports/{id}` | 同上元数据，以及后端构造的`content_url`、`download_url`、版本和已知资源缺口 |
| 正文/资源 | `GET /research-content/{snapshot}/{registered_path}` | 已登记HTML或获准资源；每个请求授权，非任意文件读取接口 |
| 下载 | `GET /api/research-reports/{id}/download` | 单文件报告下载HTML；多文件报告下载含获准相对依赖的包，附件范围明示 |

列表不必返回整份HTML；前端不需要读取公司财务JSON来重新画图。hl-trader的「公司研究」是登录后的内部阅读入口，采用以下规则：

- 默认展示`entity_id`以`company:`开头、`status`为`draft`或`ready`的已授权HTML报告；排除`demo`、`synthetic`及`archived`，只有Markdown的公司不出现。草稿可以阅读，列表和阅读页均显示“草稿”标识。
- 按`entity_id`聚合公司，公司列表只打开该主体唯一的非归档`company_research`首页。模块、专题和更新由首页卡片或链接进入。按授权提供各 HTML 页面并保留相对路径。缺主报告时显式标“主入口待补建”，可在内部待整理区查看已有材料。日期未知显示“未记录”。
- 行业与公司在列表上分开。新增「行业研究」分类时从同一索引筛出 `topic:industry-` 主体和以 `-overview` 结尾的非归档行业首页 ID。其余同主体页面仍可授权并由卡片进入。首页、模块和相关资源应使用同一个快照，跨公司或行业的相对链接也要核对目标发布与访问权限。
- 分别显示交付状态、`content_status`、数据截止日和研究缺口。`ready`表示已交付可阅读版本，不代表完整财务验收；`unreviewed`提示“内容验收未完成”，`partial`提示“部分范围已核验”，范围以正文记录为准。网站授权独立执行，不能把状态当权限。
- `unpublished_links`表示证据附件尚未纳入可访问范围，不自动隐藏正文，也不自动要求降为草稿。外层阅读页展示原链接和原因；发布副本可将对应链接禁用或改为明确的不可用提示，保持源HTML正文唯一维护。不能只留下点击后不明原因的404。核心图表、样式、图片及图表数据仍须齐全、登记并可访问，不能用此字段绕过展示依赖检查。

当前索引的公司报告仍沿用原状态，不为了接入网站批量提升为ready。当前微软和QXO分别已有一个legacy主入口；微软另有现金流专题和AI Berkshire研究试验，须从主入口关联。AMD只有一篇更新，主入口待补建；研究试验应保留其标题及试验性质说明。演示报告即使ready也不进入公司列表。实际数量和状态始终从索引读取，不硬编码这份盘点。

结构化结果JSON是可选附件，不是显示HTML的前置依赖；若HTML本身需要该JSON绘图，它就是必需展示资源，须登记并提供。原始数据不能默认对全站用户开放。

## 5. 前端怎样展示

使用独立iframe，保留报告自己的CSS和图形，避免将整份HTML注入应用DOM而造成样式冲突或脚本越权。不要把报告作为需执行服务端模板语法的字符串渲染。

静态阅读模式示例，`src`取后端返回且已授权的URL：

```html
<iframe
  title="研究报告"
  src="/research-content/preview-version/估值反推Skill/演示报告.html"
  sandbox=""
  referrerpolicy="no-referrer"
  style="display:block;width:100%;height:calc(100vh - 80px);border:0"
></iframe>
```

示例地址仅说明形态，不是可直接访问的已部署URL。URL由后端正确编码中文、空格、`#`等路径字符；不要对整个含`/`路径盲目编码或重复解码。

- 静态模式默认不运行报告脚本，核心正文/精确表/静态图仍应可读；使用frame自身滚动，不为自适应高度放开同源权限。窄屏表格局部横向滚动由报告自身CSS负责。
- 网站外层显示标题、版本、真实截止日、研究缺口、下载/返回操作，避免用“网站同步时间”代替报告数据日期。
- 若启用报告内打印按钮、目录高亮或交互图表，使用审核后的**增强模式**：隔离来源、仅按需授予`sandbox="allow-scripts"`，必要的打印另评估`allow-modals`；不要为省事同时开放脚本和同源能力。增强模式与CSP必须配套测试，不能承诺所有脚本默认可用。
- 脚本受限时，MSFT等已有报告的打印增强（如展开折叠内容）会受影响。验收时明确静态阅读/增强/下载各自支持什么；需要打印完整证据时检查折叠区是否展开，不能只看正文无报错。
- 外部来源在当前frame导航、弹窗、新标签打开和附件下载会受sandbox影响。第一版可将“来源/附件”操作放在外层受控入口；若要给frame放开弹窗/下载，先评估目的地址与权限，不为一个链接直接解除sandbox。

iframe的sandbox语义参考[MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)。

## 6. 隔离、响应头与资源检查

**推荐把报告放在独立内容来源上**，报告来源不接收主应用的宽域会话Cookie，不能调用主应用管理接口；跨来源嵌入的鉴权还须按网站实际Cookie策略验证，不能在匿名端点裸露内容。第一版同源托管只限明确登记的静态页面，且保持空sandbox和禁止脚本；还应通过响应头sandbox等手段覆盖用户直接打开内容URL的场景，不只保护iframe嵌入。

后端配置CSP限制内容加载、执行和可被谁嵌入：静态模式禁脚本，允许报告确实需要的内嵌样式/图形及获准本地资源；默认不允许联网取数。增强模式如需内联脚本，应通过已审核脚本哈希/nonce等控制，而不是给整个内部域开放任意脚本执行。未来`fetch`本地JSON时会遇到opaque-origin/CORS限制，应优先把必要展示数据内嵌；不能为绕过错误直接加`allow-same-origin`。

报告响应的`frame-ancestors`允许内部网站的实际来源，网站自身`frame-src`允许报告来源；不要叠加会阻断嵌入的`X-Frame-Options: DENY`，跨来源内容也不能盲用SAMEORIGIN。`frame-ancestors`必须在HTTP响应头设置，不能指望HTML的meta标签生效。加`X-Content-Type-Options: nosniff`，敏感URL不写进第三方分析日志。[MDN响应头说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors)

发布前检查`src`、`href`、CSS url、脚本fetch和`file://`/本机绝对路径，不能只检查图片。已知相对证据链接分三类处理：获准附件一同发布；已发布HTML/历史资料通过受控路由解析；无权或未收录的资料在资源清单标明并阻止发布或在展示副本中明确标缺口。不得静默删掉来源，亦不能因此把全部factcheck目录公开。必要的链接重写只作用于保留版本记录的展示副本，原始研究HTML和来源原文保留。

## 7. 最小联调与验收

1. 先仅登记“估值反推Skill/演示报告.html”，限制内部预览访问；无需执行Python、安装Skill或连接数据商就能展示。明确演示标识，不作为真实公司研究。
2. 登录网站→打开列表→进入报告：UTF-8中文、四块内容、精确数值与原文件一致；1280px/390px可读，页面不横向整体溢出；断网后已加载内容及打印样式仍可读。
3. 测试匿名访问、无权限用户、直接正文/附件URL、猜测路径、`../`及符号链接越界均不会泄露资料。错误资源返回真实错误，不回SPA首页。
4. 再接MSFT主报告：确认静态与增强模式边界、目录锚点、内嵌图、折叠区/打印、同目录专题与证据链接；为缺失/不可发布的相对附件明确处理结果。不能因演示单文件成功就称全库接入通过。
5. 发布新快照后切换列表指针，旧HTML与附件仍属于原版本；可回退到旧快照。展示报告日期、源版本、发布日各自含义；只有结构检查通过不代表研究内容核验通过。

## 8. 对接边界与后续扩展

本库已提供HTML索引、Schema和报告管理/校验工具，当前共登记六份既有报告。后端接口、网站鉴权、索引缓存和网站部署仍由网站侧实现，本轮未部署或配置远端权限。

后端首轮只需确定：研究库/发布包如何同步、现有登录体系怎样保护内容、怎样读取仓库唯一索引、使用哪一个内容来源。目录索引和全文检索可以以后补，不需要先改研究正文或升级research.yaml。

未来新报告继续交付HTML＋实际需要的资源/可选JSON＋日期和核验信息；不为网站恢复Markdown正文双维护。后端若需要原生章节语义读取，再单独适配HTML标题与稳定id，本文件只解决整页展示。
