## 四、历史财务与指标的最低标准

完整公司研究、现有主报告迁移，以及涉及营收的财报更新或纠错，须在取数前按 [revenue-analysis](../../skills/revenue-analysis/SKILL.md) 确定营收覆盖矩阵，并在交付前用同一矩阵核对最终营收 HTML。未安装时直接读取仓库 Skill。迁移任务保留并核验原研究覆盖范围，同时加入最新披露，不因本轮有财报更新自动改成单季专题。

完整研究和主报告迁移须按营收 Skill 的「主报告交付检查」运行覆盖脚本，输入以开工时由原始披露确定的期间为准。缺少年度、单季或集团营收金额，以及年度底表排在季度底表后，均须修正并复验。确有披露或可比性限制时，按下文记录具体例外，验收记录保留脚本发现的缺口及影响。财务来源、复算和经营解释仍须逐项验收。

### 1. 时间长度与可比性

- **默认最近三个完整财年，另列最新已披露季度/半年或 TTM。** 两个完整年加本年半年不算三个完整财年；年度、季度、半年、TTM 分开比较。
- 财年与自然年不同须标明实际起止日；季度/半年同比用上年同期。分部重划、并购、分拆、汇率与重述说明可比边界。
- 周期企业按问题延长到 5–10 年，不机械年化景气高点。近期上市、分拆、非上市或退市公司不足三年可比数据时说明已查来源、可得期间和缺口。
- 三年数据不等于三份文件；报告可能自带多期数据，也可能缺所需附注。以可追溯、可比较底表验收。

### 表格期间、单位与展示约定

1. **营收结构默认顺序**：章节前部先展示最新已披露实绩与下一季度/年度指引对照；完整历史底表依次为三完整财年年度历史 → 当年所有已披露季度的单季实绩 → 必要时单列当年累计。不能用H1替代可取得的Q1、Q2。仅半年披露或无法合理拆季的公司改列半年，并说明例外。
2. 年度、单季、累计、TTM各自成表；不在同一组比较列中把2025全年、2026H1与2026Q3并排比较。数据来自不同披露文件不是问题，比较期间不同才是问题。
3. 营收结构每格默认“收入 / 同比 / 占同期间集团收入比”，不再用两张重复表分别放金额和比例。上年基数保存在可追溯底表；需要直接比较时才另列。分部与产品服务是不同切法，分别说明分类边界及各自加总，不重复相加；没有独立业务利润就不能假造。
4. 盈利与现金流默认“三年年度底表＋最新季度同比＋当年各季度环比”。Q1环比基期是上一财年Q4，必须标明；利润率变化用百分点。亏损、负FCF及跨零变化优先比较金额，不机械给增长百分比。季节性、促销移期、付款节奏及投资收益在表后解释；季节性强时同比作为主要判断依据。累计数有解释价值时单列，不为了缩表删除重要事实。
5. 资产负债采用最新已披露期末；TTM随最新实绩滚动，写明起止期间和公式。原始累计数相减拆季须保存计算；不将年内累计每股收益直接相减冒充精确单季EPS，应使用单季披露及加权平均股数口径。
6. 指引在前部对照表及配套图中单列发布日期、预测期间、指标区间、同比基数、假设和限制；实绩与指引分列并用文字/线型区分，不混作同期间实绩序列，汇率或分类口径不同就近说明，不可直接比较。区间图显示上下限；以中点定位时显著注明为复算示意。公司未给分部指引就明确说没有；本报告用实绩加指引拼接的全年数标为复算/推演，不冒充公司指引。没有数值指引时不把“high teens”等定性说法改造成精确区间。
7. **统一单位放在整表上方**，例如“单位：B美元；比例为%”。美元金额按规模选B美元或M美元等，首次注明1 B＝10亿、1 M＝100万；不用“十亿美元”作金额单位名称。不要在每个期间表头重复单位。混合币种/量纲时表前说明，并在对应行名标明例外；股价、EPS、股数等不能误套金额单位。
8. 同一可比表精度一致；金额通常保留2—3位，比例通常保留2位，管理层四舍五入值不增补虚假精度。合理舍入差异说明，不以零替代缺失。

### 季度完整性与业务子文档继承

- **适用于公司研究的营收及财务模块和承担经营跟踪的业务页**：截至Qn已披露时，核心经营底表就地列当年Q1至Qn，不以最新季度同比、累计或TTM代替完整序列。业务收入、利润与利润率应匹配同一期间；引用集团CFO/CapEx/FCF支持业务判断时也要列完整年内单季，并明确集团/分部边界。
- 新建或重写经营底表必须执行此规则；“专题”“仅整理”“拆分迁移”不能作为省略已披露季度的理由。单条新闻未涉及经营底表时仅核查影响范围。原始资料暂未取得属于研究未完成，不写成公司未披露；仅半年披露、重述或无法拆季等例外须列已查材料、实际覆盖和影响。
- 在取数前按指标组列出“预期期间→实际期间→来源→缺口类型→验收结论”。缺口分公司未披露、研究未完成、不可比、不适用。完整性和计算正确性均通过后才能称该底表完整；入口/标题校验不替代财务验收。
- 可加总金额按Q2=H1−Q1、Q3=9M−H1、Q4=全年−9M拆季时保存输入及脚本；利润率用单季利润/收入重算。EPS、加权股本和比率不直接累计差分。Q1环比须取得上年Q4，负值和跨零优先给金额变化。
- 交付前逐组核对季度连续性、同比/环比基期、单季与累计勾稽、年度/单季/累计/TTM分表，以及摘要/跟踪/估值联动。发现的重复问题沉淀在本SOP及模板、清单，不靠为每家公司保留一份临时整改方案；用户批准执行的临时方案完成后按授权删除，原始证据和核验记录保留。

### 2. 最低底表

| 类别 | 应列内容，以披露和适用性为限 |
|---|---|
| 经营 | 营收及主要分部营收、占比、同比；毛利、经营利润、归母/归属普通股股东净利润与利润率 |
| 现金流与投入 | 经营现金流 CFO、现金 CapEx、FCF；CapEx 用途、现金支出与资产增加区别、采购/租赁承诺 |
| 财务结构 | 现金及现金等价物、计息债务及到期结构、租赁负债、净债务口径、股东权益；重大利息成本 |
| 资金效率与分配 | ROE，适用时 ROIC；EPS、股数变化、分红与回购。区分归母与合并总额，检查回购及激励稀释 |
| 当前估值 | 行情截止日、价格/币种、适用股本和市值、净债务与企业价值；可用 PE、PB、EV 倍数或 FCF 收益率 |

金融等特殊行业改用合适指标并解释，不强套工业企业 CFO/CapEx/FCF 或毛利率。未披露的业务利润、AI 收入等不假造精确分项。

### 3. 计算与解释

完整研究、主报告迁移以及改动 CFO、现金 CapEx、FCF 底表或现金桥的更新，按[现金流与资本开支 Skill](../../skills/cash-flow-analysis/SKILL.md)执行。先锁定披露期间及现金口径，再用已核输入对照最终 HTML，检查期间、金额、FCF 复算和现金桥。图表与原始披露的口径仍分别核验。

- 同比 = 本期 / 可比上期 − 1；上期为零、负值或发生盈亏转换时优先解释金额变化，不机械给正常增长率。
- 业务占比 = 分部营收 / 同口径集团营收；内部抵销与合计差异注明。
- 毛利率、经营利润率、净利率用同口径利润除以营收；净利率注明归母还是合并净利润。
- ROE 默认归母净利润 / 平均归母权益，平均权益至少用期初与期末；单季/半年不当全年，若年化须标明。ROIC 说明 NOPAT、税率和投入资本定义。
- FCF 默认 CFO − 现金 CapEx，注明无形资产、租赁、公司调整后 FCF 等差异；不以承诺支出或非现金资产增加替代现金 CapEx。
- FCF 收益率说明期间和分母；股权口径通常用对应 FCF / 市值，企业口径用匹配现金流 / EV，不混用。
- 给公式、输入、来源和结论，不能让用户自己补同比、利润率或 ROE。数据不足明确缺项，不用零补齐。
- 对重大变化解释量、价、组合、地域、成本费用、投资收益、一次性项目与口径调整；能作贡献拆解或利润桥则计算，不能量化时区分证据与推测。

### 4. 异常识别、解释与验收（2026-11-11细化）

原有“异常就近解释、提供变化桥”必须落实为以下动作；不能只写“费用高”“可能是一次性”或“待核实”就算完成分析。

1. **主动识别**：检查比例越界（如毛利率>100%、负成本）、高毛利与经营亏损并存、收入增而利润降、利润与CFO/FCF背离、盈亏转换、异常税率、投资/汇兑/重估、减值/冲回及单季差分异常。不限于本清单；比较同业前先确认会计科目分类。
2. **先核数据**：回查原始主表和附注，统一主体、币种/单位、期间、总额净额、利润归属与重述版本；保存原始累计数及拆季算式。把“算术可复现”与“原数可靠、原因确认”分开验收。明显偏离不默认是舍入，能计算时给舍入误差上限。
3. **量化异常**：就近写差额、比例/百分点及对集团贡献。毛利超过收入须算隐含成本，若分母很小同时说明金额重要性；“分母小”不能单独解释正收入下毛利超过100%。
4. **经营桥必须展开**：高毛利却亏损时，列“收入−营业成本＝毛利−研发/销售/管理/减值等＝经营利润”并勾稽。解释为何投入位于毛利以下、是否资本化与摊销，不能把高毛利当高净利或跨模式定价权。利润变化则量化主要增减贡献；利润/CFO/FCF背离给现金流桥。现金支出、费用确认及资产新增分开，不重复扣除。
5. **解释的证据等级**：分“公司附注/管理层明确说明”“可由已核数据直接证明”“研究者推测”。列出可能原因只是核查方向，不是成因结论；尽力继续核查公开证据，获取受阻才明确已查来源、具体缺项和影响，不能以待核验代替可完成的工作。
6. **持续性与投资影响**：说明发生期间、税前税后、现金/非现金、经常/非经常；会计非现金仍可能是经济损失，一次性也不自动剔除。若给正常化利润，逐项列调整依据、税效及保留风险；无法支持就不构造精确调整值。说明是否改变盈利能力、资本回报、估值及原判断。
7. **交付门槛**：每项记录“发现→原数核验→计算勾稽→成因证据→持续性/影响→结论”。原因未确认则表内标待核实，并联动摘要、模型、风险及跟踪项；不得据该异常推经营改善或把该项验收标通过。若原因已由费用桥解释，高毛利/负经营利润可以是合理业务特征，不预设为错数。用户指出一处时检查影响范围内的同类异常，不靠隐藏列/删数据规避。

- CapEx 先列三年历史和用途，再看在建、投产、爬坡、交付；扩产、维护、收购、租赁、预付款分开。金额不能直接推出新增有效产能。
- AI 投入区分已支付、承诺、在建与经营费用；产出区分独立收入、现有业务提效和待验证收益，不将云业务总收入当 AI 收入。

### 资本分配章节的最低展开

现金、融资与资本配置模块至少有三年历史、最新单季/累计进展、用途与融资解释，分别回答：

- 实际付了多少现金，投向哪些业务/项目？披露不够精细时列可用替代指标及边界，不能把集团CapEx、分部资产增加直接称为数据中心支出。
- 已付、未付款资产、在建、未开始租赁和未来采购承诺分别是多少？资产增加不是现金付款；不将承诺与未来CapEx指引简单相加。
- 分红和回购实际执行多少？剩余授权不是已执行；结合期末股数净变化、SBC及每股回报评估稀释。
- 股权投资和并购投入多少现金、现有账面价值多少、是否已交割？估值上调不是新增付款；已支付金额不再保留为“待付”。
- 经营现金能否覆盖投入？补充融资、现金余额变化及债务/租赁约束；不把全部投资现金流净额简单称为CapEx。
- 收益靠什么兑现、证据到哪一步、什么事实会证明资本配置无效？不能只以收入、利润或投资浮盈增长认定投入回报优秀。

## 七、估值与研究判断

- 先给可复算价格和估值，再解释对应什么增长、利润率、现金流或恢复情景；注明模型假设，不把反推当全体市场真实观点。
- 同业比较匹配业务、阶段、资本结构、财务期间和周期。未来交付能力不等于当前收入，成熟企业估值不能直接套在建资产。
- 主文档收敛到：当前判断、1–3 个关键假设、正反证据、最重要跟踪指标，以及什么新增事实会改变判断。
- 情景分析按需要使用，未知因素显式保留；资料完整不意味着必须给买入结论。

### 当前价格隐含的预期与兑现年份（必答，2026-11-14）

完整公司研究及涉及估值的更新，必须回答“现价已经计入什么未来、预期何时兑现、还需要多少超预期”。既有情景分析按需的规则不豁免本项；只列PE/PS/EV倍数或“市场看好AI”不达标。

1. **预期来自哪里**：分别列当前成熟业务、已在商业化的新业务、尚待验证的远期产品/技术。把公司披露/指引、有来源及日期的投资者或分析师叙事、【我的推演】分开。未经核实的产品名称和概念先确认含义与业务边界，不直接认定为公司路线或市场共识。
2. **具体是哪几年**：以行情基准日出发列目标财年及距今时间，不只写“长期”。按业务周期比较合理的兑现窗口（例如3年、5年，远期业务必要时更长），列商业化、放量、收入确认、利润与现金回收的关键节点；预测列与实绩明显区分。
3. **需要达到什么业绩**：用可复算模型反推能支撑现价的收入、利润/FCF、增长率、利润率及适用业务驱动（销量、份额、价格、版税率等）。固定哪些假设、求解哪些变量必须明确；不能把多个未知数同时反推成唯一答案。与当前基数、公司指引及可核验行业空间比较，解释可行性与竞争/投入约束。
4. **如何从未来回到现价**：明确当前市值/EV及截止日、预测期、折现率/必要回报率、终值倍数或长期增长率、期间现金流、净债务和稀释口径，股权与企业价值口径一致。用未来倍数法时列未来利润/现金流和估值折现及期间股东回报的处理；不能直接把未来利润乘倍数当今天的价值。说明终值现值占比（模型适用时），检验远期假设的影响。
5. **多少预期已被计价**：比较既有业务延续、关键新业务兑现、兑现延迟或低于预期等有区分的路径，至少展示支撑现价的条件及偏离条件的后果。列各情景的具体年份、所需业绩、现值/每股价值及相对现价差异，单独检验终值倍数收缩和兑现延迟；延迟时说明哪些费用、投入和竞争条件随之变化，不仅机械平移收入。
6. **结论与反证**：明确现价对哪些假设依赖最大、按模型哪些乐观结果已被计入、什么新增事实构成超预期或证伪，联动摘要、风险和跟踪指标。价格不能唯一识别全市场真实预期，可能由多组增长/利润率/折现率组合解释；剩余估值不能直接命名为某概念的“市场定价金额”，除非明确其为特定分部估值假设下的残差及敏感性。不编造隐含成功概率。

若证据不足以构建可靠预测，继续核查授权范围内可得信息；确实无法补齐时给可复算的条件区间、已查来源、具体缺项和影响，不能用确定语气写“市场已计入某产品”，也不能将该估值项验收标为通过。上述要求适用于后续HTML报告，不追溯改写历史Markdown。

### 估值条件反推 Skill

完整公司研究及涉及估值的更新，做到现价反推时，先读取 [implied-valuation](../../../估值反推Skill/skills/implied-valuation/SKILL.md) 判断适用性。若以可比的完整年度正利润为基数，适合用未来PE反推，并且用户已确认目标财年、股数假设、必要回报率、目标PE及敏感性范围，须使用该Skill计算所需利润、增长率与兑现延迟的影响。未安装时可直接读取仓库中的Skill说明并运行其脚本。

- 研究任务中由Agent按证据纪律核对股价、利润和当前股数等事实输入。适用但假设未确认时，集中列出待确认项，继续其他已授权的研究和核验，记录反推尚未完成。亏损、利润不可比或未来PE模型不适用时，记录原因，按本节要求采用适用模型或说明缺口。
- 将核对后的假设、目标财年、所需利润、增速和延迟结果回写公司估值模块 HTML，已有单页报告则沿用估值章节。Skill自带的HTML可用于临时复核，复算输入和结果可保存在`factcheck/`下，报告正文按唯一主入口规则维护。
- 验收时另核对公开叙事及日期、具体业务的商业化节点、所需经营结果的可行性、倍数收缩和延迟的经营影响，并同步复核摘要、风险与跟踪指标。Skill的固定假设计算结果仅作为本节的量化证据。
