# 研究 SOP 模块化与 Skill 落地方案

日期：2026-11-16；状态：待用户审核。本轮仅只读盘点并创建本方案，未搬迁/删除规则、未修改现有 SOP、未创建或安装 skill。

## 1. 背景与目标

用户希望缩短研究 SOP，并将适合重复执行的部分 skill 化。此前已在 [2026-11-14方案](2026-11-14-微软报告结构与研究Skill调整方案.md) 第5节提出 `company-research` 与 `stock-valuation`，但当前相关规范仍注明未创建 skill，本机两个常用技能目录亦未检出对应技能。

现有四个核心文件：研究方式243行、主模板234行、验收清单127行、HTML规范152行，合计756行，另有AGENTS与入口/Git规范。行数是盘点快照，不是质量指标；问题在于同一要求在标准、模板、清单中重复展开，后续修订易遗漏，单次专题也容易读取过多无关内容。

目标：保留现有研究深度与用户偏好，把“规则是什么”“这次读什么”“怎样做并证明完成”分开；常规入口简短，细节按任务读取，规则只维护一处，执行仍有验收。

## 2. 范围与非目标

范围：AGENTS中的研究路由、研究方式、主模板、验收清单、HTML规范的去重与模块化；创建两项可发现 skill；更新被移动章节的有效引用；在真实任务类型上验证路由和输出约束。

非目标：不改公司研究事实/观点，不批量迁移历史Markdown，不实现HTML入口读取器，不安装十一个互相调用的skill，不建立强制多代理流程，不新增数据服务、网站部署或行情依赖，不将本次结构改造称为全库研究验收通过。

研究报告只维护HTML，内部规范继续用Markdown；不恢复机器Markdown正文底稿。

## 3. 现状分析与必须保留的约束

- 当前是九个阅读章节覆盖十一项研究问题，不能退回机械的十一章排版。
- 三完整财年、当年连续单季、同比/环比与TTM口径、异常解释及现金流勾稽均已形成硬要求。
- 最新实绩/指引前置、日期标签与文末口径、客户与订单合并、治理文化独立、收入图后现金用途、桑基优先及负值兜底等已有用户反馈必须保留。
- 估值必须反推现价隐含哪些预期、哪些具体兑现财年、所需业绩及延迟/不及预期影响，不能仅展示倍数。
- 取证/计算、章节/链接、浏览器视觉验收是不同维度；不能彼此替代。
- 现有研究入口仍受Markdown限制，应保留既有过渡事实，不为减少SOP长度隐去工具缺口。

## 4. 设计方案

### 4.1 三层结构

1. **短入口与共通底线**：AGENTS只留工作区边界、HTML唯一正文、证据与验收底线及SOP链接；研究方式保留任务路由、九章/十一项覆盖索引、关键约束摘要及模块链接。目标研究方式约80行内、AGENTS研究条款显著缩短；不以硬凑行数牺牲规则。
2. **按需标准模块**：仓库内 `研究流程/模块/` 保存详细规范，独立于某个个人技能安装环境。跨模块共用规则只放一处，其余引用。每个模块写适用条件、所需输入、内容/计算标准、验收条目、缺口处理；纯知识说明不伪装成自动化能力。
3. **两项执行 skill**：用简短步骤识别任务、读取必要模块、组织取证与计算、回写HTML及验收记录。skill引用标准，不复制长篇规则，也不把一句“必须深入”当执行机制。

### 4.2 模块划分与加载条件

| 模块建议路径（均位于研究流程/模块） | 内容归属 | 何时读取 |
|---|---|---|
| 证据与口径.md | 信息类别、期间/单位、来源、缺口分类、可追溯计算 | 每次实质研究的共通模块；短小，不塞满业务细则 |
| 业务与竞争.md | 商业模式、客户、订单、竞争、行业供需、护城河 | 任务涉及对应主题时按模块内标题定位；完整研究需覆盖 |
| 财务与资本分配.md | 三年/年内单季、利润率/ROE/FCF、债务、投入与回报、异常桥 | 完整研究、财报更新、财务追问；图表只有展示变化时不重复财务取数 |
| 估值与隐含预期.md | 估值基准、未来业绩→现值、具体兑现年份、情景与反证 | 完整研究及任何实质估值追问，由stock-valuation工作流消费 |
| 治理文化与判断.md | 控制权/激励/文化证据、核心矛盾、关键假设与风险跟踪 | 完整研究或治理/判断相关更新；摘要判断不免除证据 |
| 更新与迁移.md | 新财报联动、旧口径清理、重构解释保留、历史Markdown停更 | 财报更新、报告重构或局部转HTML时 |

HTML规范继续作为独立展示模块，内部按表格、选图、资金流、离线交付分节读取，不再重复完整研究标准。主模板成为精简的九章骨架、内容归属及模块链接，不再嵌入另一份SOP。

验收清单保留短的通用收口、适用模块勾选、记录格式；详细验收条件跟随各模块维护，清单链接过去，不逐字复制。完整研究默认所有必需模块适用；局部任务只限本次范围，但检查受影响的摘要、估值、风险与跟踪联动。

### 4.3 两项 skill 的职责

| Skill | 触发任务 | 执行产物与边界 |
|---|---|---|
| company-research | 完整公司研究、财报更新、业务/客户/治理专题、报告重构 | 明确模式和范围→定位公司与已有材料→读取共通及所需模块→取证/计算→更新HTML→按范围验收。轻量词义答疑不强制落整篇报告，不因一条新闻重做全库 |
| stock-valuation | 贵不贵、当前价格包含什么预期、未来几年如何兑现、估值情景 | 基准行情/财务→选择模型→列已知事实与未知假设→反推所需业绩和年份→折现与敏感性→判断/缺口→HTML及计算证据。不只拉行情算PE；不将反推当唯一市场共识 |

company-research遇到估值问题时读取stock-valuation的执行指导；不要求创建子代理或启动另一聊天。避免两个skill互相循环引用。先不把财务、客户、图表、验收分别安装成独立skill；高频独立使用且有明确输入/输出的模块，以后再提取。

### 4.4 存放、发现与维护

- 权威标准留仓库，不能只藏在本机个人skill中。skill缺失时，研究方式的路由仍足以指导读取和验收，不让最低标准依赖安装成功。
- 两项skill按skill-creator默认安装到 `~/.codex/skills/company-research/` 与 `~/.codex/skills/stock-valuation/`，默认允许正常自动发现，也可显式调用；不引入逐次审批。
- 为便于Git审阅，仓库内 `研究流程/技能源/` 保留两项skill的发布源。该目录明确标记为发布源，不声称其自身会自动被发现。部署为单向复制到安装目录；以仓库源为维护点，校验源与安装内容一致，禁止两处分别修订。
- SKILL.md按skill-creator约定带name/description，正文只含目的、范围、关键步骤和必要引用。通过当前工作区定位仓库模块，不把此机器的绝对路径写成通用规则；离开适用研究库时明确缺少标准，不静默套用其他项目。
- 本轮不新增泛化财务引擎或自动下载安装脚本；需要复算优先复用各公司已有factcheck脚本。新增脚本只用于确有复用价值的确定性工作。

## 5. 数据模型、API与流程变更

无财务数据模型、research.yaml schema或外部API变更；只重组说明与执行流程。HTML章节仍按九章阅读，证券身份和历史入口兼容状态不变。

新增执行方式：任务识别 → 共通底线与适用模块 → 取证/复算 → HTML回写 → 模块实质验收 → 通用交付记录。报告核验章节简记实际范围、加载/验收模块、证据与未通过项，不另建重复质量报告，也不要求向用户展示所有内部执行步骤。

完整研究需覆盖全部十一项问题；局部更新可缩小读取范围，但不得缩小其真实影响范围。例如新财报改变盈利预期时，不能只换财务表而遗漏估值与判断。

## 6. 旧条款迁移映射

| 原位置 | 迁移主位置 | 原文件保留内容 |
|---|---|---|
| 研究方式一/二/三 | 短入口＋更新与迁移模块＋精简模板 | 开工、模式路由、九章/十一项索引及关键底线 |
| 四：财务标准/异常；五：资本分配 | 财务与资本分配 | 标准摘要与有效链接 |
| 五：商业/客户/供需；六：护城河 | 业务与竞争 | 不复制详细标准 |
| 七：估值及预期兑现 | 估值与隐含预期 | 必答摘要及链接；AGENTS旧“第七节”定位同步修正 |
| 治理文化、核心矛盾、风险与判断 | 治理文化与判断 | 模板中的阅读位置与内容提示 |
| 八：来源/术语与更新 | 证据与口径＋更新与迁移 | 共通底线，不重复流程 |
| 九及执行清单中的详细检查 | 对应模块验收条目 | 短收口清单和主报告记录格式 |
| 十：Git；研究库项目规范 | 既有专门规范 | 链接，不再复述长段 |
| HTML规范、主模板内重复研究条件 | 对应标准模块 | 保留展示专属条件和骨架，不去掉非财务模块内容 |

实施时逐条建立“原文位置→新位置→保留/合并理由→反向引用”核对表，作为本方案实施验收附录；不能凭概括删掉用户明确追问过的解释规则。现有历史方案只作背景，不整体复制进每个模块。

## 7. 实现步骤

1. 基于实施时工作树重新盘点，保留同期改动；提取全部有效要求，标记重复与冲突，区分已确认规则和未批准历史提议。
2. 建立模块并迁移规则，精简研究方式、AGENTS、模板与清单；不在移动中改变内容门槛，不删除历史报告/原始证据。
3. 校验映射、引用、九章/十一项覆盖、HTML唯一正文及入口限制；检查是否仍需在多个文件同时修改同一条规则。
4. 创建两个skill发布源与必要UI元数据，验证后安装到默认目录；对既有同名skill先检查差异，不覆盖不明来源内容。
5. 按下述任务用例验证触发、模块选择、产物及缺口处理。允许使用已有材料/明确标注的测试输入，不为验证本架构虚构公司事实或改动公司正文。
6. 记录本轮实际验收结果与剩余限制，交付模块入口及skill路径；Git提交/推送按用户授权执行，不自动捎带同期公司改动。

## 8. 风险与控制

- **拆散后遗漏硬约束**：逐条映射，短入口保留重要底线与完整研究覆盖要求；局部任务同样检查联动。
- **总量增大或重复维护**：skill只写执行，模块拥有标准，模板只写阅读骨架，清单只作收口；不按十一项强拆十一项skill。
- **模块不被读取**：入口给任务→模块路由；skill描述窄而清晰，实际任务验证读取是否命中。安装成功不等于调用成功。
- **个人skill与仓库分叉**：仓库发布源单向安装并核对一致性；不复制整份模块到个人references中形成第二份规范。
- **历史链接/章节编号失效**：先搜调用方，更新引用并检查锚点；公开使用的老文件路径保留为短入口，不盲删。
- **越界实现**：本方案不授权公司事实更新、工具读取器升级、外部操作或强制多代理。不可把技能规范检验通过称为研究合格。

## 9. 验证方式与完成标准

结构：Markdown本地链接/标题锚点有效；旧规则迁移无丢项，九章与十一项对应明确；同一标准只有一个维护主位置；源与安装内容一致；运行skill-creator的quick_validate，并检查name/description边界和无占位内容。

行为抽检：

| 请求 | 应命中 | 应避免 |
|---|---|---|
| 首次完整公司研究 | company-research＋全部适用内容模块，包含估值与交付 | 用局部模式省掉季度/客户/治理等必答项 |
| 更新Q3财报 | 财务＋更新模块，并判断估值/风险联动 | 仅替换最新季度、遗漏Q1/Q2和旧TTM |
| 现价包含未来几年的预期 | stock-valuation＋证据/财务必要部分 | 加载所有客户/治理细则，或只算PE |
| 解释高毛利却亏损 | 财务异常规则及来源 | 只说分母小、误删异常值或重做整篇报告 |
| 改HTML图表排版 | HTML专属规则及信息保留检查 | 无故刷新无关行情；以视觉检查替代事实验收 |
| 核查治理文化 | 治理模块及证据 | 把技术能力或宣传语当文化/护城河事实 |
| 一条新闻/简单词义 | 限定范围及受影响部分 | 为调用skill强制完整报告 |

本轮不需执行全库公司研究。完成应能展示各任务如何选择模块及验证结果，分别说明结构验证和行为验证，不能仅交付一堆拆好的文件。

## 10. 回滚方案

记录本轮变更和skill安装前状态；按本轮差异恢复旧入口/模块引用及skill版本，不全库reset。新增模块/skill源在确认无调用后按本轮范围撤回，历史证据及公司报告不动。个人安装目录仅恢复本轮修改，不删除其他技能或用户资源。

## 11. 待确认问题

建议批准“两项skill＋仓库标准模块＋精简入口”，先完成本轮模块化而不改公司正文；模块独立skill化留待真实使用后决定。默认skill正常可发现，安装位置沿用skill-creator默认路径，仓库保留单向发布源。

本方案等待用户审核；确认后再迁移SOP和创建/安装skill。暂停在此是本轮先交付可审阅结构的工作安排，并非skill-creator额外要求逐次审批。
