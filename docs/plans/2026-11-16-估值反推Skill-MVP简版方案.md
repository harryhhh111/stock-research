# 估值反推 Skill：MVP 简版方案

日期：2026-11-16；实施更新：2026-11-17；状态：用户已批准，本地原型已完成，用户试用与付费验证待执行。本方案收缩[完整商业化方案](2026-11-16-投资研究Skill与MCP产品市场调研及商业化方案.md)的首发范围；完整方案保留为后续参考，不作为第一版开发清单。2026-11-17按用户明确批准实施；实际交付与验证见[原型核验记录](../../估值反推Skill/factcheck/核验记录.md)。

## 1. 背景与目标

首客为中文专业投资者与小型投研团队。第一版只验证一件事：**用户是否愿意为“现价要求未来赚多少钱、增长多快”的可复算分析付费。** 不先验证完整AI投研平台。

一句话产品：输入一组价格和业绩数据，选择目标年份、必要回报率和未来估值倍数，得到支撑现价所需的利润及增长率，以及延迟兑现的影响。

## 2. 范围与非目标

只做一个可本地运行的 Skill，附确定性计算脚本和一页HTML模板；一次分析一家公司、一个利润口径，输出一份结果。

不做MCP、独立网站、账号、订阅、后台数据库、自动行情/财报采集、九章完整研究、复杂行业模型、自动交易、多平台适配。无需把全部SOP先拆完，也不开发通用财务框架。

## 3. 现状分析

现有SOP已明确估值隐含预期、兑现财年、折现和证据要求，可抽取所需规则；已有研究报告和公司专项脚本可以提供参考，但不是已经可销售的通用工具。

第一版切出估值问题的一个计算环节，不声称单靠此模型就能识别真实市场共识，或说明某项新业务究竟被计价多少。

## 4. 设计方案：一个问题，一页结果

**用户提供/确认输入 → Skill解释口径并补问缺项 → 脚本计算 → 生成HTML。** 不要求用户填写几十个财务字段。

| 输入 | 说明 |
|---|---|
| 公司/股类、价格与日期 | 使用同币种，注明来源；用户提供值标为用户输入，未核实不能冒充已核事实 |
| 当前年度归属普通股股东净利润、期间及来源 | 用正值、可解释的同口径基数，不混GAAP与调整后利润 |
| 当前与目标年股数 | 明确ADS/普通股换算；目标股数可默认不变，但显著标假设 |
| 目标财年、距基准日年数n | 明确财年末及计时口径，不只写“几年后” |
| 必要年化回报率r、目标年PE | 都是用户/研究者假设，不是市场事实；默认值如有采用，须用户确认 |

HTML只展示四块：

1. **直接答案**：在所列假设下，到目标财年需要多少净利润、相对当前需要多快的增长。
2. **路径对照**：原定年份、延迟一年、延迟两年；说明延迟后仍要维持同一年化回报率时，所需利润如何变化。
3. **小型敏感性表**：目标PE × 兑现年份，展示所需利润/增长，不做复杂仪表盘。
4. **输入、公式与限制**：来源、核验状态、币种/期间、假设及缺口常驻可见。图表有帮助时再加，首版表格足够。

不能从此直接断言“市场已计入AGI CPU”；只能回答哪些盈利条件能支撑现价。业务归因需要另外的业务证据与模型，不纳入首版承诺。

## 5. 数据模型、计算及流程变更

无外部API或研究入口schema变更。一个本地输入对象保存上述字段及来源/状态，一份结构化结果同时驱动HTML；不生成Markdown报告副本。Skill及内部规则继续用Markdown。

简化模型假设期间无现金分配，采用目标年股权PE法：

- 目标年所需股价＝当前股价 × (1＋r)^n。
- 所需净利润＝目标年所需股价 × 目标年股数 ÷ 目标年PE。
- 利润年复合增长率＝(所需净利润 ÷ 当前年度净利润)^(1/n) − 1。

这是满足指定年化回报率的条件反推，不是完整DCF或真实定价结论。分红对总回报的影响未建模，回购/增发仅通过目标股数假设反映；重大资本结构变化、亏损、特殊行业或不可比利润不强套模型，明确不适用，不自动补造预测。延迟情景保持其他假设不变，是简化对照，不冒充包含费用与竞争变化的经营预测。

## 6. 实现步骤与投入

建议批准后用7—10个工作日试做，创始人负责研究口径和用户反馈，一名工程人员全职或部分时间协助；不按上一版26—35万元启动完整团队。

1. 用1—2天固定输入、公式、适用范围和HTML样稿。
2. 用3—4天完成一个Skill、计算脚本、错误提示和一页HTML输出。
3. 用余下时间验证算例，并让5名目标用户在其现有支持Skill的工具里试用；先支持他们实际使用最多的一个宿主。

首轮设预算上限1—3万元作为讨论假设，主要用于短期工程协助与必要外部边界核查；非报价或已批准采购。若适用授权/业务意见成本超过此限，先缩小测试或重新审核，不跳过必要核查。

## 7. 验证方式与成功标准

计算对照手算/表格，覆盖目标年股数变化、零/负利润、不合法PE/年数、币种不一致及延迟情景。HTML离线可打开、精确值/来源可读，不依赖网络或悬停。

5名目标用户中至少3名能在约10分钟内完成一次有效分析；至少2名对自己的第二个标的主动再次使用。记录他们此前怎样做、节省多少返工，而非只听“看起来不错”。

产品及收费边界确认后，以99—299元的一次性试点包检验实际付费，具体交付和支持范围先说清；首轮目标是至少2名实际付费用户，不以口头意愿或免费安装量代替。该价格是实验假设，不是已有市场结论。

只选择一个能满足发布/结算条件的渠道做实验；可优先核查Capafy是否接受此形态和经营主体，不把上架/收款资格当已获批。平台条款依据完整商业方案，实际提交前复核；没有合适结算路径也不先建设支付系统。

## 8. 风险点

- 简单模型可能过于容易替代：用复用和付费验证；若用户只需一次免费计算，不急着扩展为平台。
- 假设主导答案：每次明确“给定这些假设”，不伪装成市场共识或买卖建议；不适用时停止计算。
- 使用客户数据不等于自动有商用处理权限；用户输入仍需来源/权限边界。对具体证券的收费分析是否涉及许可要求，须在对外收费前按经营主体与客户法域确认。减小MVP不等于豁免业务边界。

## 9. 回滚方案

独立发布源实施，不改公司报告和原始证据、不删除历史Markdown。若验证不成立，停在本地原型，撤回本轮新包及未交付收费，保留用户反馈；不继续搭MCP或账户系统。

## 10. 待确认问题

建议只批准这个单一Skill的原型范围；预算、收费/发布及外部动作按具体边界确认。复用和付费成立后再讨论自动取数、财报更新或MCP，一次只加一个能力。

本简版方案已于2026-11-17获用户批准；本地原型已实施，剩余试用与商业验证按核验记录执行。
