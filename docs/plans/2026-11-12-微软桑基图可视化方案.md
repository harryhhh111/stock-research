# 微软收入与现金桑基图可视化方案

方案日期：2026-11-12。状态：待用户审核；本轮只读分析并编写方案，未修改现有HTML、生成器或研究结论。

## 背景与目标

用户希望参考Blockworks Hyperliquid Financials，以“从哪里收钱、流向哪里”的连续带状流图理解微软，而不是主要依靠柱状图或现金余额瀑布图。目标是让读者沿资金/会计形成路径阅读，节点金额、带宽和精确底表可以互相核对。

参考：[Blockworks Hyperliquid Financials](https://app.blockworks.com/projects/hyperliquid/analytics/hyperliquid-financials)。本轮网页文本可取得指标定义，但动态桑基图未通过视觉读取；布局建议依据用户确认的图形偏好及库中2026-09-30保存的收入流向原始数据，不声称已经复刻当前网站的样式。

## 范围与非目标

- 改造现有`MSFT/传统软件与现金流.html`测试页，形成两张主桑基图及一张不按金额编码的业务收费示意图；维持离线HTML。
- 保留可展开/默认可读的精确底表、来源、口径说明与生成式机器底稿。
- 非目标：重做公司完整研究、刷新到最新行情、模拟传统软件独立现金流、部署网站、复制Blockworks私有代码、推定每笔软件收入被用于哪座数据中心。

## 现状分析

现有测试页已有现金桥与年度CFO/CapEx/FCF柱状图，计算可勾稽，但连续路径不够突出。用户关心的业务来源和现金用途被分散成不同表格，视觉无法一眼串起。

披露限制决定不能直接画“Windows/SQL Server现金收入→研发/AI投入”：年度产品收入部分混合传统许可与云服务，财报又未披露这些业务的完整独立现金流。收入不是收款，利润不是可自由分配现金。

## 设计方案

### 主图A：收入如何形成经营利润

标题：**微软卖了什么，这些收入留下多少经营利润？**

采用从左到右的四列桑基图：

`产品收入 → 集团收入 → 营业成本 / 毛利 → 研发 / 销售 / 管理 / 经营利润`

- 默认FY2026，左侧按财报已披露产品类别展示；Windows与设备、M365商业产品与云服务、服务器产品与云服务等沿用原名。小额项可默认合组，展开时保持同一比例和勾稽。
- 不把“服务器产品与云服务”改名成SQL Server，不把M365合计收入称为传统Office许可，也不称其为传统软件现金收入。
- 集团收入331.839分为营业成本106.374、毛利225.465；毛利分为研发35.562、销售26.710、管理7.956和经营利润155.237。上述数据需在实施时补入有出处的结构化输入，逐节点守恒。
- 暂停在经营利润，不延伸到净利润、分红和CapEx；这些项目属于不同会计层次。若未来扩到净利润，需单独引入其他收益、税项，而非从经营利润直接减现金分配。
- 文字提示常驻图下：这是会计收入/费用关系，不是银行现金流；公共节点后的路径不能反推出具体业务成本或利润。

### 主图B：集团可用现金如何留存和使用

标题：**经营产生的现金，如何被投入和股东回报吸收？**

采用三列桑基图：

`期初现金 + 经营现金净流入 → 本图现金来源合计 → 投资净流出 / 融资净流出 / 汇率减少 / 期末现金`

默认FY2026，单位B美元：

| 来源 | 金额 | 去向 | 金额 |
|---|---:|---|---:|
| 期初现金 | 30.242 | 投资净流出 | 139.500 |
| CFO（已扣经营付款） | 182.935 | 融资净流出 | 52.546 |
|  |  | 汇率减少（非付款） | 0.196 |
|  |  | 期末现金留存（非费用） | 20.935 |
| 合计 | 213.177 | 合计 | 213.177 |

投资净流出可展开为现金固定资产投入115.948和其他投资净流出23.552；后者是139.500－115.948，包含证券买卖、收购及其他净额，必须称“其他投资净流出”，不称AI投入或股权投资。

融资净流出可展开：现金分红26.445、现金流表回购22.271、偿债3.000、剩余融资净流出0.830。残差来自52.546－26.445－22.271－3.000，需与原表发股流入及其他融资净额核对。融资租赁本金若包含在剩余科目中，不再另加扣一次。

本图明确采用净流量观察，不称“全部现金总收入和总付款”。期初余额不是当年赚的钱，期末留存不是支出，汇率不是付款。CFO中已扣的工资、研发现金付款等不再扣；非现金折旧、未起租承诺、回购授权不画成本期资金流。

### 辅图C：第一层的客户—产品—收费链路

用等宽箭头示意（明确不按金额）：

- PC厂商→Windows OEM许可；
- 企业IT→Windows商业/Windows Server/SQL Server许可；
- 企业与个人→Office/M365本地许可或订阅服务；
- 云资源和AI应用单独标记，指向既有AI专题。

这张图回答“谁付钱、买什么”，不假装取得产品级收款金额。主图A/B均为集团披露口径，用于第一层的上下文，不能把本页标题或摘要改写为传统软件独立资金流研究完成。

### 视觉与交互

- 横向大画布、细节点、柔和半透明曲线；金额决定带宽，图中固定显示名称与金额。沿用清晰浅底，适合研究阅读和打印。
- 收入来源固定业务色，经营利润/经营现金用绿色，成本和资金净流出用低饱和暖色，余额及汇率用中性色；正负和非现金性质同时用文字表达。
- 悬停或键盘聚焦高亮相邻路径，展示金额、分母占比和来源；核心信息无需悬停。
- 默认主图A与B同时显示，不用切换隐藏两种口径。图内年度选择后重算整图和表格；无脚本时默认FY2026完整静态图及三年底表保留。
- FY2024—FY2026年度趋势保留为次级图，不抢主图；单季另列，不能与年度混成连续期间。第一版不为凑季度选择器补造缺失数据。
- 窄屏以图容器横向滚动配合完整标签/底表，不能把带宽挤成无法阅读的细线；打印输出全部关键图表及来源。
- 很小流量保持真实带宽，通过外置标签、引导线和明细表补充，不设虚假最小流量宽度。

## 数据模型、生成与流程变更

- 扩展现有核验输入，补充来源日期、附注位置、期间类型、金额单位、实际/复算、公式、缺失状态，不改写已有原始文件。
- 图形数据明确`basis`（收入费用/现金净流量/非定量示意）；节点与边记录原始指标键及来源，数据不跨basis自动连线。
- 带宽、标签、比例、表格和摘要均由同一数值生成。派生残差记录输入和公式，不能按美观手调。
- 沿用`MSFT/factcheck/build_cash_view.py`生成离线HTML与同源Markdown机器底稿，核心图形采用内嵌SVG；如使用布局库，只负责排布，最终静态SVG必须离线可见。
- 不变更入口schema。research.yaml继续定位真实Markdown底稿，阅读链接指向HTML；无外部API或服务变更。

## 风险与验证方式

- 风险：图形暗示收入等于现金，或传统软件直接资助AI。验证：两张图标题和basis明确分开，不跨图连线。
- 风险：净流量被误当总付款。验证：名称保留“净”，可展开残差公式；亏损/净流入期间须调整节点方向，不能取绝对值凑守恒。
- 风险：业务拆分、成本分摊和小项造成错误精度。验证：原始表加总、所有中间节点入出一致；产品级未知成本不得按收入比例分摊为事实。
- 风险：图漂亮但不可读。验证：逐个检查标签遮挡、颜色对比、比例、数字、来源、零/负/缺失状态；默认静态内容完整，打印不截断。
- 验收分开记录：财务勾稽、同源生成、入口结构、浏览器视觉实测；前几项不能替代最后一项。
