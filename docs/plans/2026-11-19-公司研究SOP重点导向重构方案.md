# 公司研究 SOP 重点导向重构方案

日期 2026-11-19。首轮 SOP、模板、验收与接入约定已更新，实际报告试读待开展。

## 1. 背景与目标

现行公司报告要覆盖十一项问题，并按九个固定章节展开。读者即使拿到一份材料齐全的报告，也可能需要跨几个章节才能拼出公司最重要的判断。QXO 的案例说明了这一点：主体变化、收购、融资和治理分别有记录，仍需串成一条能回答普通股股东如何获得回报的证据链。

这次重构有两个目标。研究时先看行业与业务模式，找出最可能影响判断的问题，再决定取证深度。交付时，读者能从开头看懂公司靠什么赚钱、为什么值得研究、我们目前怎么判断，以及什么证据会改变判断。

## 2. 范围与非目标

- 调整公司研究的开工顺序、模块权威来源、HTML 阅读结构和交付验收。完整研究、主报告迁移与局部更新各有适用范围。
- 沿用每家公司唯一 HTML 主入口，首页以大卡片打开独立模块页。完整研究仍按十一项要求核查，底表、模型和证据放各自模块。适用的三完整财年、年内单季、可比期及复算标准继续执行。
- 本次范围限于研究组织和阅读体验。全库报告迁移、行情与数据接口重建、新增 Skill 或 MCP 单独处理。已有营收、现金流和估值 Skill 继续作为对应模块的执行工具。

## 4. 设计方案

### 4.1 研究怎么做

1. **先确认研究对象和原任务。** 明确上市主体、业务边界、既有报告和本次范围。用户要求迁移主报告时，开工盘点旧报告有价值的证据和解释。
2. **先看行业。** 问客户为何花钱、产业链哪一段有议价权、供需或竞争正在变什么。限定到足以解释公司的业务和回报。多业务公司先找各主要业务所在的子行业，再判断哪条链最影响集团结果。
3. **再看业务模式。** 用一笔代表性生意解释谁付钱、为什么选它、如何收费、如何交付、何时确认收入和收到现金、需要先投入多少。区分公司表现和行业共同变化。
4. **选一个主问题。** 从用户追问、与同行的差异或证据中的重大异常出发，明确这个问题为什么会改变判断。列两三个需要验证的事实及可能推翻判断的证据。碰到控制权变化、跨行业转型或小主体收购大资产，追查主体沿革、交易资金、权利变化与每股结果。保留用户指定的重点，新证据使主问题改变时记录原因及受影响模块。
5. **分模块取证并验收，再汇总判断。** 每个模块说明适用场景、应查证据、写入位置和通过条件。脚本负责期间覆盖与复算，原始披露和经营推导由研究者核验。关键缺口仍存在时，主线明确写出当前能下的结论和结论边界。

### 4.2 规则怎么拆

建议将详细标准放在 `研究流程/standards/modules/`，按阅读需要逐块迁移。下表是规则归属，完整研究按适用性覆盖，单篇正文由主问题决定篇幅。

| 模块 | 负责的判断或证据 | 对应现有要求 |
|---|---|---|
| 行业与竞争 | 产业链、利润来源、供需、同业差异和行业周期 | 行业景气、竞争对手、行业对护城河的约束 |
| 公司业务模式 | 付费方、交易与交付、客户及订单、业务级护城河 | 业务、客户、订单承诺、护城河 |
| 营收与盈利质量 | 集团和分部、期间覆盖、增长贡献、异常利润 | 营收、盈利，调用现有营收 Skill |
| 现金、融资与资本配置 | 现金桥、投入与回款、债务、融资稀释、并购与股东回报 | 负债现金流、资本分配和资金效率，调用现有现金流 Skill |
| 主体沿革与治理 | 控制权、管理层激励、关联关系、重大转型与交易 | 治理文化及相关异常。识别到触发条件时在开工阶段优先调查 |
| 估值、反证与判断 | 现价包含的业务预期、兑现财年、所需结果、延迟与反证 | 估值、核心矛盾、风险与跟踪，适用时调用现有估值反推 Skill |

迁移时逐条记录原位置、目标位置及验收点。报告模板负责阅读结构和证据定位，HTML 规范负责图表与显示，交付清单负责收口。每项详细标准由一个位置维护。

### 4.3 报告怎么写

- **首页**保留公司名称、日期、一句话判断和最值得追问的问题。首屏直接展示模块大卡片。每张卡片写模块名、它要回答的问题和一句关键发现或最大缺口，可用一个关键指标辅助。卡片顺序沿模板固定，行业第一，业务第二。当前最能改变判断的问题在摘要突出。
- **模块页**使用独立 HTML 和稳定路径，每张卡片直达一个页面。页面开头回答本模块的问题，随后给关键证据、图表、精确底表、口径和本模块验收记录。页内提供返回首页及相关模块链接，一次研究中的证据链可跨页追踪。
- **模块可单独优化。** 修改模块时只动对应页面及必要证据，若改变公司判断或其他模块输入，就同步更新首页摘要、相关估值或跟踪条件。保留既有有效锚点或提供明确的旧位置到新页面映射。全篇覆盖及跨模块验收仍从首页可查。

以 QXO 为试读题，主问题可以是「买来的业务扣除收购与融资成本后，能否提高普通股股东的每股现金流」。主线顺序可用「建材分销的整合逻辑 → 上市主体如何转型并融资 → 并购经营现金与股东分配 → 什么表现能支持或推翻判断」。当出现关键资料缺口，主报告明确结论目前只能到哪里。该例用于验证阅读结构。

## 5. 数据模型、接口与流程变更

- 主报告开工记录几项必要信息：任务类型、主体及证券、主问题、关键验证点、本轮范围、需保留的历史证据。利用现有核验记录。交付沿用同一范围对照正文和附录。
- 维持 HTML 索引字段和现有 `research.yaml` 接口。首页沿用 `company_research`，独立模块按现有 `topic` 规则登记并共享同一个公司 `entity_id`，网站公司列表只显示首页。模块链接用相对路径，支持离线浏览。营收和现金流底表移动后保留稳定表格定位与期间标签，交付在最终模块页运行原有检查并验证所需的路径调整。
- 验收分两层。第一层问主问题有没有答案、证据和反证，核心缺口是否说明影响。第二层对照完整覆盖或本轮影响范围，核对财务、图表、HTML、索引及来源。关键研究项未通过时，按实际状态交付阶段成果。

## 6. 实现步骤

1. 用 QXO 现有报告做卡片顺序和旧内容映射。先试读首页和「现金、融资与资本配置」模块，验证读者能否直达研究重点及证据。
2. 将 `研究方式.md` 改为短入口，先落实「行业 → 业务模式 → 选主问题」。先抽取这两个模块的详细规则，其他规则按映射逐步迁移，迁移期间保留可查的现行条款。
3. 一起更新 `AGENTS.md`、报告模板、展示规范和交付清单，消除固定九章与主线写法之间的冲突。保留原有取数、图表和证据标准。
4. 在首个试点或下一次适用研究中验证 HTML 和已接入的三个 Skill。通过后按模块逐次迁移剩余规则。

## 7. 风险与处理

- **报告短了，证据找不到。** 每条关键结论附证据位置，保留已核底表、来源和用户明确追问的问题。旧锚点逐一对照。
- **先选角度后只找支持材料。** 开工同时列出反方解释和证伪条件。主问题随证据修正，记录理由。
- **行业研究变成百科。** 每段行业背景落到一个会影响公司判断的问题，行业资料按这一需要取舍。
- **拆文档把规则复制多遍。** 迁移后入口和清单只保留足以导航及收口的条款。每次迁移复查旧条款去向与引用。
- **缩短正文造成脚本漏检。** 在最终 HTML 上重跑相关检查，对照附录表格与图表。表的位置变化不能减少期间或降低口径标准。

## 8. 验证方式

| 用例 | 通过条件 |
|---|---|
| QXO 试读 | 开头能复述业务如何赚钱、核心疑问、主要证据和未决事项。正文能顺着资金、控制权、收购及每股回报读完一条主线 |
| 独立更新 | 只更新一张卡片对应的模块后，卡片、模块路径和直接引用仍有效。会改变判断的更新同步到首页及受影响模块 |
| 完整研究覆盖 | 十一项都能从首页定位到模块页，三完整财年和年内单季等底表仍可检查。关键项缺失时验收能指出具体证据缺口 |
| 现有报告调整 | 重要解释、日期、锚点、单位和引用可定位。图表和精确表同源，现有 Skill 与索引检查仍可执行 |
| 局部更新 | 按用户范围更新，覆盖实际影响到的摘要、数据、估值和跟踪项。核验时能辨别局部更新与完整主报告迁移 |

## 9. 回滚方案

将文档迁移和试点报告分别提交。若试读变差、旧证据难找或现有检查失效，回退对应模板及规则迁移，按原九章与现有交付清单继续执行。已有数据、报告索引、已装 Skill 和原始证据可独立使用。修复后重做试点再推广。

## 10. 待确认问题

- 建议完整研究采用「大卡片首页＋独立模块页」，十一项仍作为研究覆盖要求。首个试读优先验证首页和一个核心模块，再扩展其他模块。
- 建议以 QXO 为首个试读样本，先迁移行业与业务模式规则，再按实际使用效果迁移其余模块。

首轮验证使用临时样本，登记公司首页、营收模块、现金模块、行业首页及行业模块。双向相对链接、跨项目锚点、营收覆盖和现金桥通过。既有公司报告的改版另行按试点范围执行。
