# 研究库整理计划

整理日期：2026-10-14。状态：四项目版本 1 入口试点已获批准并完成；market 字段版本 2 修订已于 2026-10-15 获批准并完成四入口与校验器迁移，stock_data 读取端尚未改造。试点结果见 [四项目验证结果](../../研究流程/2026-10-14-研究入口四项目验证结果.md)。

配套文件：[研究库项目规范草案](2026-10-14-研究库项目规范草案.md)。

## 1. 背景与目标

研究库已有公司研究、行业主题、个人判断、计算脚本和证据，但目录名不能可靠表达主体身份，文件排序不能确定主研究。目标是保留研究资产，为机器建立稳定的身份、文档与章节入口，让人和看板读到同一份可追溯研究。

成功标准：证券能定位唯一研究主体及主文档；主题能关联多家公司；关键观点可以完整定位；缺失或冲突显式报告；研究存在不触发关注池或交易建议。

## 2. 范围与非目标

范围：当前库盘点、身份与入口规范、四个样本试点、入口校验、逐批扩展、相关链接治理，以及 stock_data 读取契约的设计和后续对接。

非目标：全库搬迁、自动合并或删除旧文档、统一重写历史研究、自动生成或覆盖研究判断、自动加入关注池、修改行情系统、提交或推送现有工作区改动。stock_data 的代码改造需在其工作区核对规范和实现后开展。

## 3. 现状分析

依据：2026-10-14 本地文件列表、现行 AGENTS.md、研究方式.md、Git 管理说明及四份样本文档标题；本轮未检查 stock_data 源码，也未重做研究数据核验。

|---|---|---|

| NBIS | `Nebius公司研究/Nebius深度研究报告.md`，含核心结论、风险矩阵、监测框架 | 保留中文目录，关联 NBIS 身份并映射现有标题 |
| INTC | `INTC/INTC.md`，已含 `7. 我的看法` | 以当前主文档为准，不恢复旧独立文件 |

已有嵌套公司目录，如 `SSD/SNDK/`、`数据中心/矿场/CORZ/`，证明入口发现需要递归。现有库还包括非上市公司、数字资产和方法笔记，不能全部强套股票身份。

Git 工作区已有修改、删除、重命名及未跟踪文件；整理不能把这些状态当作本轮造成，也不能顺带回滚、暂存或提交。历史的“116 份 Markdown”不作为当前盘点基线。

## 4. 设计方案

每个明确主体或主题维护一个 `research.yaml`，位置跟随现有研究目录。文件仅维护身份、文档路径、关联和章节定位；正文是研究结论的唯一来源。全局索引由入口生成，不手工维护第二套结论。

主体 ID 与证券分离。公司支持多个上市证券；主题独立建档；非上市公司证券列表为空。数字资产区分协议、代币与运营主体，不自动映射为公司。详细字段与规则见配套规范草案。

现有章节先映射，缺失项报告缺口；新增完整研究采用统一摘要章节。不能因为有了入口就宣布历史研究达到 SOP 标准。

## 5. 数据模型、读取接口与流程变更

入口模型：`schema_version`、稳定 `entity_id`、`kind`、名称/别名、证券列表（版本 2 每项必填 market、mic、symbol）、唯一 `primary_document`、辅助文档、`related_entities`、语义章节定位。

读取契约：证券市场及代码 → 唯一主体 → 主研究和关键章节；主题 ID → 主题研究及关联主体。返回源路径、读取版本、缺失项与截断状态。字段的最终接口形式在 stock_data 实现核对后确定，不在本轮假定已有 HTTP API。

主文档流程：新增证据 → 留存来源与核验 → 研究员判断 → 更新正文 → 检查入口 → 消费端读取明确版本。消费端不反向改写观点。

## 6. 实现步骤与阶段验收

| 阶段 | 工作与交付 | 完成条件 |
|---|---|---|
| 0 审核 | 审核本计划及规范草案 | 用户明确批准后才开始实现 |
| 1 盘点 | 在研究流程目录建立当前文件清单，记录主体、主文档候选、判断位置、缺口、旧链接 | 使用当前工作树；歧义列出，不按排序猜测 |
| 2 四样本 | 为 ORCL、NBIS、INTC、NAND 增加入口；仅做必要的正文链接补充 | 四个身份与主文档人工确认，现有目录及证据保留 |
| 3 校验 | 建立可重复运行的入口与链接校验，输出错误和内容缺口 | ID/证券唯一、文件存在、章节可定位、主题关联可解析 |
| 4 读取对接 | 核对 stock_data，替换猜目录/取首篇的行为，按章节读取并展示来源版本 | 四样本端到端通过；未知、歧义、缺失和截断均有提示 |
| 5 分批扩展 | 先现有公司，再嵌套公司、主题、非上市与数字资产；批次清单逐项审核 | 每个纳入对象入口有效；未纳入对象可见，不冒充全库完成 |
| 6 持续维护 | 经批准将组织规则接入 AGENTS.md；研究质量仍引用研究方式.md | 新建/更新研究遵循统一入口与检查 |

不预设所有研究必须整改正文。每批先确认入口，再按使用需求修复链接或补充摘要；移动和合并单独列清单批准。

## 7. 风险与处理

- 主体混淆：集团、子公司、上市证券、协议和代币分开建模；别名只辅助搜索。
- 章节变动：校验定位唯一性；找不到时报告，不回退为正文开头冒充观点。
- 重复身份：校验整个仓库，冲突阻断该主体导入。
- 内容过时：显示研究日期与分项数据截止日；入口创建日期不等于研究更新日期。
- 工作树与 Git 版本不一致：消费提交版本必须来自该提交；本地预览明确标识工作树，不能标成干净提交。
- 规范重复：项目组织规范不复制十一项研究标准，避免与研究方式.md 分叉。

## 8. 验证方式

正向：ORCL 读到末段判断；NBIS 通过证券定位中文目录；INTC 读到主文档判断；NAND 按主题定位并关联多个主体；嵌套目录可发现。

反向：重复 ID/证券、无效路径、越界路径、重复标题、缺失章节、未知版本、无研究的证券均有明确状态；未知 schema 版本拒绝加载。测试使用临时样本，不改原始研究证据。

回归：校验关注池和交易判断没有因入口导入而变化；主文档与附件链接有效；本轮差异不包含历史改动或原始数据删除。

## 9. 回滚方案

新增入口与校验工具按独立变更管理，失败可撤销对应新增项。消费端保留上一可用版本，切回时标明旧读取方式的限制，不能静默返回错误研究。正文链接修改保留逐文件差异，按本轮变更撤销，不使用全库重置。任何移动前记录原路径与引用清单；本计划默认不移动文件、不删除证据。
