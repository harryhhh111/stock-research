# 研究库项目规范草案

整理日期：2026-10-14。状态：待审核，批准并接入工作区规范后生效；不替代现行 AGENTS.md。

配套文件：[研究库整理计划](2026-10-14-研究库整理计划.md)。

## 1. 背景、目标与适用范围

本规范解决研究资产的身份、入口、关联、更新及机器读取问题。适用于公司、非上市企业、行业主题及明确区分的数字资产研究。后续维护以正式版 [研究库项目规范](../../研究流程/研究库项目规范.md) 为组织入口。研究内容的深度、数据口径与交付标准以 [研究方式.md](../../研究方式.md) 为唯一入口；数据与 Git 边界遵循 [AGENTS.md](../../AGENTS.md) 与 [Git 管理说明](../../研究流程/2026-10-08-Git管理说明.md)。

非目标：统一所有旧目录名称、用索引替代正文、把研究状态当投资建议、强制合并历史笔记或自动化修改观点。

## 2. 现状与兼容原则

现有库同时存在代码目录、中文目录、嵌套公司、多篇研究和独立“我的看法”。保留现有路径和有价值证据，以显式入口兼容；新规范不使旧文档自动达标。对原规范的新增扩展为：允许 `research.yaml`、新材料 `updates/`、跨项目方案 `docs/plans/`；现有 research/、动态/、归档/ 不自动迁移。

## 3. 目录与文件

- 每个研究主体或主题一个明确入口，可在现有嵌套目录中。
- 根目录保留跨项目规则与资料；公司研究、数据、脚本和附件进入所属项目目录。
- 每个入口只有一个主文档。专题、独立判断、历史复盘与来源均通过链接关联，不能根据文件名排序选主文档。
- 新材料可放 `updates/YYYY-MM-DD-主题.md`；记录发生日、来源公开日、核对日及对假设的影响，研究员确认后再回写主文档。
- 核验使用 `factcheck/`，原始数据放 `factcheck/data/`，原始文件保留不改。脚本从自身位置推导路径。
- 图表附件保存在项目内，名称包含日期或主题。归档不改变其历史观点性质。
- 仓库内 Markdown 链接相对当前文档；入口中的路径相对入口所在目录。外部来源使用完整 URL；不得新增机器专用绝对路径。

## 4. 身份与入口数据模型

### 4.1 身份规则

`entity_id` 全库唯一、创建后稳定，使用 ASCII 小写。例如 `company:oracle`、`company:nebius`、`company:intel`、`topic:nand`。改名不换 ID；合并、分拆与退市须人工处理，不复用旧 ID。`kind` 允许 `company`、`topic`、`protocol`、`token`、`other`；协议与代币分开建档并显式关联。

每项股票证券必须显式填写 `market`、`mic`、`symbol` 三个字符串。`market` 表示上市交易市场分类，`mic` 表示交易所，`symbol` 表示该交易所的证券代码。证券仍以 `mic + symbol` 唯一标识，代码不丢失前导零；增加 market 不改变证券身份。market 不表示公司注册地、收入来源或交易币种。公司证券列表允许为空或多项；主题、协议和代币不得填股票证券。代币需要时另增经过审核的链/合约身份字段，不能仅用同名 ticker 匹配。

同一证券只能映射一个主体；不同股类或多地上市作为不同证券。母子公司分别建主体，不能共享同一主研究身份。别名只用于检索，不能替代 ID 或证券唯一匹配。

### 4.2 市场与交易所规则

市场枚举采用 `US`（美股）、`HK`（港股）、`CN`（中国内地股票市场）、`JP`（日本）、`KR`（韩国）、`DE`（德国）、`CA`（加拿大）、`TW`（台湾）、`IN`（印度）、`FR`（法国）、`AU`（澳大利亚）、`IT`（意大利）。A 股归入 CN；不得将 A、SH、SZ、NASDAQ 等混作 market 值。其他市场须先补充规范及映射，再纳入正式入口，不临时自由填写。

`mic` 优先使用具体股票交易所的 MIC，不强制全部使用运营 MIC。日本的 XTKS 是东京证券交易所分段 MIC，其运营 MIC 为 XJPX；为避免混淆集团内不同场所，日股使用 XTKS。允许组合如下，新增交易所须显式扩展映射，不靠四字符格式判断有效：

| market | 允许的 mic | 含义 |
|---|---|---|
| US | XNYS、XNAS | 纽约证券交易所、纳斯达克 |
| HK | XHKG | 香港交易所证券市场 |
| CN | XSHG、XSHE、XBSE | 上海、深圳、北京证券交易所 |
| JP | XTKS | 东京证券交易所（运营 MIC 为 XJPX） |
| KR | XKRX | 韩国交易所股票市场 |
| DE | XETR、XFRA | Xetra、法兰克福证券交易所 |
| CA | XTSE | 多伦多证券交易所 |
| TW | XTAI | 台湾证券交易所 |
| IN | XNSE、XBOM | 印度国家证券交易所、孟买证券交易所 |
| FR | XPAR | 巴黎泛欧证券交易所 |
| AU | XASX | 澳大利亚证券交易所 |
| IT | XMIL | 意大利米兰证券交易所 |

上表是项目初始支持范围，不是全部交易场所清单。正式接入前核对 ISO 10383 官方 MIC 名录及证券上市资料；未支持组合必须报错，不能自动归入近似交易所。

证券代码按对应市场的上市代码规范化后保存为字符串，保留前导零、股类及必要标点；行情供应商的后缀或专有代码由适配层转换，不直接写入通用 symbol。币种需要时单独扩展，不能由 market 强行推断。

多地上市按证券逐项填写市场；非上市公司与主题仍用空证券列表，不能填写猜测市场。消费端收到 `market + symbol` 时，只在该市场内匹配：无匹配返回未建档，多条匹配返回歧义并要求 mic，不按排序选取。

### 4.3 字段约定

| 字段 | 要求与含义 |
|---|---|
| schema_version | 必填整数；本次市场字段修订为 2，旧试点版本为 1 |
| entity_id / kind / name | 必填，稳定身份、对象类型、展示名 |
| aliases | 可选字符串列表，旧名、中文名等 |
| securities | 必填列表；每项必须包含 market、mic、symbol；无证券用空列表 |
| primary_document | 必填路径，唯一主研究 |
| primary_section | 可选，必填 heading_path，可加 table_row（表格第一列的原文完整文字）；限定共享文档中的公司章节或公司行。未填写表示整篇主文档 |
| research_scope | 可选非空字符串，说明仅业务专题、首轮核验或共用底稿等研究边界；不是复制研究结论 |
| documents | 必填列表，可为空；元素为 path、role；role 为 supplement、opinion、review、source |
| related_entities | 必填列表，可为空；元素为 entity_id、relation；relation 为 theme、related、parent、subsidiary、underlying |
| sections | 必填映射；固定语义键定位正文，不复制观点内容 |

`sections` 的语义键为 `thesis`、`open_questions`、`metrics`、`risks`、`research_metadata`。每项为 `{path, heading_path}` 或 `null`；null 表示未建立该部分。路径必须指向主文档或已声明的辅助文档。`heading_path` 是从最外层实际祖先标题到目标标题的字符串数组，去掉 Markdown 的 # 标记，保留编号和标题文字。标题定位须唯一；提取到下一个同级或更高级标题之前。不依赖不同网页引擎生成的锚点规则。

入口示意（不是本轮创建的正式 ORCL 入口；未核验的章节置空）：

```yaml
schema_version: 2
entity_id: company:oracle
kind: company
name: Oracle
aliases: [ORCL, 甲骨文]
securities:
  - market: US
    mic: XNYS
    symbol: ORCL
primary_document: ORCL.md
documents:
  - path: 股价复盘-2024-2026.md
    role: review
related_entities: []
sections:
  thesis:
    path: ORCL.md
    heading_path: ["Oracle（ORCL）研究笔记", "10. 我的看法"]
  open_questions: null
  metrics: null
  risks: null
  research_metadata: null
```

关联使用稳定 ID；反向关系由读取端推导，避免手工维护双份列表。`theme` 指本主体属于目标主题；`parent`/`subsidiary` 为明确主体关系，不能仅凭投资持股推断。未建档对象先记入盘点待办，不写不可解析的关联 ID。

路径允许必要的 `../` 引用，但解析后必须仍在仓库内；禁止绝对路径、越界路径、指向仓库外的符号链接。入口只引用 Markdown 文档，证据附件通过正文引用。

多家公司在同一文档中有独立研究时，可在各公司元数据目录建立入口，primary_document 使用相对路径共用原文档；primary_section 限定本公司章节，读取端须遵守范围，不能把另一公司的判断作为本公司判断。限定章节必须唯一且存在；缺失或歧义阻断入口。比较表须用 table_row 精确选择公司行，返回表头与该公司全部同名行；指定行不存在时阻断入口。不得把比较表的整组公司当成单公司结果。无合适标题的历史公司单篇笔记仍可整篇读取，不为消除缺口而编写判断。

## 5. 正文与日期规范

新完整研究在主文档提供五个可定位部分：核心判断、待验证问题、跟踪指标、主要风险、研究日期与数据截止日；可以是现有章节，语义定位不要求历史标题统一改名。

- 核心判断标清【我的推演】，列关键假设、正反证据及改变判断的条件。
- 待验证问题说明缺口及影响，不用占位符替代可完成的核验。
- 跟踪指标说明口径、来源、最新观察及触发复核的条件；没有阈值依据时不编造阈值。
- 风险说明传导机制与反证，避免只有风险名称。
- 元数据记录研究状态、实质更新日期、财务期间、行情截止时间及其他关键数据截止日。无法统一截止日时分项记录，未知明确标注。

研究状态建议使用 `draft`、`active`、`archived`，表示研究维护状态，不表示看多、关注池成员或买入建议。已有独立“我的看法”可继续作为 opinion 文档，由入口定位；主文档链接过去，避免重复抄写。

研究质量继续执行十一项问题、三完整财年与最新可比期间、必要计算、来源及核验判定等现行要求，不在此另建一套标准。

## 6. 消费端读取契约与流程

递归发现入口，忽略 `.git`、缓存、环境目录及明确的外部参考库；读取指定版本时入口和正文必须来自同一版本。不得将被忽略的嵌套参考仓库自动纳入研究库。

读取结果至少提供：主体 ID、名称、匹配证券（包含 market、mic、symbol）、主文档路径、关联对象、各语义章节正文和状态、源版本、研究日期及数据截止信息。章节状态区分 `ok`、`missing`、`ambiguous`、`truncated`；接口整体另区分未建档、无效入口和正常读取。

优先提取语义章节；展示预算不足时明确标出截断并提供全文入口，不能只取文档开头当完整研究。展示章节属于具体作者/研究员的判断，不由读取系统补写。

共享看板默认读取已审核提交的明确 commit；本地预览可读工作树，但必须标记 `working-tree` 和脏状态，不能仅返回 HEAD 冒充当前内容版本。前端仓库链接按配置生成，不使用本机绝对路径。

stock_data 负责展示与关联行情，研究库负责正文、判断与证据；关注池独立维护，入口导入不能改变成员或买卖结论。具体函数与 HTTP 路由待其代码核对后确定。

## 7. 校验与日常维护

错误阻断相关入口：语法错误、重复 YAML 键、未知版本/字段、非法字段类型、重复 ID/证券、主文档缺失、路径越界、辅助文件缺失、关联 ID 不存在。版本 2 还须阻断：market 缺失、未知市场、未知 MIC、market/MIC 不匹配；同一 mic + symbol 即使填写不同 market 也仍然是重复证券。

内容缺口显式报告：未设置章节、标题不存在或不唯一、缺日期、研究过时。缺口允许保留历史入口，但消费端不能显示为完整观点；新完整研究交付必须消除缺口或说明原因。全库发布前不能隐去错误入口，应提供未导入清单。

新建流程：查重 → 确认主体边界 → 创建主文档与入口 → 完成研究 → 校验 → 审阅。更新流程：保存证据 → 核验 → 判断变化 → 回写正文 → 校验章节和日期。改路径时同步更新入口与反向引用，禁止先删后补。

## 8. 实施步骤与治理

按配套计划先四样本、再校验和消费端、最后扩库。规范批准后，在 AGENTS.md 增加本规范链接与简短组织规则；研究方式.md 保持研究质量唯一入口。规范变更记录日期、兼容影响与迁移要求，不自动触发历史文档重构。

### 8.1 市场字段修订与迁移

2026-10-14 修订：从版本 1 的 mic/symbol 改为版本 2 的 market/mic/symbol。现有校验器拒绝未知字段和版本，因此本修订属于不兼容升级，不能只改 YAML 而不改读取器。

当前状态（2026-10-15）：市场字段修订已获用户批准，四个试点入口已升级版本 2，校验器同步支持版本 2 和带警告的版本 1 过渡读取。10 项测试通过，见 [版本 2 验证结果](../../研究流程/2026-10-15-研究入口市场字段验证结果.md)。尚未接入 stock_data。

实施顺序：

1. 校验器与读取端增加明确的版本分支和市场映射；版本 1 如需过渡读取，只能由已知 MIC 推导 market，并标明旧格式及推导来源；未知 MIC 报错，不能默认 US。
2. 三家公司入口显式补 market: US；NAND 保持 securities: []；四份入口均升级 schema_version: 2。转换中保留 entity_id、路径与正文。
3. 更新证券索引与展示输出，保留 mic + symbol 唯一键，增加市场筛选及歧义处理。
4. 补充缺市场、非法市场、市场/交易所冲突、同代码跨市场、多地上市、前导零、空证券列表及旧版本过渡测试，再重新生成四项目验证结果。

回滚时同时恢复上一版读取器与四份版本 1 入口，不能让旧校验器读取新增字段，也不能仅降低版本号而保留新字段。版本 2 正式写入后不再生成新的版本 1 入口。

## 9. 风险、验证与回滚

风险：身份误配、章节漂移、正文与索引分叉、截止日失真及过度整理。通过唯一性检查、语义定位、正文单一来源、日期分项和分批审核降低风险。

验证至少覆盖中文目录、嵌套公司、多证券、非上市公司、主题多公司关联、独立判断、缺失标题、重复标题、截断及脏工作树版本。财务数据正确性仍由研究 SOP 与 factcheck 核验，结构校验不替代事实核验。

回滚使用本批变更差异或独立提交撤销；禁止全库重置、清理原始数据或重写历史。消费端切回上一可用版本并显示版本；研究正文和证据优先保留。
