# SOP桑基图规范修订方案

日期：2026-11-12；状态：待审核。本轮只创建本方案，不修改SOP正文。

## 背景与目标

用户认可微软HTML中的收入利润桑基图、集团现金桑基图。现有SOP已要求HTML、同源图表及现金勾稽，但图形选择主要列柱状图、瀑布图，未规定如何展示连续来源和分配关系。

目标：将“钱从哪来、如何形成利润、现金流向哪里”作为默认研究问题；数据满足条件时优先用桑基图，避免只展示孤立金额。不将某张图强制套用于所有企业。

## 范围、非目标与现状分析

范围为四份跨项目文件：研究方式.md、研究流程/规范/HTML报告与财务可视化规范.md、研究流程/规范/公司研究主文档模板.md、研究流程/规范/研究更新与交付检查清单.md。

非目标：不批量改历史报告、不扩展入口schema、不强制采用某个前端库、不将微软示例当成全行业会计模型、不把用户认可当前图形等同于所有设备和打印已验收。

现有规则中的费用/现金区分、非现金剔除、图表表格同源与视觉验收继续保留。补充桑基图选择与守恒要求，并将“现金变化一律瀑布图”细分为结构与变动两种问题。

## 设计方案：建议写入的规则

### 1. 总SOP：先解释商业与资金路径

建议在研究方式.md的HTML展示段增加：

> 新研究及明确重构的报告，应解释收入来源、利润形成和现金来源用途；数据适合连续分配且可勾稽时，优先用桑基图展示来源→汇总→分配。收入费用与现金流分别成图；图形不能替代三年及最新季度底表。数据不足或行业不适用时说明原因，改用费用桥、现金变化桥或不按金额编码的业务关系示意图。

只在总SOP保留原则，细则集中到展示规范，避免重复维护。

### 2. 展示附件：两种主桑基图＋一种业务示意

| 要回答的问题 | 优先图形 | 边界 |
|---|---|---|
| 哪些业务创造收入，如何留下利润 | 收入费用桑基图：业务收入→集团收入→成本/毛利→费用/经营利润 | 产品分类互斥；不能猜产品级成本；进入净利润时需补其他收益及税项 |
| 现金从哪来，留存或用到哪里 | 现金来源用途桑基图 | 采用原现金流量表口径，可展示净流量但须显著标净；余额、汇率不是付款 |
| 余额或利润为何比上期变化 | 瀑布图/变化桥 | 保留原规则，不用桑基图替代所有变动解释 |
| 谁向谁购买什么、如何付费但金额不足 | 等宽箭头业务示意 | 明确“不按金额”；不可凭空估算成资金流 |
| 历史趋势与构成变化 | 柱状图、折线图及精确表格 | 桑基图是单期结构，不替代完整期间序列 |

### 3. 桑基图硬约束

拟在HTML报告与财务可视化规范.md增加专节：

- 一张定量图使用同一主体、期间、币种、单位及会计口径。集团图不能冒充分部图；传统软件授权收入、云服务收入、客户收款分开。
- 带宽由金额统一缩放；图内不能单独放大某条流，小额通过外置标签、引导线和明细表处理，不能设置虚假最小金额宽度。
- 中间节点入流合计＝出流合计；源头及终端节点按其定义检查。舍入容差依据原始精度说明，不能修改原数凑守恒。
- 所有边必须有来源或可复算公式。残差只能在总额可靠、已知项同口径时生成并标“未拆分/其他净额”；没有可靠总额就不用残差补齐。
- 不推断穿过公共汇总节点后的逐笔归属；业务收入汇总后分配为集团费用，不表示已披露各业务独立利润或资金用途。
- 收入利润与现金分别成图。CFO已扣经营付款，不能再次扣工资/研发现金；折旧、SBC、非现金租赁、资产增加、授权及未来承诺不画为本期付款。
- 现金图可用净流量或原表可得的总流入/总流出，但不可混标。期初余额不叫当期收入，期末余额不叫费用，汇率不叫付款；父项展开时不与子项重复相加。
- 负利润、负CFO、净流入、抵销及冲回不得直接取绝对值作为正向分配。按真实经济方向设置明确的补充来源/净流入节点并勾稽；无法清晰表达时改用带符号瀑布图或表格。不能为画桑基图而隐去亏损。
- 节点常驻显示名称与金额，主体/期间/单位/口径及关键限制在图旁可见；占比给出分母，悬停仅补充信息。业务配色固定，收益、费用、余额等性质同时用文字区分。
- 多类别可合并为有完整明细的互斥组，不能用“其他”掩盖关键业务；默认视图优先可读，不能牺牲必要信息。
- 默认交付离线可见静态图；交互增强可高亮路径、展开明细及选择已取得期间，但无脚本时核心图、表、来源仍完整。缺期不能用切换器掩盖。

金融、保险、协议代币等按行业重建节点定义。收入/净收入、资产本金、发行代币、经营费用和权益分配不能照搬工业软件公司的路径。

### 4. 模板：把图放在相应章节

- 第2节营收、第3节盈利：链接或就地放收入利润桑基图及同源底表；同一主图不重复复制。
- 第3节现金流、第8节资本分配：现金桑基图解释整体来源用途，必要时用细项/趋势图解释投入。
- 图边先写一句它回答的问题，表后解释变化和异常；没有足够披露时说明替代展示与影响，不补造产品级现金流。
- 最新实绩优先；若因重述或材料限制选择旧年度结构图，必须显著标历史及原因，同时保留最新季度底表。新图形不改变季度完整性规则。

### 5. 验收清单：新增具体检查项

1. 图的主体、期间、金额单位、收入/现金/净额口径明确。
2. 每条边与底表同源，带宽同比例，中间节点守恒，残差及舍入有依据。
3. 没有跨图混接、重复扣款、父子重复计入、负值绝对化及未披露业务分摊。
4. 标签与小额明细可读，来源就近，键盘高亮/无脚本降级（如有）检查；历史图与最新季度底表未混同。
5. 财务勾稽、结构链接、桌面/窄屏/打印视觉结果分别记录。受权限或工具阻断时可交付明确标记的预览，不能宣布视觉验收或完整研究验收通过。

## 数据模型/API/流程变更

不规定新的统一schema、不增加接口。现有结构化输入补足主体、期间、口径、原值精度、来源、状态、公式；实现可采用节点/边结构，图与表复用同一数值。HTML与Markdown机器底稿的现有过渡规则不变。

执行流程：先判断研究问题→核对披露与口径→选择桑基或替代图→同源生成→逐边/节点勾稽→视觉实测→记录真实完成范围。

## 实现步骤

用户批准后：

1. 在展示附件补充图形选择表与桑基图专节，调整现金图相关措辞以消除冲突。
2. 总SOP增加简短原则和附件引用；模板与清单同步，不全文复制细则。
3. 逐条对照四份文档，确认不削弱十一项、三年及季度完整性、异常解释和来源标准。
4. 写修订日期及实际验证记录，检查相对链接；不改历史研究或已知事实截止日。

## 风险点与验证方式

风险：强制套图、口径混合、负值隐藏、伪精确分摊、静态新图掩盖期间缺失。通过规则与案例反检：微软正常盈利、经营亏损企业、负FCF企业、融资净流入、分部抵销和未披露产品成本六类情形均应能明确选择图形或说明不适用。

检查文件间术语一致，所有引用链接有效；明确区分“提出规则”和“已有通用工具能力”，不把微软局部生成器宣称为全库通用生成器。

## 回滚方案

按本轮四份规范的差异逐项撤销，保留方案及既有研究图形。不得重置工作树或覆盖用户同期SOP修改；本轮不迁移入口和数据，无额外数据回滚。

## 待确认问题

建议批准“符合披露与守恒条件时优先桑基图”的规则，而非无条件强制每家公司两张图。方案获明确确认前，不修改SOP正文。
