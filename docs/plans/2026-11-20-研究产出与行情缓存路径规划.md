# 研究产出与行情缓存路径规划

日期 2026-11-20。状态为待审阅。

## 背景与目标

CRWV 的滚动行情与固定复算输入混放在 `factcheck/data/`。因此 `.gitignore` 要按 NBIS、CRWV、QQQ 和日线、小时线排除六种文件，再为历史回测的三份 CSV 逐一放行。目录应直接表达文件的用途和生命周期。临时产物用固定目录和文件名，纳入研究证据的输入与结果有稳定定位。

## 范围

- 先用 CRWV 的行情下载与 NBIS/CRWV 配对回测试点。
- 同步涉及的下载、复算脚本、历史专题中的路径与运行说明、Git 跟踪规则和 SOP 目录约定。
- 验收预览沿用已有的 `factcheck/visual/`。

## 非目标

- 策略模型、交易成本、样本口径及财务分析修订。
- HYPE、数字资产及历史财报资料的全库迁移。
- 图表、HTML 报告与网站读取契约改造。

## 现状

| 读写方 | 现状 | 需要解决的问题 |
|---|---|---|
| [行情同步脚本](../../CRWV/factcheck/sync_stock_daily.py) | 把请求返回值写到 `data/<运行日>-<标的>-<频率>.csv` | 每天产生新文件，滚动下载和固定输入共用路径 |
| [回测脚本](../../CRWV/factcheck/nbis_crwv_pair.py) | 逐个标的选择文件名最新的日线。显式传 `--snapshot` 时读取该日期的三份输入 | 下载缺一条腿时，默认回测可能混用不同日期的文件 |
| [历史回测说明](../../CRWV/2026-10-21-NBIS-CRWV-pair回测.md) | 固定输入已被 Git 跟踪。读到的三份 CSV 各 250 行，覆盖 2025-10-21 至 2026-10-19 | 文件名的 2026-10-21 是快照标识，实际行情截止需要单独记 |
| 回测结果 | 运行结果以运行日命名并写在 `factcheck/` 顶层，已有一份 2026-10-21 结果纳入 Git | 日常试跑和归档结果需要不同位置 |

本地盘点时，旧规则下没有发现额外的被忽略滚动行情文件。公司财报证据另有 `q3-2026/`、`full-rebuild/` 等目录。

## 目录设计

路径以所属研究项目为根。用两条目录规则统一处理本地生成物，分别为已有的 `**/factcheck/visual/` 和拟采用的 `**/factcheck/cache/`。

| 用途 | 标准目录 | 文件与处理 |
|---|---|---|
| 滚动下载和清洗 | `factcheck/cache/market-data/polygon/<频率>/` | 例如 `1d/nbis.csv`，按证券和频率固定文件名。保存最近一次完整批次 |
| 回测试跑 | `factcheck/cache/backtests/<主题>/` | 例如 `nbis-crwv/result.json`。同主题重跑覆盖同名结果，运行日期和输入版本记录在结果中 |
| 验收预览 | `factcheck/visual/` | 用固定的桌面、窄屏和打印文件名 |
| 固定复算输入 | `factcheck/data/backtests/<主题>/<快照ID>/` | CRWV 试点用 `nbis-crwv/2026-10-21/`，三份输入按原字节迁移。已审核固定输入及清单纳入 Git |
| 归档复算结果 | `factcheck/results/backtests/<主题>/` | 已有结果迁到 `nbis-crwv/2026-10-21.json`。以所用的快照 ID 定位 |
| 财报与来源证据 | `factcheck/data/<财报期间或专题>/` | 按现有研究证据的追溯要求保管。验收脚本、核验记录仍从 `factcheck/` 访问 |

缓存固定覆盖最近有效批次。只有需要交付和长期复算的运行才归档为一个快照，日期或版本号写在归档处。稳定目录一律按类别忽略，试点通过后删除 CRWV 的九条按文件名配置。

## 数据与流程

1. 下载脚本从自身位置定位项目，按频率写入滚动目录。批次清单记录提供方、证券、频率、复权设置、请求范围、实际首末交易日、行数和每份文件的 SHA-256。固定快照使用同类清单，历史无法核实的字段显式标未知。
2. 三份行情都取得并校验后再发布新批次。先准备临时文件，校验后逐个原子替换并最后更新清单，发布完成前保留可恢复的上一批文件。回测先读取完整批次，核对每份输入字节与清单哈希，再用这组字节计算。发布中断或清单与文件不一致时明确报错，并可恢复上一批。
3. 保留 `nbis_crwv_pair.py --snapshot 2026-10-21` 调用方式，由它读取固定快照。省略参数时读取有效滚动批次，缓存未就绪时提示历史复算命令。两种模式都写试跑目录，输出记录输入快照或批次、实际期间和参数。
4. 经审阅的结果才进入归档结果目录。发布结果指明固定输入和脚本入口。现有小型结果逐字节迁移，新增元数据放在清单中。

## 实施步骤

1. 清点所有旧路径的读写方和工作区文件，计算现有三份固定输入与归档结果的哈希。
2. 建立目录与清单，同步迁移固定输入、归档结果和引用，更新同步脚本与回测脚本。
3. 用仓库固定输入从异目录离线复算。用临时文件和模拟下载验收滚动批次、失败恢复及连续两次运行的行为。
4. 更新 SOP 的目录说明，再以通用缓存规则替换 CRWV 的九条规则。检查预览、市场数据和结果归档各自的 Git 状态。

## 风险与验证

- **历史复算被新行情覆盖。** 比较迁移前后三份 CSV 及归档 JSON 的哈希。运行固定快照，复现 250 个交易日和 2026-10-19 截止日。数值结果与迁移前基线逐项比较，运行时间和路径属于运行元数据。
- **同一批次混用行情。** 用缺一只标的、部分下载失败、三份文件来自不同批次的测试检验读取失败及旧批次保护。两次正常同步检查文件名集合稳定。
- **忽略范围过大。** 用 `git check-ignore --no-index` 确认临时行情、试跑结果及截图命中通用规则，财报证据、固定 CSV、归档结果和脚本可跟踪。清点全库现有的 `factcheck/cache/` 再启用通用规则。
- **引用断裂或牵连在途研究。** 检查历史专题和执行命令的所有实际路径，复核报告索引。按字节对照迁移前后的旧文件，限制 Git 差异到试点和规范。

## 回滚

按试点变更恢复原读取路径和原忽略规则，按哈希把固定输入及归档结果还原。缓存和新快照留在本地，以原件或核验过的复制件恢复。保留其他在途报告、索引改动和暂存内容。

## 待确认

- 建议首批用 CRWV，其他项目后续按同一目录规则逐个盘点。
- 建议滚动行情留最近一次完整批次，需长期复用的版本进入固定快照。
- 建议无滚动批次时由回测明确提示使用 `--snapshot`，避免把历史快照当当前行情。
