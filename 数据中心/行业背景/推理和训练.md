如果你只是想要一个**足够简单、能用于算 AI 数据中心需求的比例**，我建议目前先记：

> **2026 年：推理约 60%–70%，训练约 30%–40%。**
> 中性假设直接用：**推理 65%，训练 35%**，大约就是 **2:1**。

这个数量级和现在几组公开估算基本一致。

Gartner 2026 年 8 月最新预测，AI-optimized IaaS 支出中，**推理约 233 亿美元，训练约 190 亿美元**，也就是：

> 推理 **55%**
> 训练 **45%**。([Gartner][1])

但这是按**云基础设施支出**计算。

如果按实际 **compute 消耗**看，推理比例会更高。Deloitte 对 2026 年的估计是：

> 推理大约占全部 AI compute 的 **2/3**，
> 训练约 **1/3**。([Deloitte Italia][2])

Epoch AI 最新研究专门看大型 AI 开发商，得到的范围更高：

> **推理约 60%–80%**，
> 训练约 **20%–40%**。

而且他们认为目前训练和推理仍然属于“同一个数量级”，并不是已经变成 90:10。([Epoch AI][3])

所以我会这样记：

| 口径               |         推理 |         训练 |
| ---------------- | ---------: | ---------: |
| Gartner：AI 云支出   |    **55%** |    **45%** |
| 我们的中性假设          |    **65%** |    **35%** |
| Deloitte：Compute |   **~67%** |   **~33%** |
| 大型 AI Lab 范围     | **60–80%** | **20–40%** |

### 为什么推理已经超过训练？

很简单。

训练是：

> GPT-6 训练几个月
> → 极其恐怖的一次性算力消耗。

但推理是：

> ChatGPT
> Claude
> Codex
> Claude Code
> Copilot
> Agent
> API

**一天 24 小时不停地有人调用。**

而且用户越多，推理就线性增加。

例如：

100 万用户
→ 1000 万用户
→ 1 亿用户
→ 10 亿用户

哪怕模型完全不升级，推理算力需求都会一直涨。

所以现在产业正在发生：

> 2022–2023：**训练主导**
> ↓
> 2024–2025：接近 50:50
> ↓
> 2026：**推理开始主导**
> ↓
> 未来：推理占比继续增加

Futurum 的估算也类似：2025 年已经是 **推理 58.6% / 训练 41.4%**，预计 2030 年会达到约 **72% / 28%**。([Futurum][4])

---

## 对我们前面那个“收入能养多少数据中心”的问题，这特别重要

假设未来全球有：

> **100 GW AI 算力**

我现在会非常粗地先拆成：

**65 GW 推理**
+
**35 GW 训练**

而不是以前想象的：

> 大部分 GPU 都在训练 GPT-6。

实际上到了今天，**真正长期把数据中心填满的越来越是推理。**

而且这意味着训练和推理的经济逻辑完全不同：

### 训练 35 GW

背后的理由是：

> “我要训练更好的模型。”

它本身**不直接产生收入**。

OpenAI 花几十亿美元训练一个模型，是赌这个模型以后能够赚钱。

### 推理 65 GW

背后的理由是：

> “已经有人在用 AI。”

ChatGPT 用户
Claude Code 程序员
企业 API
Microsoft Copilot
Agent

每调用一次，都对应实际需求。

所以：

> **训练 = R&D / CapEx 型需求**
>
> **推理 = Revenue 型需求**

这两个必须分开看。

---

而这也让我觉得，我们前面那个研究方法还可以再简化一步。

以后看 AI 数据中心泡不泡沫，可以直接看三个数字：

> **AI 年收入**
>
> ↓
>
> **能支撑多少推理 GW**
>
> *
>
> **AI 公司愿意额外烧多少钱训练下一代模型**
>
> ↓
>
> **能支撑多少训练 GW**

也就是说，如果全球最终建设 **100 GW AI 数据中心**，我们不能要求今天 AI 收入直接养活全部 100 GW。

因为其中可能有 **30–40 GW 本质上是模型公司的研发投入**。

真正需要最终用户收入持续养活的，主要是那 **60–70 GW 推理基础设施**。

**所以我们后面如果要判断“几十 GW 到底有没有需求”，重点应该盯推理这 65%，训练那 35% 可以另外算。**这会比单纯拿 OpenAI 收入对整个 Stargate 投资额合理得多。

我也可以持续跟踪这个比例是否继续向推理倾斜。

这个问题目前没有一家公司给出“全行业短 Context vs Agent”的完整统计，但已经有足够的数据让我们做一个**比较靠谱的区间估算**。

如果我们的目的是算 **AI 数据中心推理负载**，我现在会先用：

> **2026 年大模型推理算力：普通/短对话约 55%–65%，Agent 型约 35%–45%。**

中性值可以直接记成：

> **短对话 60% / Agent 40%。**

但这里有一个非常重要的现象：**按“请求次数”看，Agent 占比远低于 40%；按 token 和 GPU 算力看，Agent 却可能已经接近 40%。**

原因很简单。

### 普通 Chat

比如：

> “Microsoft 365 Copilot 是什么？”

可能就是：

10k input
→ 2k output
→ 完事。

一个任务只调用模型 1～几次。

而 Agent 是：

> “帮我检查整个代码库，把这个 bug 修掉。”

然后后台：

读取代码
→ LLM
→ 搜文件
→ LLM
→ 修改
→ LLM
→ 跑测试
→ 失败
→ LLM
→ 再修改
→ 再测试……

一次用户请求实际上变成：

> **几十次模型推理。**

微软刚刚发表的 GitHub Copilot Agent 真实生产数据非常夸张：

> 320 万用户
> 1300 万 sessions
> **7.61 亿次 LLM calls**
> **95 万亿 tokens**

也就是平均一个 Agent session 大约：

> **58 次 LLM 调用**

而且包含约 **730 万 token 的累计处理量/session**。之所以数字这么大，是因为 Agent 会反复把代码、历史状态、工具结果等上下文送回模型。([微软][1])

所以你可以理解成：

> **一个 Agent 用户可能顶几十个甚至上百个普通问答用户的 token 消耗。**

---

## 现在已经有一个特别好的实际数据

OpenAI 今年 6 月披露：

在**企业客户**里面：

> **Codex 已经占 ChatGPT + Codex 输出 token 的 64%。**

也就是说：

### 企业 AI 已经是 Agent > Chat。

不是预测，是已经发生了。

OpenAI明确说，复杂的长期 Agent 任务需要更多计算，这正是 Agent token 增长如此快的原因。([OpenAI][2])

更极端的是 OpenAI 自己的员工。

2025 年 8 月：

> Codex <10% token

到了 2026 年：

> 普通员工 >85% output token 来自 Codex
> OpenAI 全公司 **99.8% output token** 来自 Codex。

也就是说，一个真正把 Agent 工作流用起来的组织最终很可能从：

> Chat 90 / Agent 10

变成：

> Chat 10 / Agent 90。([OpenAI][3])

---

## Anthropic 也出现了一模一样的现象

Anthropic 在今年 6 月的 Economic Index 里专门说：

一年前 Claude 的绝大多数使用还是：

> 人 ↔ Claude 对话

现在因为：

> **Claude Code + Cowork**

快速增长，Claude session 已经越来越多变成长时间运行的 Agent 任务，以至于 Anthropic 甚至不得不改变自己的使用量统计方法。([Anthropic][4])

所以 OpenAI 和 Anthropic 都在看到同一个方向。

# 但是为什么我没有说“Agent 已经占 60%？”

因为还有 **10 亿级普通消费者**。

OpenAI 目前：

> ChatGPT >10 亿 weekly users

而 Codex：

> > 500 万 weekly users。([OpenAI][5])

人数差了两个数量级。

绝大多数普通消费者仍然是：

问问题
翻译
写邮件
搜索
做题
聊天
总结

也就是传统 Chat / Search 型 inference。

所以形成一个很有意思的结构：

| 按什么统计           |   短 Chat |    Agent |
| --------------- | -------: | -------: |
| **用户人数**        |    ~95%+ |       很低 |
| **任务次数**        | ~80–90%+ |  ~10–20% |
| **Token**       |  ~55–65% |  ~35–45% |
| **企业 AI token** |     ~36% | **~64%** |
| 重度 AI 原生企业      |     <10% | **>90%** |

前两行是我根据现有用户规模做的数量级判断，**不是公司披露数据**；后面 OpenAI 企业的 64% 是实际披露。

# 对我们算数据中心，最重要的是第三行

我们根本不关心：

> 有多少人点了一次 ChatGPT。

我们关心的是：

> **谁烧了 GPU。**

所以我建议我们的 AI 数据中心模型暂时这样拆：

假设：

> 全球 AI = 100 GW

前面我们估：

> **推理 65 GW**
>
> 训练 35 GW

那么这 65 GW 推理，可以第一版再拆：

### 普通 Chat / Search / short-context

**约 39 GW**

### Agent

**约 26 GW**

即：

> **推理内部：60 : 40**

这只是一个 **2026 base case**，不是精确统计。

---

# 但未来我反而认为这个比例会倒过来

因为普通 Chat 的逻辑是：

> 人发一句
> AI 回一句
> 停止。

它受制于人的速度。

一个人一天可能问：

> 20 次、50 次、100 次。

但 Agent 不一样。

你可以同时开：

Agent A 写代码
Agent B 查资料
Agent C 做 Excel
Agent D 做 PPT
Agent E 分析数据

人在睡觉，Agent 还可以继续运行。

OpenAI 已经观察到一个极端案例：

> 最重度的 1% Codex 用户一天可以产生 **超过 60 小时的 Agent runtime**

因为他们同时并行运行多个 Agent。([OpenAI][3])

这实际上突破了：

> **一个人一天只有 24 小时**

这个传统软件使用上限。

所以我会非常粗略地预期：

| 时间       |  普通 Chat |       Agent |
| -------- | -------: | ----------: |
| 2025     |     ~75% |        ~25% |
| **2026** | **~60%** |    **~40%** |
| 2027–28  |     ~40% |        ~60% |
| 成熟阶段     |  ~20–30% | **~70–80%** |

后面三年的数字是**我的情景假设，不是行业预测共识**。

但方向我认为已经相当清楚：

> **未来推理算力的大头，很可能不是几十亿人在 ChatGPT 问问题，而是几亿人背后同时运行大量 Agent。**

这对我们前面讨论的几十 GW 数据中心特别关键。因为如果 AI 永远停留在“问完就走”的 Chat 模式，我会对几十上百 GW 的需求非常怀疑；**Agent 才是有可能把推理需求再放大一个数量级的东西。**
